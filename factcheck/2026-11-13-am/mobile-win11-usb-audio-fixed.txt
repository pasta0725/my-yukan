If your USB headset, mic, or speaker went silent or showed “This device cannot start (Code 10)” after September’s Windows security updates, Microsoft’s November 10, 2026 Patch Tuesday updates resolve the remaining documented symptoms. The September 14 emergency patch only fixed part of the problem.
What Happened: USB Audio Not Working After a Windows Update
According to 
BleepingComputer’s original report
, Microsoft’s September 2026 security updates broke some USB audio devices. BleepingComputer named those updates as KB5124008 and KB5124012.
Microsoft’s 
Windows release health entry
 traces the issue on most branches to the September 8 security update and lists a broad set of affected platforms. On Windows 11 version 26H2, Microsoft instead says the problem appeared after installing version 26H2 itself. That list covers Windows 11 versions 23H2 through 26H2, Windows 10 versions 21H2 and 22H2, Windows 10 Enterprise LTSC 2016 and 2019, and Windows Server 2012 through Windows Server 2025.
Affected PCs showed three symptoms:
A “This device cannot start (Code 10)” error in Device Manager
No sound output at all
Volume controls and sound settings that stopped responding
The failing layer is narrow. Microsoft says the issue is limited to devices using the older USB Audio Class 1.0 standard. Budget USB headsets, mics, DACs, and older USB speakers commonly use this standard, though not every device in these categories is necessarily affected.
Microsoft’s documented scope is USB Audio Class 1.0 devices only, and it doesn’t list USB Audio Class 2.0 devices as affected. That isn’t a guarantee for every other audio setup, and it doesn’t rule out unrelated audio problems.
To check your own PC, open Device Manager from the Start menu search. Then expand 
Sound, video and game controllers
. A yellow warning icon on a USB audio entry, with Code 10 in its properties, matches this bug.
How the Two-Stage Fix Stacks Up
On the branches affected by the September 8 update, Microsoft fixed this in two passes. An out-of-band update on September 14 
addressed only the multichannel failures
, such as 8-channel and 3D audio modes. On Windows 11 that update was 
KB5129195
 for versions 24H2 and 25H2, and KB5129194 for version 26H1. On Windows 10 ESU and Enterprise LTSC 2021 PCs, it was 
KB5129236
. Microsoft’s notes for it say other audio symptoms were not resolved.
The remaining symptoms were fixed on November 10. Microsoft’s 
KB5132061 release notes
 list the USB Audio 1.0 Code 10 fix for Windows 11 versions 24H2, 25H2, and 26H2. 
BleepingComputer also reported the fix
, citing Microsoft’s Release Health dashboard. Other branches ship separate packages, so KB5132061 is not the number every reader should expect.
For Windows 11 23H2, Microsoft’s 
23H2 release health page
 lists 
KB5131087
 as the resolving update. For Windows 10 ESU PCs (versions 21H2 and 22H2) plus Enterprise and IoT Enterprise LTSC 2021, Microsoft lists 
KB5131096
. Consumer and commercial Windows 10 22H2 PCs receive it through the 
Extended Security Update
 program. Match your version against the table below, or check Microsoft’s 
Release Health dashboard

The Reaction
Community reaction is still forming. We haven’t seen verified reports of the November fix failing.
What to Do Next
Open 
Settings
 > 
Windows Update
, click 
Check for updates
, install the November security update for your Windows version, and restart.
If audio still fails, go to 
Settings
 > 
Windows Update
 > 
Update history
. Make sure the November update for your specific branch shows as installed, not just any KB number you found online. If you use a multichannel device, check that the September 14 fix or a later update is there too.
If Code 10 persists after both updates, the cause may lie elsewhere. Check the cable, the port, the device’s driver or firmware, and the device itself.
Can’t update right now? Microsoft’s release health entry notes that some customers restored audio on multichannel devices by switching to 2-channel mode. Treat that as a stopgap. If you’re replacing a budget headset anyway, a USB Audio Class 2.0 headset or USB DAC falls outside this bug’s documented scope.
Our Take
Install the November update that matches your Windows version. Don’t keep pausing it. Holding back security patches to protect a headset is a bad trade.
For most readers this is a contained problem. Microsoft limits the bug to USB Audio Class 1.0 devices and lists a resolving November update for the branches it documents, though persistent failures can still have another cause.
The real trap is the timeline. If you installed the September 14 patch and still had silence, you may have thought your hardware died. That may not be the case.
Wrapping Up
The November 10 update that matches your Windows version is the fix that matters. After you install it, reboot, then unplug the USB device and plug it back in. Then check Device Manager. If the entry shows no warning icon and you hear sound, the fix stuck. If Code 10 follows the device to a different port or another updated PC, suspect the device, its driver, or its firmware rather than this bug.

The device produces no audio output at all, even though it’s plugged in and selected.
The volume controls don’t respond, or they stay stuck at zero no matter what you do.
Sound settings become unresponsive or simply aren’t available.
There are two details on that page that are easy to miss. The first is that Microsoft says the problem is limited to 
USB Audio Class 1.0
 devices, and the second is that it isn’t really a 26H2-only bug, because Microsoft ties it to the September 8, 2026 update and lists a long range of affected versions, from Windows 11 versions 23H2 through 26H2 to several Windows 10 releases and a fair number of Windows Server editions. That means skipping 26H2 won’t protect you, and holding back updates won’t fix a PC that’s already affected.
Microsoft released an out-of-band update, 
KB5129195
, on September 14, 2026, and it fixed one part of the problem, where devices that worked in stereo failed in multichannel modes, but it left the Code 10 and no-sound symptoms open. The status was last updated on September 29, and Microsoft said at the time that a fix would come in a future Windows update, and that fix arrived on November 10, 2026, when the KB5132061 release notes listed it as resolved: USB Audio 1.0 devices “might fail to start and display error code 10 in Device Manager” is now fixed.
Is Your Headset a USB Audio Class 1.0 Device?
Most people have never heard of audio “classes,” and that’s perfectly reasonable, so rather than guessing you can check yours in Device Manager with the steps below.
Right-click Start and open 
Device Manager
, which is where Windows keeps the details for each piece of hardware.
Expand 
Sound, video and game controllers
 and double-click your USB headset or speaker to open its properties.
Go to the 
Details
 tab and pick 
Compatible Ids
 from the drop-down so you can see how the device identifies itself.
Look for a line starting with 
USBClass_01
, and if it ends in 
Prot_00
 you have a USB Audio Class 1.0 device, while 
Prot_20
 means it’s USB Audio Class 2.0.
If yours turns out to be Class 2.0, this particular bug probably isn’t what’s causing your trouble, so you can skip ahead to the general fixes near the end of the article.
How to Fix USB Audio No Sound and Code 10 on Windows 11
Step 1: Switch the device to 2-channel stereo
This is the workaround Microsoft itself mentions, and it’s the first thing I’d try, because some users got their audio back simply by switching the device over to 2-channel mode.
Press 
Win + R
, type 
mmsys.cpl
 and press Enter, and the classic Sound window will open.
On the 
Playback
 tab, select your USB device and click 
Configure
, then choose 
Stereo
 and work through the wizard until it finishes.
Select the device again, click 
Properties
, open the 
Advanced
 tab, and set the Default Format to a 2-channel option such as 
2 channel, 16 bit, 48000 Hz
.
Click 
Apply
, then unplug the device, wait a few seconds and plug it back in so Windows picks up the new setting.
If the headset has a microphone, it’s worth checking the 
Recording
 tab as well and setting its format to a basic option like 1 channel or 2 channel, 16 bit, 48000 Hz.
Step 2: Install every available update
Open 
Settings > Windows Update
 and click 
Check for updates
, because the November 10, 2026 security update (KB5132061 on 24H2, 25H2 and 26H2) contains Microsoft’s fix for the Code 10 and no-sound problem. While you’re there, open 
Advanced options > Optional updates
 and look under driver updates too, since your PC maker may have posted an audio or USB controller driver in that section.
Once you’ve updated, press 
Win + R
, type 
winver
 and make a note of your build number, which is handy to have if you end up contacting support later on.
Step 3: Uninstall the device and let Windows reinstall it
In Device Manager, right-click the USB audio device and choose 
Uninstall device
, but leave the box for deleting the driver unticked. Unplug the device, restart the PC and then plug it back in, so Windows loads a fresh copy of the USB audio driver, which sometimes clears a stuck Code 10.
Step 4: Try a different USB port, and skip the hub
Plug the device straight into the PC rather than into a hub, dock or the USB port on a monitor, and if you’re using a front-panel port, try one on the back of the motherboard instead. If the device is on a USB 3.x port and your PC still has a USB 2.0 port, give that a go as well, because although it sounds old-fashioned, older audio devices sometimes behave better there.
Step 5: Install the maker’s own software or driver
A lot of gaming and pro headsets ship with their own app and driver (the companion apps from Logitech, Razer, SteelSeries and similar companies are good examples), and using the maker’s driver instead of the generic Windows one can sidestep the bug entirely. I’d check the support page for your exact model to see what’s on offer.
Step 6: Use a different connection for now
If your headset also has a 3.5 mm jack or Bluetooth, I’d switch to that until the fix lands, since it isn’t the most elegant solution but it will get you through the week’s meetings.
Step 7: Consider rolling back, carefully
If you upgraded to 26H2 within the last 10 days, you can go back under 
Settings > System > Recovery > Go back
, though keep in mind that Microsoft says the bug also affects older versions, so rolling back may not help at all. I also wouldn’t uninstall security updates just to chase an audio bug, because that leaves the PC exposed and is unlikely to fix this particular problem anyway.
If you’re running a business,
 Microsoft says IT admins who need an immediate workaround for the remaining symptoms can get in touch with Microsoft Support for Business.
Still No Sound? Rule Out the Usual Suspects
If your device turned out to be USB Audio Class 2.0, or the steps above didn’t help, there’s a good chance you’re dealing with a different problem, so it’s worth running through a few quick checks.
Click the speaker icon on the taskbar and make sure the right output device is selected, because Windows has a habit of switching to the monitor’s speakers after an update.
Right-click the speaker icon, choose 
Sound settings
, and run 
Troubleshoot common sound problems
 to let Windows look for obvious faults.
Try the headset on another PC, and if it’s silent there as well, the problem is with the hardware rather than Windows.
If 26H2 has brought you other trouble, take a look at our guide to 
fixing the Windows 11 26H2 black screen after sign-in
. For USB drives that are acting up too, we also cover 
how to fix an external drive not showing up on Windows 11
, and if the Xbox app stopped opening after the same update, see 
how to fix the Xbox app not opening on Windows 11
.
FAQs
Why does my USB headset say Code 10 on Windows 11?
Code 10 means Windows couldn’t start the device, and since the September 2026 update Microsoft has confirmed that some USB Audio Class 1.0 devices fail in exactly this way. Switching the device to 2-channel stereo and installing the latest updates are the first things I’d try.
Has Microsoft fixed the Windows 11 USB audio bug?
Yes. KB5129195 fixed the multichannel problem in September, and the November 10, 2026 update (KB5132061 on Windows 11 24H2, 25H2 and 26H2) fixes the Code 10 and no-sound symptoms.
Does this only affect Windows 11 26H2?
It doesn’t, since Microsoft lists Windows 11 versions 23H2 to 26H2, several Windows 10 releases and a number of Windows Server editions as affected.
That covers everything for now, and the stereo trick is the one I’d try first, with the rest of the steps there to catch the cases it misses. Microsoft’s full fix is now out in KB5132061, so if you haven’t installed the November update yet, that’s the step to take first.
