2026年10月のWindows更新以降、「SQL Server」の接続に問題。数日中に緊急（OOB）修正へ
 外部DBへの接続が閉じられず蓄積、パフォーマンスが低下するおそれ 
樽井 秀人
2026年11月12日 16:52
「Windows release health」における当該問題の記載
 　米Microsoftは11月11日（現地時間）、「SQL Server」のリンクサーバークエリで作成された接続が、クエリの完了後も開いたままになることがある問題を明らかにした。
2026年10月の月例セキュリティパッチ
以降をサーバー環境に適用すると発生するという。 
 　この問題は、OLE DBプロバイダーを使って外部データベースに接続する「SQL Server」のリンクサーバークエリで発生する。影響が確認されているのは、「Oracle」や「PostgreSQL」への接続など。クエリを実行するたびに外部データベースへの接続が閉じられないまま積み重なり、長時間運用するとサーバーのパフォーマンスが低下することがある。影響を受ける環境では、関連するクエリが実行されていないにもかかわらず、外部データベースへの接続数が増え続けるという。 
 　アイドル状態の接続を特定して手動で閉じたり、SQLサービスを再起動したりすれば、一時的に負荷を軽減できる。ただし、実行中のクエリやトランザクションが中断されるおそれがあるほか、しばらく運用すると問題が再発する可能性もある。 
 　影響を受けるプラットフォームは、以下の通り（括弧内は起因となったパッチのKB番号）。執筆時現在、「Windows 11 バージョン 26H2」は影響範囲として記載されていない。

Microsoft: Recent Windows updates cause SQL Server performance issues
                            By 
Sergiu Gatlan
November 12, 2026
07:11 AM
1
Microsoft has confirmed that Windows updates released since the October 2026 Patch Tuesday are causing SQL Server performance and stability issues.
As detailed in a Windows release health dashboard update on Wednesday, this is caused by server queries that leave connections open after the queries complete. These connections accumulate instead of closing, degrading server performance over time.
"This issue affects SQL Server linked server queries that use OLE DB providers to connect to external databases. Oracle and PostgreSQL connections are among those known to be affected," Microsoft explained.
"In affected environments, administrators might observe an increasing number of open connections to external databases, even when the associated SQL Server linked server queries are no longer running."
It also added that admins may be able to manually close connections left open due to this bug or restart the SQL service to temporarily address stability and performance issues, but this can also kill active queries and may not fully address the issue, as it will resurface again after some time.
Microsoft says the issues impact both client (Windows 10 and Windows 11) and server (Windows Server 2012 and later) systems and will be fixed with an out-of-band Windows update to be released over the next few days.
While it works to resolve the bug, Microsoft said IT administrators can reach out to 
Microsoft Support for Business
 for a mitigation that can address the issue until a fix is available.
In September, Microsoft also 
shared a temporary workaround
 for SQL Server crashes on some Windows Server 2025 due to recent memory management changes.
The bug affects SQL Server when the Lock Pages in Memory (LPIM) Windows policy is enabled and may cause SQL Server crash dumps, SQL Server services to stop or restart unexpectedly, failures during database maintenance operations, memory corruption errors, and access violation exceptions (with 0xC0000005 error codes).
Yesterday, the company also confirmed reports that the 
November 2026 security updates are failing to deploy
 on Windows 11 systems where the October preview update has been installed, with affected users seeing 0x80070306, 0x800f0989, or 0x800f0993 error codes.

Call: Known issue.
 Microsoft has confirmed that Windows updates from October 13 onward can leave SQL Server linked server connections open after the query is done. They pile up and the server slows down. Microsoft says an out-of-band fix is coming “in the next few days.” November’s updates don’t fix it, since they include October’s changes. If your SQL Servers use linked servers to Oracle, PostgreSQL or anything else over OLE DB, start watching connection counts. It’s a slow leak, not an outage, so we wouldn’t pull a month of security fixes over it.
What breaks:
 In Microsoft’s words, “connections created by SQL Server linked server queries might remain open after the queries complete.” Each new query adds more, and “this can slow or degrade server performance after prolonged run time.” It affects linked server queries that use OLE DB providers. Oracle and PostgreSQL are the ones Microsoft names. The tell is a climbing count of open connections to the external database while no linked server queries are running.
Who’s hit:
 SQL Server boxes with OLE DB linked servers, after the October 13 update or anything later. Microsoft lists Server 2025, 2022, 2019 (and 1809), 2016, 2012 R2 and 2012, plus Windows 11 23H2 through 26H1 and Windows 10 1809 / LTSC 2019. The October KBs it names include KB5126646 (Server 2025), KB5126655 (Server 2022), KB5126651 (Server 2019) and KB5126836 (Server 2012 R2). Microsoft opened the issue on November 11. We haven’t seen admin reports outside Microsoft’s own entry yet.
Workaround:
Microsoft has a mitigation for business customers, but you have to get it through Microsoft Support for business. If this is hurting a production server, open the case now rather than when the OOB slips.
For short-term relief, close the idle connections or restart the SQL Server service. Microsoft warns that both can interrupt running queries and transactions, and that the problem comes back.
Graph connections from each SQL host to its linked targets, so you see the climb before your users do. Plan a service restart in a maintenance window if the count keeps climbing.
Install the out-of-band update when it ships. We’ll update this post when it does.
