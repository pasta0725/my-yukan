PCの電源をオフにしてもAIエージェントは働き続ける
一般的な開発環境では、開発対象となるコードはローカルマシン上のファイルシステムに保存されます。そしてそのローカルに保存されたコードを、プログラマやAIエージェントが記述し、ビルドやテストなどを行っていきます。
今回Google Antigravityの新機能として搭載されたリモートエージェント機能は、これをGoogleが管理する分離されたリモートのクラウド環境上で実行してくれるため、手元のPCの状態に関係なく、そのままAIエージェントが作業を継続してくれる、というものです。
これにより、AIエージェントに指示をしたら、あとはお昼休みや出張や就業時間外に手元のPCの電源をオフにしても、AIエージェントはクラウド上でそのまま作業をし続けてくれます。
なにか確認や指示が必要になった場合、ユーザーはスマートフォンなどからいつでもリモート環境で作業しているAIエージェントにアクセスできます。
リモートのAIエージェントが参照するコードや関連ファイルは、GitHubのリポジトリを指定し、Googleドライブからファイルやフォルダを選択したり、デバイスからファイルをアップロードしたりすることで設定できます。
現時点でGoogle Antigravityのリモートエージェント機能は、個人の Googleアカウントでログインしている「Google AI Pro」および「Google AI Ultra」の登録者が利用可能となっています。

In one minute
Google
 is gradually rolling out Antigravity Remote Agents, which run agent sessions and tools in an isolated, Google-managed remote environment. For builders, the practical change is that eligible tasks can continue after a laptop sleeps or a browser closes, without keeping a local machine online. Access is currently limited to personal Google AI Pro and Ultra accounts.
What happened
Google
’s Antigravity documentation describes Remote Agents as a way to run agent sessions and tools in an isolated, Google-managed remote environment rather than on a local machine. The stated benefit is continuity: long-running tasks and command execution can continue when a user closes a browser, puts a laptop to sleep, or switches between desktop and mobile devices. The documentation presents this as a distinct execution mode, not simply a way to view or control a local session remotely.
Remote Agents is being rolled out gradually to subscribers on 
Google
 AI Pro and Google AI Ultra who sign in with a personal Google Account. The documentation says it is not available on the free plan, Google AI Plus, or business accounts using Google Workspace or Google Cloud. It does not provide a price for Remote Agents as a separate product; the listed access condition is an eligible subscription. Users can launch and manage sessions from the Antigravity desktop app, the Antigravity CLI, or a browser at antigravity.google.com. In the browser, a user can start a standalone remote conversation or create a project and add resources.
A remote project can include 
GitHub
 repositories, Google Drive files, and files uploaded from a computer. The app can create a project around an existing GitHub repository, and the CLI can run conversations remotely. The supplied documentation excerpt also says users can unblock permission requests from a phone. These options make the remote environment useful for repository tasks and background work, while allowing access from more than one device.
Google distinguishes Remote Agents from Remote Control. Remote Agents execute in Google’s isolated remote environment and do not require a local machine to stay powered on. Remote Control connects to a user’s own desktop workstation or server, which must remain powered on and online. Remote Control is intended for work needing local hardware, local development servers, local toolchains, or uncommitted local checkouts. The distinction matters: a cloud session needs remote resources, while local work remains tied to the host machine.
The supplied material identifies the relevant Antigravity CLI command as 
agy --remote-agent
 and says this requires CLI version 1.4.12 or later. It also notes that the same v2.29 wave refreshed the interface, voice mode, and Jupyter notebook viewer. Those items are mentioned alongside the rollout, but the documentation excerpt does not specify their detailed behavior or availability separately. The central change documented here is remote execution for eligible agent sessions, with a gradual rollout and account restrictions.

Cursor

Why it matters
For a team that already uses Antigravity, the key operational choice is whether a task depends on the local development environment. Repository work that can use the remote resources listed in the docs may be able to continue without tying up a workstation. That can make overnight or mobile workflows more practical, and may reduce interruptions caused by a sleeping laptop or closed browser.
But moving execution off the laptop is not a universal upgrade. A task that needs a local server, hardware, a local toolchain, or uncommitted files still points toward Remote Control, where the host must remain online. Teams also need to consider which repository and Drive resources they authorize for a managed remote environment. The documentation describes isolated execution, but does not provide enough detail here to evaluate its security controls or compare its operational guarantees with a team's existing setup. Treating the two modes as different deployment contexts, rather than interchangeable buttons, is the useful starting point.

Limits and uncertainty
The source establishes the rollout, account eligibility, supported entry points, resource types, and broad difference between Remote Agents and Remote Control. It does not state a rollout schedule, regional availability, separate usage limits, compute specifications, task-duration limits, or pricing beyond requiring an eligible subscription. It also does not detail the permission model, data retention, isolation guarantees, or how remote environments handle secrets. The claim that work continues while a laptop sleeps describes the intended mode, not a quantified reliability commitment. The excerpt mentions a v2.29 wave and CLI 1.4.12+, but does not give a release date.
Skill to build now
Classify a task before sending it to a remote agent: does it need only a repository or other listed remote resource, or does it depend on a local server, uncommitted checkout, hardware, or toolchain? Try one small repository task through Remote Agents and record any missing local dependency. That gives a concrete basis for choosing cloud execution or Remote Control for the next longer-running job.
Reader takeaway
Antigravity now documents cloud-hosted agent execution for eligible personal Pro and Ultra subscribers. Use it when a task can work from remote resources and should outlast your active session; use Remote Control when the work still depends on your local machine. The availability limits and missing operational details are reasons to test a small task first.

Questions.
Are Antigravity’s remote agents free?
No. Google’s docs say they’re for Google AI Pro and Ultra subscribers on a personal Google Account, and they aren’t “on the free plan, on Google AI Plus, or for business accounts (Google Workspace or Google Cloud).” The November 9 changelog says they reached “Google AI Pro subscribers on a paid plan.” Google AI Pro is $19.99 a month.
Why don’t I see remote agents or voice mode in Antigravity?
Google says both finished rolling out on November 9, 2026, so check the rest. Update the app to 2.29.0 or later, or the CLI to 1.4.12 for remote agents and 1.5.0 for voice mode. Remote agents need Google AI Ultra, or Google AI Pro on a paid plan, on a personal account. Voice mode isn’t for business or enterprise accounts, and Start Voice mode appears only in an empty message box.
Do Antigravity’s remote agents keep working with my laptop closed?
Yes. They run in an “isolated, Google-managed remote environment,” and Google says they keep working when you close your browser, put your laptop to sleep or switch devices. Remote Control is different, because it needs your own computer on and online.
Do remote agents ask before running commands?
Not by default. Google’s docs say the preset is “always-proceed (turbo), so remote agents run commands without asking for approval.” You can change it to default or request review in your remote agent settings.
Can I use voice mode with a remote agent?
No. Voice mode works only in local conversations in the app, not in Remote Control sessions or conversations that run in the cloud, and the CLI doesn’t offer it in remote agent sessions.
Do remote agents replace Jules?
Partly. Like Jules, they run on your GitHub repositories in Google’s cloud, but they need a paid plan, where Jules had a free tier, and their docs don’t mention pull requests or issue labels. You can finish Jules sessions until November 11, 2026.

Remote projects and resources
Section titled ‚ÄúRemote projects and resources‚Äù
While local 
projects
 mount directories from your workstation
under 
Folders
, remote projects attach external context under 
Resources
.
You can attach or remove resources when creating a remote project, or at any
time under 
Project Settings
 > 
Resources
 by clicking 
Add Resource
:
GitHub
: Authorize GitHub with OAuth and select one or more repositories to
attach to the project. Conversations automatically clone and mount your
connected repositories into the remote workspace for development. All private
repositories within the same project must belong to the same GitHub user or
organization owner; to work with private repositories from multiple owners,
create a separate remote project for each owner.
Google Drive
: Select files or folders from your Google Drive (using the
Google Drive Picker on the web interface or the Drive file list in the
Antigravity App), such as Google Docs, Sheets, Slides, PDFs, or folders. The
remote agent reads attached Drive files on demand during conversations.
Uploaded files
: Upload local files from your device (up to 8 MiB per file,
50 files and 100 MiB per project, and 2 GiB total across your account),
including source code, text and data files, images, PDFs, and 
.zip
 archives.
Uploaded files persist across conversations in the project and are staged
under 
/home/antigravity/upload
.
In the Antigravity CLI, run 
/projects
 to attach and remove resources. For
details, see 
Attach repositories and files
