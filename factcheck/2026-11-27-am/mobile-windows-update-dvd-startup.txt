2026年11月、Windows Updateのあとに回復画面や自動修復に戻り、デスクトップまで進めなくなった2台を調べました。どちらも2018年モデルで、Windows 11 26H2 を使っていました。
富士通 LIFEBOOK A748/TX
（FMVA3101BP）では、10月のプレビュー更新 
KB5127936
 が入った状態で、回復画面にエラー 
0xc0000001
 が表示されました。 
富士通の2018年モデル一覧
NEC LAVIE DA700/KAW
（PC-DA700KAW）では、11月のセキュリティ更新 
KB5132061
 が入っていました。プレビュー更新 
KB5132057
 の処理が始まったあと、自動修復を繰り返しました。 
NECの機種別発表日
2台には、DVD書き込みソフトなどが使うCorel（コーレル）製の旧ドライバ 
PxHlpa64.sys
（バージョン 
3.01.01.0
）が残っていました。どちらも、Windowsの起動時にこのドライバを読み込む設定でした。Windowsの保護機能「仮想化ベースのセキュリティ（VBS）」は有効に設定されていました。
富士通には、DVD書き込みソフト
「Roxio Creator LJ」
と、DVD再生用の
「Corel WinDVD」
が入っていました。Corelは、
PxHlpa64.sys
をRoxio製品などのディスク書き込みに使うドライバと説明しています。このことから、今回の富士通では
Roxio Creator LJが導入元の有力候補
です。 
Corelのドライバ解説
NECでは、バックアップ・復元用の
「Roxio BackOnTrack 4.6」
がインストールされていました。 
Roxio BackOnTrackの製品説明
更新を取り消したあとの再起動でも、2台とも同じ症状が続きました。
PxHlpa64.sys
の読み込みを止めると、
正常に起動し、初期化を回避することができました。
 対処後は、2台とも11月のセキュリティ更新 
KB5132061
 を入れた状態で起動できました。
目次
自分のPCが対象か調べる
Windowsが起動するPCなら、
PxHlpa64.sys
 が残っているか、起動時に読み込む設定になっているかを確認できます。この検出ツールは読み取り専用です。設定の変更、ファイルの削除、結果の外部送信は行いません。
PxHlpa64.sys 検出ツールをダウンロード（ZIP）
ダウンロードしたZIPを右クリックして「すべて展開」を選び、展開先にある 
pxdetect.cmd
 をダブルクリックします。Windowsが起動しない場合は、このツールではなく
起動できないPCの復旧手順
をご覧ください。
「起動時に読み込む設定です」と表示された場合：
この記事の2台と同じ起動設定です。表示だけで不具合の原因と決まるわけではありません。不要になった旧ドライバの扱いは、
残った旧ドライバの削除手順
を参照してください。
「無効」または「関連ファイルや登録が残っています」と表示された場合：
ドライバの起動時読み込みが確認されたわけではありません。関連するソフトを今も使っているなら、表示だけを見てファイルを消さないでください。
「見つかりませんでした」と「確認できませんでした」は別です。
 パッケージ内のファイル確認はWindows 11 22H2以降に対応します。起動設定を自分で確認する場合は、
コマンドによる確認手順
をご覧ください。
PxHlpa64.sysが原因と考えられる場合の最短手順
Windows Update後に自動修復や回復画面へ戻り続けるPCで、
古いDVD用ドライバ 
PxHlpa64.sys
 が起動時に読み込まれる設定だった場合
に試す方法です。
古いDVD書き込みソフトを入れた覚えがなくても、購入時から付属していることがあります。PCが起動しないときは本体ラベルや注文メールで型番を確認し、スマートフォンでメーカーの「付属ソフト」「ソフトウェア一覧」を調べます。今回の富士通 
FMVA3101BP
 ではRoxio Creator LJが手がかりになりました。
USBメモリなし
、
USBメモリあり
のどちらか一方で進めます。
USBメモリなし：手動で復旧
回復画面からの手動手順
に進みます。変更前の設定を保存してから、
Start
 だけを 
0x4
（無効）に変えます。対象が見つからない、表示が違う、保存に失敗したという場合は、設定を変更せずに止めます。
USBメモリあり：補助ファイルを使う
復旧補助ファイル（ZIP）
を別のPCで展開し、
pxfix.cmd
 をUSBメモリの最初に開く場所にコピーします。USBから起動する必要はありません。
USBメモリを起動しないPCに挿し、回復画面の［トラブルシューティング］→［詳細オプション］→［コマンド プロンプト］を開きます。BitLockerの回復キーを求められたら、そのPCの回復キーを入力します。
diskpart
、
list volume
 の順に入力します。名前や容量からUSBメモリを見分けてドライブ文字を控え、
exit
 で元の画面に戻ります。
USBメモリが 
E:
 なら 
E:\pxfix.cmd
 を実行します。表示されたWindowsの場所を確認し、
Disable this driver?
 と出たら 
Y
 を入力します。ファイルは条件が一致したときだけ確認を表示し、変更前の設定を保存してから無効化します。

exit

STOP

USB版はテスト環境で動作を確認しています。この記事の実機では手動手順を使いました。
どちらの方法でも、再起動してデスクトップまで進めば起動は復旧しています。DVDドライブが表示されない場合は、
起動後のDVDドライブの確認
に進みます。
旧DVDドライバを無効にする復旧手順
古いDVD書き込みソフトを使っていたPCで同じ症状が出たときは、まず 
PxHlpa64.sys
 の登録を調べます。登録があれば、Windowsの起動時に読み込む設定かを確認します。セーフモードでデスクトップが開く場合と、回復画面しか開けない場合で、調べ方が変わります。
セーフモードで起動できる場合
回復画面から入るには、［トラブルシューティング］→［詳細オプション］→［スタートアップ設定］→［再起動］と進み、表示された一覧で［4］を押します。 
Microsoftのセーフモードの開き方
セーフモードのデスクトップで［Windows］キーを押しながら［R］を押します。開いた画面に 
cmd
 と入力し、［Ctrl］と［Shift］を押したまま［Enter］を押します。
管理者のコマンド プロンプトが開いたら、次の1行を入力して［Enter］を押します。
sc.exe qc PxHlpa64
VBSを一時的に止めて起動できたNECでの表示。上から2行目の 
START_TYPE
 が 
0 BOOT_START
、4行目のパスの末尾が 
PxHlpa64.sys
 です。
結果の 
START_TYPE
 の行に、Windowsがこのドライバをいつ読み込むかが表示されます。
0 BOOT_START
 なら、Windowsが立ち上がる早い段階で読み込む設定です。エラー 
1060
 が出た場合は、このドライバの登録がありません。
0 BOOT_START
 と出た場合は、その行を控えてから次のコマンドで無効にします。
sc.exe config PxHlpa64 start= disabled
成功したら［スタート］→［電源］→［再起動］を選び、デスクトップまで進むか確かめます。 
Microsoftのsc.exe configの説明
回復画面しか開けない場合
［トラブルシューティング］→［詳細オプション］→［コマンド プロンプト］を開きます。次のコマンドを入力し、
C:
 にWindowsの設定ファイル 
SYSTEM
 があるか確認します。
dir C:\Windows\System32\Config\SYSTEM
ファイルが見つからなければ、
C:
 を 
D:
 や 
E:
 に変えて調べます。以下のコマンドでも、実際に見つけたドライブ文字を使います。BitLockerの画面が出た場合は、回復キーでドライブのロックを解除します。
富士通の回復画面では、
E:
 を調べると一覧に 
SYSTEM
 が表示されました。
続けて次の2行を実行します。1行目で設定ファイルを読み込み、2行目で通常起動に使う設定の番号を調べます。
reg load HKLM\RepairSys C:\Windows\System32\Config\SYSTEM
reg query HKLM\RepairSys\Select /v Default
富士通の回復画面。
Select
 の一覧の2行目で、
Default
 の値が 
0x1
 と分かります。
結果の 
Default
 が 
0x1
 なら 
ControlSet001
 を使います。
0x2
 なら、以降のコマンドの 
ControlSet001
 を 
ControlSet002
 に置き換えます。 
NECの回復画面での表示
次のコマンドで、
PxHlpa64
 の登録内容を表示します。
reg query HKLM\RepairSys\ControlSet001\Services\PxHlpa64
富士通 FMVA3101BPの回復画面。画面左側にある 
Start
 の行を右へ読むと、値は 
0x0
 です。撮影時は 
/v Start
 を付けて、この項目だけを表示しました。画像内の一時的な読み込み名はマスクしています。
表示された 
ImagePath
 に 
PxHlpa64.sys
 があることを確認し、
Start
 の行を見ます。
Start
 は、Windowsがこのドライバをいつ読み込むかを決める項目です。
0x0
（数値の 
0
）なら、Windowsの起動時に読み込む設定です。
この場合は、次の1行目で元の登録を書き出し、成功したら 
Start
 を 
4
（無効）に変えます。読み返した値が 
0x4
 になったことを確認してから、最後の2行で設定ファイルを閉じて再起動します。

reg add HKLM\RepairSys\ControlSet001\Services\PxHlpa64 /v Start /t REG_DWORD /d 4 /f
reg query HKLM\RepairSys\ControlSet001\Services\PxHlpa64 /v Start

wpeutil reboot
PxHlpa64の起動設定。上の 
Start
 は変更前の 
0x0
、下は無効化後の 
0x4
 です。
再起動後、デスクトップまで進むか確かめます。登録が見つからない場合や 
Start
 が 
0x0
 と異なる場合は、
reg unload HKLM\RepairSys
 で閉じて別の原因を調べます。変更しても復旧しない場合は、回復画面で同じ登録を開き、控えた元の値に戻せます。
起動できたらDVDドライブを確かめる
DVDドライブが認識されない場合は、CD/DVDドライブの 
LowerFilters
 から 
PxHlpa64
 の登録だけを外し、再起動します。変更する場所は、後述するNECの「起動後にDVDドライバを無効化」で説明します。
富士通とNECの症状と復旧
富士通 FMVA3101BPは旧DVDドライバの無効化で復旧
富士通では電源を入れると回復画面に「PCは正しく起動できませんでした」と表示されました。エラーコードは 
0xc0000001
 です。
富士通 FMVA3101BPの回復画面。「PCは正しく起動できませんでした」と表示されました。
Windowsを必要最低限の機能で立ち上げる「セーフモード」では起動できたため、通常起動時に読み込まれるドライバを調べました。
更新の取り消しなどでは改善しませんでしたが、旧DVDドライバ 
PxHlpa64.sys
 の読み込みを無効にすると、Windowsは正常に起動し、デスクトップが表示されました。データとアプリはそのまま残っています。
起動直後はDVDドライブにエラーコード 
32
 が出ていました。DVDドライブが追加で使うドライバの一覧 
LowerFilters
 に、読み込みを止めた 
PxHlpa64
 の登録が残っていたためです。Windows上でその登録を外して再起動すると、DVDドライブが認識されました。 
Microsoftのエラーコード32の説明
NEC LAVIE DA700/KAWはVBSと旧ドライバの設定変更で復旧
NEC LAVIE DA700/KAW（PC-DA700KAW）では、11月20日に任意のプレビュー更新 
KB5132057
 の処理が始まったあと、起動できなくなりました。 
KB5132057の公開情報
システムの復元や更新の取り消しでは改善しませんでしたが、VBSを一時的に無効にすると通常起動できました。
起動後に旧DVDドライバを無効にしてからVBSを有効に戻すと、データとアプリを残したまま正常に起動できました。
NEC LAVIE DA700/KAWに表示された自動修復の画面。
NECで行ったVBSと旧ドライバの設定変更
VBSは 
Virtualization-based Security
 の略で、日本語では「仮想化ベースのセキュリティ」です。仮想化の機能を使い、Windowsを守る処理をほかの処理から隔離して動かします。 
MicrosoftのVBSの説明
回復画面でVBSを一時的に無効化
NECはセーフモードでも起動できなかったため、回復画面のコマンド プロンプトから作業しました。［トラブルシューティング］→［詳細オプション］→［コマンド プロンプト］で開けます。 
MicrosoftのWindows回復環境の説明
回復画面では、Windowsが入っているドライブの文字が普段と違うことがあります。
dir C:\Windows\System32\Config\SYSTEM
 で設定ファイルがあるか確かめます。調べたときはNECが 
C:
、富士通は 
E:
 でした。暗号化されたドライブの回復キーを求められた場合は、BitLocker回復キーを使います。
内蔵ドライブにあるWindowsの設定（レジストリ）を編集するため、次のように 
SYSTEM
 ファイルを読み込みました。各行を実行し、成功したことを確認して次に進みます。
HKLM\NECVBSLIVE
 は読み込んだ設定に付けた一時的な名前です。 
Microsoftのreg loadの説明
reg load HKLM\NECVBSLIVE C:\Windows\System32\Config\SYSTEM
reg query HKLM\NECVBSLIVE\Select
NECの回復画面。
Select
 の上から2行目が 
Default
 です。
写真の上段にある 
Select
 の一覧では、上から2行目の 
Default
 の右端が 
0x1
 です。これは、通常起動で使う設定一式の番号が 
1
 という表示です。番号を3桁で表した 
ControlSet001
 が、実際に開いた設定の名前です。写真の下段にも、その名前が出ています。
一番下にある 
EnableVirtualizationBasedSecurity
 の右端にも 
0x1
 と出ています。この欄では、VBSが有効という意味です。別のPCを調べる場合は、
Default
 の番号を見て、対応する 
ControlSet
 を開きます。
まずVBSの設定値を調べ、変更前の設定を書き出しました。以下では保存先を 
C:\DeviceGuard-before-vbs-trial.reg
 としています。ドライブ文字は実際に使っているものに合わせます。
reg query HKLM\NECVBSLIVE\ControlSet001\Control\DeviceGuard /v EnableVirtualizationBasedSecurity
reg export HKLM\NECVBSLIVE\ControlSet001\Control\DeviceGuard C:\DeviceGuard-before-vbs-trial.reg
書き出しが成功してから、この値だけを 
0
（無効）にしました。変更後の値が 
0x0
 になったことを確かめ、
reg unload
 で設定ファイルを閉じてから再起動しました。
reg add HKLM\NECVBSLIVE\ControlSet001\Control\DeviceGuard /v EnableVirtualizationBasedSecurity /t REG_DWORD /d 0 /f
reg query HKLM\NECVBSLIVE\ControlSet001\Control\DeviceGuard /v EnableVirtualizationBasedSecurity
reg unload HKLM\NECVBSLIVE
wpeutil reboot
VBSを一時的に無効にした直後の画面。設定行の右端が0x0に変わりました。
Windowsの更新状態はそのままでも、VBSを一時的に無効にすると正常に起動し、デスクトップが表示されました。ここで一時的に止めたVBSは、古いドライバの対処を済ませてから戻します。同じ確認を行っても起動しない場合は、回復画面で設定ファイルを開き、記録した元の値に戻します。
起動後にDVDドライバを無効化
起動後は、変更前の設定を保存してから旧DVDドライバを無効にしました。レジストリエディターから変更する場合は、［Windows］キーを押しながら［R］キーを押し、
regedit
 と入力して開きます。アドレスバーに次のパスを入力します。
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\PxHlpa64
右側にある 
Start
 の値を 
0
（起動時に読み込む）から 
4
（無効）に変更しました。これで次の起動から 
PxHlpa64.sys
 の読み込みが止まります。 
Microsoftのドライバ起動設定の説明
次に、DVDドライブが追加で使うドライバの一覧を、次の場所で確認しました。
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4d36e965-e325-11ce-bfc1-08002be10318}
一覧は 
LowerFilters
 という値に保存されています。このNECで登録されていたのは 
PxHlpa64
 の一行だけだったため、
LowerFilters
 の値を削除しました。ほかのドライバ名も並んでいる場合は、
PxHlpa64
 の行だけを取り除きます。
そのあと再起動し、古いドライバの読み込みが止まり、DVDドライブがエラーなしで認識されることを確認しました。
VBSを有効に戻して起動確認
DVDドライブが認識されたことを確認してから、管理者として開いたPowerShellでVBSの設定を元の 
1
 に戻しました。起動済みのWindows上では、現在使っている設定を 
CurrentControlSet
 から開けます。
$deviceGuard = 'HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard'

再起動後は通常どおりサインインでき、DVDドライブも認識されました。Windowsが報告するVBSの稼働状態は 
2
（有効で実行中）になりました。

MicrosoftのVBSの稼働確認手順
VBSと旧DVDドライバが起動時に干渉する理由
VBSは、仮想化を使ってWindowsの保護処理を隔離する仕組みです。その隔離環境で、ドライバなどがWindowsの中核部分で実行するコードを検査する機能が「メモリ整合性（HVCI）」です。 
MicrosoftのVBSとメモリ整合性の説明
メモリ整合性が有効な環境では、ドライバが使う同じメモリ領域を「書き換え可能」と「実行可能」にすることなどが制限されます。この条件に合わないドライバは、正常に読み込めなかったり、動作中に問題が生じたりすることがあります。Corelも、旧版の 
PxHlpa64.sys
 にメモリ整合性との互換性問題があることを案内しています。 
Microsoftのドライバ互換性の説明
 ·

Microsoftのドライバ起動設定の説明
NECでは、VBSを一時的に無効にすると起動し、
PxHlpa64

更新の数日後、再起動で症状が出る理由
NECの記録では、VBSに関する設定項目が更新されたのは11月11日でした。その後、11月20日朝までの7回の正常起動はすべて高速スタートアップで、VBSが使う保護用のメモリ領域は使われていませんでした。システムを復元したあとも、VBSの有効設定は残っていました。
高速スタートアップでは、前回のWindowsの中核部分（カーネル）とドライバの状態を保存し、次の電源投入で再利用します。一方、［再起動］ではそれらを一から読み込み直します。この違いにより、
保護機能の設定変更の影響が、普段の電源投入ではなく再起動で表面化する場合があります。

再起動で互換性問題が表面化した可能性
VBSの設定が変わった後に何度か電源を入れて正常に使えていたとしても、それだけで新しい設定の下での起動に成功したと判断するのは難しい。
電源投入と再起動の違い
が起動障害の原因を調べる上で重要になる。
Microsoftは互換性を事前に評価する方針
Microsoftは
10月のプレビュー更新KB5127936
に、対応するPCのメモリ整合性を自動的に有効化する変更を導入した。
11月のセキュリティ更新KB5132061
にもこの変更が含まれる。
メモリ整合性（HVCI）はVBSを利用し、Windowsの中核部分で実行されるコードの整合性を隔離された環境で判定する保護機能。Microsoftは
技術文書
で、一部のアプリやドライバとの互換性問題によってまれに起動障害が発生する可能性にも言及している。
Corelの
サポート文書
にも旧版の
PxHlpa64.sys
とメモリ整合性との非互換が記載されている。このドライバを含むライブラリはRoxio製品のほか、ライセンスを受けた他社のディスク書き込みソフトでも使用される。
修理した富士通のPCにはRoxio Creator LJとCorel WinDVDが、NECのPCにはRoxio BackOnTrack 4.6がインストールされていた。
Microsoftは
メモリ整合性の自動有効化に先立ち
、ハードウェアの能力や互換性、性能などを評価する方針を示している。利用者や管理者が既に無効化している場合は、その設定も維持すると説明している。
国内のシステム管理者が公開した別の実機記録では、Windows 11 25H2のHP ProDesk 405 G8でもKB5132061を適用した状態で旧ドライバを無効化して復旧していた。復旧後はVBSが稼働していたが、メモリ整合性は実行されていなかったという。
HPの事例では起動に失敗した時点で保留中だった更新の影響も切り分けられていない。富士通やNECの記録を含め、起動障害が発生した時点でメモリ整合性が稼働していたかまでは特定できていない。
旧ドライバを含めた

起動しなかった起動には、保留中の更新もあった
1台目の Windows Update の記録では、11月19日の12:06に「Windows 11, version 26H2」のダウンロードが始まり、12:28にインストールが始まっています。これは KB5121794 で、24H2 と 25H2 の端末をバージョン 26H2 にする機能更新です。
11月22日に回復環境で確認したとき、KB5121794 と .NET の累積更新は「Install Pending」（インストールの保留）でした。起動した後の確認では、2つとも「Staged」になり、.NET の以前の版が11月22日の10:18に Installed に戻っていました。Windows のバージョンは 25H2 のままです。
このため、起動しなかった起動は、「値が 1 になってから最初の起動」であると同時に、「保留中の更新がある起動」でもあります。PxHlpa64 を無効にすると起動したことは記録で確かめられました。一方で、値が 1 だったことの影響と、保留中の更新の影響は、この記録では分けられていません。

reg load HKLM\OFFSYS C:\Windows\System32\config\SYSTEM
set P=HKLM\OFFSYS\ControlSet001\Services\PxHlpa64

1行目で、起動できない Windows のレジストリ（SYSTEM）を OFFSYS という名前で読み込みます。2行目は、PxHlpa64 の登録場所を P という短い名前に置き換えています。長い行は途中で Enter を押すと失敗するためです。3行目と4行目で、DeviceGuard の値と PxHlpa64 の登録を表示します。5行目で Start を 4 に変更し、6行目で変更後の値を表示します。7行目で、読み込んだレジストリを保存して閉じます。
ControlSet001 を指定したのは、Select キーの Current が 1 だったためです。

VirtualizationBasedSecurityStatus の値は、Microsoft Learn の説明では、0 が「VBS は有効になっていない」、1 が「有効だが実行されていない」、2 が「有効で実行中」です。
1台目が起動しなかったときは、PxHlpa64 の Start が 0 で、EnableVirtualizationBasedSecurity が 1 でした。1台目は、DeviceGuard キーが更新されてから次の再起動までの5日間は動き続け、その再起動で起動しなくなっています。
3台目は KB5132061 を適用済みですが、確認した時点で PxHlpa64 は無効で、EnableVirtualizationBasedSecurity は値そのものがありませんでした。
PxHlpa64 を無効にするために使ったコマンド
2台目では、起動した後に PxHlpa64 を無効にしました。使ったスクリプトの中心は次の3行です。管理者として開いた PowerShell で実行します。
reg export "HKLM\SYSTEM\CurrentControlSet\Services\PxHlpa64" <保存先> /y
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\PxHlpa64" -Name Start -Value 4 -Type DWord
(Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Services\PxHlpa64").Start
1行目で、変更前の PxHlpa64 の登録内容をファイルに書き出します。<保存先> には、書き出すファイルの場所を指定します。2行目で Start を 4 に変更し、3行目で変更後の値を表示します。2台目は、実行後に再起動して、PxHlpa64 が Stopped、Disabled になったことを確認しました。
この操作も、Microsoft が案内している手順ではありません。Corel のサポート資料は、PxHlpa64.sys を入れたソフトを特定し、削除するか対応した版に入れ替えることを案内しています（Corel の資料で、Microsoft の資料ではありません）。
無効にした後の影響
Microsoft Learn の説明では、Start が 4 のドライバーは無効で、読み込まれません。ドライバーが無効になっている機器は、デバイス マネージャーで Code 32 と表示されます。
PxHlpa64 は、CD/DVD ドライブのクラスの LowerFilters に登録されていました。Microsoft のサポートページには、CD/DVD ドライブが認識されない場合に UpperFilters と LowerFilters を削除する手順があります。削除した後は、CD/DVD の書き込みソフトが正しく動かなくなることがあるとも書かれています。
調べた端末には DVD ドライブがなく、ドライブの認識や書き込みの動作は確認していません。PxHlpa64 を無効にした後に確認できたのは、Photoshop Elements 12 が起動することだけです。

：値が 1 だったことの影響と、保留中の更新の影響は分けられていません。

：EnableVirtualizationBasedSecurity を 1 にしたものが何かを示す記録はありません。1 になる前の値も分かりません。
再発するか
：PxHlpa64 の Start を 0 に戻すと再び起動しなくなるかは、試していません。
復帰後の再起動
：1台目は、復帰した後に再起動していません。
別の機種
：先に紹介した Dell 製の端末が同じ組み合わせだったかは、今回の方法では調べていません。

：国内の記事には、起動用の領域の空き不足で起動用のファイルが消えていた事例や、BIOS で仮想化機能をオフにして起動した事例の報告もあります（第三者の情報です）。KB5132061 の後に起動しない端末が、すべてこの記事の組み合わせとは限りません。
