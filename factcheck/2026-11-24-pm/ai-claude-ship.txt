Anthropic、PRのレビューから修正、承認までをAIで支援する「Claude Ship」公開
公開
2026年11月24日 10時21分
[ITmedia]
印刷する
Googleで優先するソースとして追加
　米Anthropicは11月23日（現地時間）、AIエージェントがプルリクエスト（PR）のレビューや修正を行い、チームが定めたポリシーに従って承認を判断する「Claude Ship」を発表した。
3月に提供を始めたコードレビュー機能「Code Review」
と、新たなAIエージェント「PR Steward」「Claude Approvals」で構成する。Claude Ship全体はβ版として提供する。
（画像：Anthropic）
　対象は「Claude」の「Team」「Enterprise」プランのユーザーで、GitHubのリポジトリで利用できる。エージェントをどこで稼働させるのかや、どの変更に人間の承認を必要とするかは、チーム側で設定できる。
　既に一般提供しているCode Reviewは、複数の観点からPRを詳しくレビューする機能だ。見つけた問題を検証・分類した上で、PRにコメントとして投稿する。レビューの深さは、リポジトリごとに「Quick」「Standard」「Deep」の3段階から選べる。Anthropicによると、Claude Codeの開発チームでは、6月から9月にかけてマージしたPRの数が2倍以上に増え、マージ後に変更が取り消されたPRの割合は40％以上減少したという。ただし、同チームではCode Reviewを他のレビュー手段と併用している。
　PR Stewardは、継続的インテグレーション（CI）の失敗やマージコンフリクト、レビューコメントに対応し、PRをマージ可能な状態に保つエージェントだ。承認やマージ自体は行わない。変更をプッシュするたびに、何を変更したかと、その変更を元に戻す方法をコメントに残す。開発者は「@claude」と書いて作業を指示でき、「@claude stop」で停止できる。
　Claude Approvalsは、チームがリポジトリ内のファイルに記述した承認ポリシーに従って、PRを承認するかどうかを判断する。コードの担当者を指定する「CODEOWNERS」ファイルを拡張したような仕組みだ。ポリシーで許可すれば定型的な変更を自動承認でき、特定の変更には人間の承認を必須にできる。判断材料にはCode Reviewの指摘や、自然言語で定義した分類器を利用できる。
　Anthropicは、まず承認せずに判断結果を確認する「観察専用モード」で試すことを推奨している。十分に信頼できると判断した段階で、ブランチ保護の設定によってClaude Approvalsの承認を必須にできる。
Claude Shipでレビュー、修正、承認が進む流れ（画像：Anthropic）
　開発者がClaude Codeで新コマンド「/ship」を実行すると、Claudeがコードのプッシュ、PRの作成、レビュー、指摘事項や失敗したチェックへの対応まで進める。マージできるかどうかは、開発者の権限とリポジトリのブランチルールによって決まる。/shipは同日から、Claude Codeとデスクトップアプリで順次提供する。
　管理者がリポジトリ単位でClaude Shipを有効にすれば、開発者が/shipを実行しなくても、チームのPRに自動で適用される。管理者はレビューの深さや実行タイミング、月額の利用上限を設定できる。Claude Approvalsは、接続済みリポジトリのデフォルトブランチにポリシーファイルを配置すると動作を開始し、管理者が無効化することもできる。既存のブランチ保護や必須チェックとも併用可能だ。
　料金はトークン使用量に応じた従量課金で、PRの数や規模、レビューの深さや頻度、PR Stewardの作業量によって変わる。Claude Approvals自体に基本料金はかからないが、ポリシー内の分類器にはトークン使用量に応じた料金が発生する。Claudeのレビューを呼び出すポリシーでは、観察専用モードでもCode Reviewの料金が発生する。/shipの実行は通常のClaude Codeの利用として扱う。
　条件を満たすEnterpriseプランの組織は、最低1万ドル分のClaude Ship用クレジットを申請できる。申請期限は2027年1月15日で、申請から30日以内に利用する必要がある。
　一方、データを保持しない契約条件である「Zero Data Retention」や、HIPAA（米国の医療情報保護法）対応構成を利用する組織、顧客管理の暗号鍵を利用する組織は対象外となる。
　なお、AnthropicはClaude Shipについて、AIがバグやセキュリティ上の脆弱性などを見逃す可能性があると注意を促している。

Anthropic launches Claude Ship to help AI agents review, fix and approve code changes
Anthropic has launched Claude Ship, a new suite of AI agents that can review code, fix pull request issues and automatically approve routine code changes.

AI Quick Read
Anthropic on Monday launched Claude Ship, a new suite of AI agents designed to automate code reviews, fix software development issues and approve routine code changes. The new offering will help development teams manage the increasing volume of code generated by AI tools and reduce the time they wait for software updates to be ready for release, said the company.
Claude Ship integrates automated code reviews, pull request fixes, and AI-based code approvals for Claude Team and Enterprise subscribers who use GitHub repositories. With the launch, the company aims to change how it uses AI to assist with coding, this time extending automation not only to code creation but also to code review and approval processes before code goes live.
Claude Ship introduces three AI-powered tools
According to Anthropic's official announcement, 
Claude 
Ship consists of three key components: Code Review, PR Steward and Claude Approvals.
A new feature, Code Review, evaluates proposed code changes and looks for issues. In the meantime, PR Steward and Claude Approvals are in beta.
PR Steward is meant to address common problems in pull requests (PRs): failed continuous integration (CI) checks, merge conflicts and feedback during code reviews. The agent can also make corrections and post comments explaining what it changed and how developers can reverse those changes if necessary.

Claude Approvals can approve code changes automatically
The most significant new feature is 
Claude 
Approvals, which enables AI agents to approve code changes according to rules set by development teams.
In software repositories, teams can develop approval policies in a file, Anthropic says. These policies may be written in natural language and may take into account various aspects such as code review results and the company's classifiers.
This may reduce the amount of manual approval required for routine code changes from developers. However, teams can still decide which changes require human intervention and set rules for escalating more complicated decisions.

Anthropic recommends starting with observe-only mode
Since Claude Approvals is still in beta, 
Anthropic 
recommends that development teams initially use its observe-only mode. This will enable teams to evaluate the AI's decision-making before granting it full approval authority.
There is also the option to start with one repository and set monthly budgets for use. Teams control where Claude operates and can choose from review settings such as Quick, Standard and Deep.
Anthropic says Claude Ship is rolling out the Claude Team and Enterprise plans for GitHub repositories. PR Steward and Claude Approvals are still in beta, while Code Review is available.

Anyone who has opened a pull request knows how this goes. They start on the next thing, and then the review comes back. So they stop, dig back into the old code, push a fix, and wait for the review to run again. Then they go find someone to approve it.
There's a good reason it works this way. Most teams want a person to approve every change, and that's easy to keep up with when people write every line. But a lot of developers build with agents now. On the Claude Code team, 
Claude writes most of our code
, and we wanted everything after the PR to move that fast too.
That's why we built 
Claude Ship
, available today in beta. It can review PRs, fix them, and decide what's ready to merge based on policies each team sets. Teams stay in control of where it runs and which changes need a person. The goal: ship code as fast as teams write it.
Eligible Claude Enterprise organizations can claim at least $10,000 in Claude Ship credits to use within 30 days of claiming. Claim by January 15, 2027. 
Terms apply.
How Claude Ship works: review, fix, and approve
Claude Ship is made up of 
Code Review
, which is already generally available, and two new agents in beta: PR Steward and Claude Approvals. Together, they take a pull request through review, fixes, and an approval decision so teams don't have to manage each step manually.
Code Review
 performs an in-depth review of pull requests against the codebase through multiple lenses. It collects findings, adversarially verifies them, categorizes them, and posts them to a PR. On the Claude Code team, where Claude's review is one layer of a broader process, merged PRs 
more than doubled
 from June to September while the share reverted fell by more than 40%. Code Review gives teams fast reviews, clear findings, and a choice of Quick, Standard, or Deep review levels for each repository.
PR Steward
 works to keep a PR green, but is designed not to approve or merge pull requests. It jumps in on failing CI checks, merge conflicts, and review feedback from Code Review, other review tools, or team members. After every push, it comments with what it changed and how to undo it. Developers can comment 
@claude
 with an instruction to steer the work, or 
@claude stop
 to have it step back.
From there, 
Claude Approvals
 applies an approval policy that the team writes as a file in the repository. Claude can approve routine changes on its own if the policy allows it, or can require deeper human sign-off for certain scenarios. It works like a smarter CODEOWNERS file. Teams can have Claude Approvals consider a variety of signals in its decision-making process, including Code Review findings or their own classifiers using natural language. For most customers, we recommend enabling this first in observe-only mode to build confidence before configuring branch protection to require Claude Approvals' green light.
Two ways to get started
For developers: 
/ship
 it from Claude Code
Developers can try Claude Ship on their own pull requests with the new 
/ship
 command in Claude Code. When a change is ready, they run 
/ship
. Claude pushes it, opens the PR, reviews the change, and works on feedback and failing checks to help get it ready to merge. What can merge depends on the developer's permissions and the repository's branch rules.
For admins and engineering leaders: set the rules, one repository at a time
Turning Claude Ship on for an entire repository puts it to work across a team's pull requests automatically, under settings and an approval policy the team controls. Developers don't need to manually invoke the 
/ship
 command.
Admins choose where
it runs.
 An admin turns on Code Review and PR Steward for each repository. Claude Approvals starts when a connected repository has a policy file on its default branch, and an admin can turn it off.
Each
repository gets the settings it needs.
 Admins choose the review level (Quick, Standard, or Deep), choose when reviews run, and configure spend limits.
Teams keep the tools they have.
 Claude Ship works with existing branch protection and required checks.
Teams set the pace. They can start with one repository, choose a review level and when reviews run, set a monthly spend limit, and run their approval policy in observe mode until they trust it.
How the Claude Code team ships
We run Claude Ship on many of our own pull requests. One of the biggest changes is who can act on customer feedback. For example, a product manager on the Claude Code team can now read a piece of feedback, talk through ideas and tradeoffs with Claude Tag, have it open a PR, and move on to the next thing while Claude Ship takes it through review, fixes, and an approval decision.
Recently, a customer was confused because our Analytics API documentation implied an Admin key could pull Pro and Team usage. The PM asked Claude Tag whether a fix was in flight, and it opened one. Code Review found nothing blocking, a docs reviewer signed off, Claude Approvals passed, and the fix merged that same evening.
What customers are saying
“We have had numerous cases where Claude Code Review caught real issues before a human reviewer got to the pull request, and PR Steward helped the contributor fix them. Our reviewers were already using Claude Code to keep up with the volume, so having Code Review, PR Steward and Claude Approvals start automatically when a pull request opens makes that simpler. We keep a human in the loop, and the human’s time now goes to the changes that need it.”
Vatsal Bhatt, Director of Engineering
“PR Steward is helping teams in our pilot spend less time working through code review feedback and more time building. We can tailor it to our teams’ processes, including how it suggests changes and organizes feedback. That flexibility has made it a useful part of the development workflow.”
Alex Devkar, Senior Vice President, Engineering and Analytics
Availability
Claude Ship is available on Claude Team and Enterprise plans for repositories on GitHub. Code Review is 
generally available
, and PR Steward and Claude Approvals are in beta.
Claude Ship usage is billed on tokens, so turning it on can add to an organization’s costs. The amount depends on the number and size of pull requests covered, the review level, how often reviews run, and how much work PR Steward does. Admins can set spend limits for Code Review and PR Steward. Claude Approvals has no base charge, but classifiers in a policy are billed on the tokens they use, and a policy that uses Claude's review triggers a billed Code Review, even in observe mode. Running 
/ship
 counts as regular Claude Code usage.
Claude Ship is not available to organizations with Zero Data Retention, the HIPAA configuration, or customer-managed encryption keys.
Get started
Developers can update Claude Code and run 
/ship
 on their next change. 
/ship
 is rolling out in Claude Code and the desktop app starting today.
Teams already using Code Review can add PR Steward on a repository, and an approval policy in observe mode.
Teams new to Code Review can read the 
setup guide
 to connect GitHub and turn on their first repository.
