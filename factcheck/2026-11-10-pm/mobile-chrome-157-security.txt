GoogleがChrome 157を提供開始　多数の脆弱性を修正
　Googleは11月3日、デスクトップ向け「Google Chrome」の最新版「Chrome 157」を安定版として公開した。バージョンはWindows／Macが157.0.8103.38／.39、Linuxが157.0.8103.38で、今後数日から数週間かけて順次配信する。
Googleがデスクトップ版Chromeブラウザの最新版をリリース
　このアップデートには、計213件のセキュリティ修正が含まれている。深刻度の内訳は、4段階で最も高い「Critical」が7件、2番目の「High」が77件、「Medium」が75件、「Low」が54件だ。
　Criticalの7件は、解放済みメモリの使用（Use after free）が4件、バッファーオーバーフローが2件、メモリ破損が1件で、GPU関連のDawn、ANGLE、WebGLの他、Prerender、Geometry、Coreが対象となっている。なお、今回修正された脆弱（ぜいじゃく）性について、Googleは悪用の事実を公表していない。
　Chromeを既にインストールしている場合は順次自動更新されるが、メニューの「ヘルプ」→「Google Chromeについて」を選ぶと手動でも更新できる。
OpenAIが「ChatGPT」の「Chat」と「Work」タブを統合へ
　OpenAIは、ChatGPTの「Chat」と「Work」を1つの画面に統合する計画を明らかにした。同社はサブスクリプションユーザー向けのメールで、今後数週間のうちに少数のユーザーを対象にテストを始めると案内した。参加者の意見を踏まえて改善した後、提供範囲を広げるという。
ChatGPTのChatとWorkタブが統合され、ChatGPTとCodexの利用枠も共通になる
　現在のChatGPTでは、質問や会話はChat、調査や資料作成など複数の手順にまたがる作業はエージェントのWorkと、トグルなどで切り替えて使い分ける必要がある。統合後は、アイデアを対話で検討する段階から、ファイルやプラグインを使ってWebサイトやプレゼンテーションを作らせる段階までを、1つの画面で続けて進められるようになる。なお、開発向けのCodexは引き続き別の画面として残る。
　併せて、利用枠の仕組みも変わる。OpenAIのヘルプページによれば、12月からPlus、Pro、BusinessプランではChatGPTとCodexの利用枠が共通になる。WorkのエージェントをChatGPT本体に取り込むことに伴う変更で、利用量はトークン単位で計測され、高度なモデルや複雑なタスクほど多くの利用枠を消費する。一方、即答向けの「Instant」でのチャットは利用枠を消費しない。
　OpenAIは、ほとんどのユーザーにとって、利用枠のリセットを待つ頻度は今と変わらない見込みだとしている。残りの利用量とリセット時刻は「設定」の「使用状況」で確認でき、上限に達した場合は、リセットを待つ他、プランのアップグレードやクレジットの購入で利用を続けられる。

　うっかり見逃していたけれど、ちょっと気になる――そんなニュースを週末に“一気読み”する連載。今回は、11月1日週を中心に公開された主なニュースを一気にチェックしましょう！
「ChatGPT Classic」デスクトップアプリ、2027年1月30日で提供終了
　OpenAIは、ChatGPTの旧デスクトップアプリ「ChatGPT Classic」の提供を2027年1月30日に終了する。現在、Classicを起動すると提供終了を告げるダイアログが表示され、新しいChatGPTデスクトップアプリのダウンロードが案内される。ダイアログでは、チャット履歴は全て引き継がれ、前回の続きから再開できると説明している。
ChatGPT Classicの提供が2027年1月30日に終了する
　同社は7月9日、Chat（質問や会話）、Work（調査・分析や、文書、スプレッドシート、プレゼンテーションの作成）、Codex（ソフトウェア開発）を1つにまとめた新しいデスクトップアプリを、macOSとWindows向けに公開していた。
　従来のアプリは「ChatGPT Classic」の名前で残り、移行は必須ではなかった。モデルの更新やバグ修正、セキュリティパッチの提供は継続する一方、WorkやCodexといった新しいエージェント機能は新アプリでのみ使えるとしていた。今回の告知で、Classicを使い続けられる期間に区切りが付いた形だ。
　なお、移行手順を案内するOpenAIのヘルプ記事「Moving to the new ChatGPT desktop app」は、11月6日時点では終了日に触れておらず、Classicを引き続き使えるという記述のままだ。
Bluetooth SIGが新機能「High Data Throughput」の採択を発表　通信速度が最大7.5Mbpsに
　Bluetooth SIG（SIG）は11月4日、Bluetooth Low Energy（LE）の通信を高速化する新機能「Bluetooth High Data Throughput（HDT）」を正式に採択したと発表した。HDTは「Bluetooth Core 7.0」にオプション機能として盛り込まれている。
Bluetooth SIGが新機能Bluetooth HDTの採択を発表した
　HDTは、Bluetooth LEにノイズや干渉に強い変調方式を備えた新しい物理層（PHY）を追加するもので、最大ビットレートは7.5Mbpsに引き上げられる。現行のLE 2M PHY（2Mbps）の4倍近い。SIGが7月に公開したブログによれば、変調方式にはQPSKとQAMを使い、ビットレートは2／3／4／6／7.5Mbpsの5段階となる。
　パケットごとにレートを切り替えられるため、電波状況に合わせて速度と安定性のバランスを取ることができる。会員企業による初期のデモでは、現行方式では16秒ほどかかる数MBのファイル転送が、約4秒に縮まったという。
　SIGは速度に加え、周波数の利用効率、省電力性、通信の安定性も同時に高まるとしている。データを短時間で送り終え、無線部分が低消費電力の状態で過ごす時間を長くできるためだ。
　最初の主要な用途として挙げるのはワイヤレスオーディオで、ロスレスやハイレゾ音源の伝送、マルチチャンネルのサラウンドや空間オーディオに向けた仕様の標準化を進める。SIGはこれらの仕様を2027年にリリースする見込みだ。この他、XRやスマートグラス、AI処理を伴うデバイス、スマートウォッチのセンサーデータ同期、ファームウェアのアップデートなどでの活用を想定している。

===== https://www.securityweek.com/chrome-157-rolls-out-with-213-security-fixes-seven-rated-critical/
(status 200)
Google has promoted Chrome 157 to the stable channel with patches for 213 vulnerabilities, including seven critical memory safety bugs.
At the top of the list is a buffer overflow issue in Dawn, the open source and cross-platform implementation of the WebGPU standard. It earned the reporting researcher a $10,000 reward.
The second is a memory corruption in the open source graphics engine abstraction layer ANGLE that was awarded a $1,000 bug bounty.
No rewards were listed for the remaining five critical flaws (four use-after-free defects and a buffer overflow). Google reported two of them, Anthropic’s Xinyang Ge reported two, and researcher Wenbin Liu reported the fifth.
Chrome 157 also fixes 77 high-severity vulnerabilities, including more than a dozen reported by external researchers. However, Google has disclosed only the bounties paid for two of them, namely $10,000 for an incorrect authorization, and $2,000 for an out-of-bounds read.
Per Google’s 
advisory
, the company handed out $31,000 in rewards to the reporting researchers, but it has not determined the bug bounties to be paid for 39 of the flaws.
Advertisement. Scroll to continue reading.
The most common types of vulnerabilities the fresh browser update resolves include incorrect/missing authorization (51), use-after-free (45), UI misrepresentation (19), type confusion (13), information leak (13), out-of-bounds read/write (11), improper input validation (9), and uninitialized resource (9).
Google makes no mention of any of these security defects being exploited in the wild, but users should update their browsers as soon as possible.
The latest Chrome iteration is now rolling out as versions 157.0.8103.38/.39 for Windows and macOS, and as version 157.0.8103.38 for Linux.
