Webサイトの7割が「PHP」を利用　影響範囲は？
　PHPは、WebサイトやWebアプリケーションの開発に使うプログラミング言語で、ユーザーの操作を反映する「動的なページ」を作成できることが特徴だ。Webサイトの「問い合わせフォーム」「ログイン機能」や、ECサイトの「ショッピングカート機能」、他にも掲示板やSNSのような機能を実装できるため、多くの企業が採用している。

　ただし、11月19日夜に修正プログラムが公開される脆弱性のうち、深刻度がCriticalの脆弱性による影響を受ける環境は一部に限定される。The PHP Groupは、Criticalな脆弱性が悪用されるのは「デフォルト以外の設定、または通常と異なる設定をしている場合」と説明している。

PHP開発チームは11月18日（現地時間）、公式サイトで「
Upcoming Critical PHP Security Release
」と題した告知を公開し、11月19日にセキュリティアップデートを提供する予定であることを明らかにした。
PHPに再び「致命的」な脆弱性が見つかった
PHPの全サポート版にセキュリティ更新、深刻度は最大「Critical」
今回の更新は、PHPが通常実施している4週間ごとのリリースサイクルの一環として提供される。修正対象には、サポートされているすべてのPHPバージョンに影響するセキュリティ上の脆弱性が含まれており、最も深刻なものは「Critical」に分類される。
ただし、Criticalと評価された脆弱性については、PHPのデフォルト設定以外の構成、または一般的ではない環境でのみ影響を受けると説明している。すべてのPHP環境で同じ深刻度の問題が発生するわけではない点に注意が必要だ。
現時点では、脆弱性の具体的な技術情報や修正対象となるバージョン番号は公開されていない。これらの詳細は、セキュリティアップデートの公開と同時に明らかにされる予定だ。
企業のWebサイト管理者はアップデートの準備を
PHPは、企業のWebサイトやWebアプリケーションなどで広く利用されているプログラミング言語だ。PHP本体に脆弱性が存在する場合、利用しているバージョンやサーバの構成によっては、Webサービスのセキュリティに影響する可能性がある。
PHP開発チームは、今回の脆弱性に関する詳細情報を修正版の公開時に提供するとしており、利用者に対して、公開後速やかにアップデートできるよう準備することを強く推奨している。
企業のシステム管理者やWebサイト運用担当者は、自社のサーバで稼働しているPHPのバージョンや設定を確認するとともに、修正版の公開後に影響範囲を確認し、必要な更新を進めることが望まれる。
なお、PHPでは10月21日にも、認証なしでリモートから任意のコードを実行される可能性がある2件のCritical脆弱性に対応したセキュリティアップデートが公開されている。今回の更新は、それに続くセキュリティ対応となる。

PHP security updates fix 18 flaws, including critical RCE bugs
                            By 
Lawrence Abrams
November 19, 2026
11:28 AM
0
The PHP dev team released security updates for 18 vulnerabilities, including critical flaws that could allow unauthenticated attackers to remotely execute code on vulnerable servers.
The updates were released Thursday, November 19, for all supported PHP branches, with PHP 8.5.13, 8.4.28, 8.3.37, and 8.2.36 now available.
Security firm 
Aikido reports
 that the updates address 18 CVEs affecting PHP's core engine, session handling, PHP-FPM, CGI, and other components.
One of the most serious flaws, tracked as CVE-2026-129289, is a critical PHP-FPM request smuggling vulnerability with a CVSS score of 9.2.
According to Aikido, the flaw allows unauthenticated attackers to execute PHP code remotely on vulnerable servers that reuse connections to PHP-FPM under certain conditions.
The vulnerability affects certain nginx, Apache, HAProxy, and LSAPI configurations that reuse backend connections to PHP-FPM.
Standard nginx and Apache configurations that do not reuse backend connections are not affected by the attack.
Other important vulnerabilities fixed in the updates include:
CVE-2026-129474:
 A use-after-free vulnerability involving magic method backtraces that could lead to remote code execution.
CVE-2026-129496:
 A timezone cache use-after-free vulnerability that could lead to remote code execution.
CVE-2026-126714:
 A vulnerability involving partially overwritten session files that could lead to remote code execution.
CVE-2026-115560:
 A session serializer mismatch vulnerability that could lead to remote code execution.
CVE-2026-129291:
 A PHP-FPM epoll use-after-free vulnerability that could lead to local privilege escalation.
CVE-2026-128090:
 A PHAR OpenSSL signature bypass vulnerability involving an algorithm downgrade.
Additional fixes address memory corruption, information disclosure, cross-site scripting, denial-of-service issues, and potentially unsafe handling of HTTPS and FTPS URLs.
The releases follow a warning issued Wednesday by the PHP security team that the upcoming updates would address vulnerabilities affecting all supported PHP versions, with the highest severity rated critical.
"The issues rated CRITICAL require either non-default configuration or uncommon setups," the PHP security team 
warned
.
One of the vulnerabilities, CVE-2026-115560, was already disclosed in an 
October 23 informational advisory
 and relates to how PHP handles session data under certain configurations, potentially leading to remote code execution.
As a temporary mitigation, PHP recommended disabling session upload progress by setting 
session.upload_progress.enabled=0
 and restarting PHP workers. This setting was also recommended to mitigate the recent 
PHP2Shell flaws
.
For CVE-2026-129289, administrators who cannot immediately install the security updates can mitigate the vulnerability by disabling persistent backend connections between their web servers and PHP-FPM, ensuring connections are closed after each request.
Aikido warns that these mitigations do not address all vulnerabilities fixed in the November updates and recommends ensuring PHP-FPM and LSAPI listeners are not directly exposed to untrusted networks.
Although the official security updates are limited to supported PHP branches, third-party maintainer Ondrej Surý has also 
released patched packages
 for unsupported PHP versions dating back to PHP 5.6.
Aikido has similarly released 
hardened PHP container images
 containing backported security fixes for unsupported versions, including PHP 5.6, 7.0, 7.1, 7.2, 7.4, and 8.1.
PHP administrators are urged to upgrade to PHP 8.5.13, 8.4.28, 8.3.37, or 8.2.36, depending on their supported branch, to address the newly disclosed vulnerabilities.
