Claude Enterprise has new security and admin features, including a security center, generally available inference hooks, centralized management, and additional access controls.
To see how Claude is set up, the security center shows how your organization’s Claude settings compare with Anthropic’s recommended configuration. To apply your policies, inference hooks send prompts and tool calls to your data security tools for a check. To manage access, centralized management gives your company one admin console for company-wide settings, and new access controls let you sign members out through the Admin API, manage your IP allowlist yourself, and help prevent shadow IT by blocking personal and other outside Claude accounts in Claude Desktop on managed computers.
We also recently announced an Endpoint Detection and Response (EDR) integration, which runs your organization's sensor inside the 
unified Claude
 and Cowork virtual machine on the user's computer.
Security teams need to see how Claude is configured, what it does on company devices, and how data is handled as people work. These features give them that visibility and control.
Security center: review your Claude security settings in one place
Security teams can review Claude's security settings for chat, Cowork, and Claude Code on one page, instead of setting by setting. The security center is a new page in Organization settings that compares settings with Anthropic's recommended configuration, so your team can see what to change and where to change it.
For each control, the security center shows the current value, the recommended value where there is one, and a link to the setting where you can change it. It also shows which settings are new or recently changed. The security center checks your configuration each time the page loads, so automatically checked controls reflect your current settings. Organizations with the Compliance API can read the same results through it.
Attestations give your admins a shared workspace for security reviews. They can work through the process together once, recording the current state of each control, accepting risks, and flagging issues in one place.
You can download the security center page as a report to share with auditors and relevant stakeholders. The report marks which controls the page checked automatically and which an Owner confirmed. The security center is guidance based on Anthropic's recommendations, not a certification or a guarantee of compliance with any law or standard.
Inference hooks
Inference hooks connect Claude to the data security tools your organization already uses, so your data loss prevention (DLP) and security policies can apply to prompts and tool calls as people work.
There are two kinds of hooks, both now generally available:
Prompt hooks send prompts from supported Claude products to your security tool for a check.
Pre-tool-call hooks check tool calls in supported Claude products before they run.
Hooks work with security vendors. Your team keeps the policies it has already written and applies them to Claude.
Centralized management: one console for identity and access across your organization
Centralized management gives your parent organization, which represents your company across its Claude Enterprise and Claude Platform organizations, its own admin console at admin.claude.com. Admins manage company-wide settings there once for the organizations under your parent, instead of from individual organization settings. These settings include single sign-on, directory sync (SCIM), domain verification, groups, and Compliance API keys.
The console shows every organization under the parent in one place and adds two roles. Parent organization owners can manage everything at the parent level, including who holds the owner and admin roles. Parent organization admins can manage everything except those role assignments.
Companies can also connect more than one identity provider, each with its own single sign-on and SCIM configuration. An acquired company can keep its existing provider, or your team can move to a new provider one domain at a time.
Each organization keeps its own members, roles, settings, and organization-level security controls, such as IP allowlisting, tenant restrictions, and session duration. A parent role doesn't grant access inside an organization by default, but Compliance API keys created at the parent can read data across organizations.
Access controls: member sign-out and shadow IT prevention  
Security teams can now sign a member out of Claude with a single Admin API call, without removing them from the organization. The call ends that member's sign-in sessions on every browser and device, and apps like Claude Code have to sign in again. It doesn't end API keys, cloud sessions already running, or scheduled routines, and the member can sign in again afterwards.
Enterprise admins can now set up and manage their IP allowlist themselves, without going through Anthropic. An IP allowlist limits access to most Claude products to the IP addresses your organization approves.
Admins can now set the most-used Claude Desktop settings, with no device management push. To help prevent shadow IT, admins can also block personal and other outside Claude accounts in Claude Desktop on managed computers. Owners can also limit which workspace folders people can use with Claude.
Endpoint Detection and Response (EDR) in Cowork and unified Claude
When Cowork and unified Claude work locally, they run shell commands and code in an isolated virtual machine on the user's computer for additional protection. That isolation helps protect the device, and security teams have asked for the same visibility into the virtual machine that they have everywhere else on the endpoint.
Admins can now run their organization's EDR sensor inside the Cowork virtual machine. The sensor reports activity there to the same console your security team already monitors. This covers the virtual machine on the user's computer, not Cowork sessions in the cloud.
Admins set up the integration through device management on macOS and Windows. Each time the virtual machine starts, Claude verifies the sensor package's signature from your EDR vendor before installing it. Sensors run in detection mode: they report activity to your security team and don't block it. The integration works with supported EDR vendors, which are listed in the 
Help Center
.

Admins of the other organizations review and approve, and the last approval completes setup. Setup can't be undone, so identify your parent organization admins before you start.

CrowdStrike Secures AI Agents Inside Claude Cowork
Built in partnership with Anthropic, this integration extends Falcon protection to AI agents across their lifecycle, from agent creation through job execution.
November 03, 2026
•
                Michael Devins
•
Securing AI
When Claude Cowork executes code locally, it runs inside an isolated virtual machine on the user's computer. On the host, that VM runs as a single opaque process: The agent's activity inside the VM, including the processes it spawns, the packages it installs, and the network connections it makes, is not visible to the host's endpoint security sensor. Because host folders can be mounted into the VM, sensitive data can sit within the agent's reach.
Today at Fal.Con Europe 2026, CrowdStrike announced it is bringing 
CrowdStrike Falcon® Guardian
 protection natively into Anthropic's Claude Cowork. Built in partnership with Anthropic in response to enterprise customer demand, this integration extends Falcon protection to AI agents across their lifecycle, from agent creation through job execution. It runs the Falcon sensor directly inside the Cowork VM on both macOS and Windows to bring runtime visibility and detection into the agent's execution environment. 
The integration is now available in beta on macOS, with Windows support expected later in November.
See Falcon Guardian in action:
How It Works
Consider this scenario: A user asks Cowork for a script to align their slides to a brand standard. While completing the task, the agent installs the latest version of a common Python package. Neither the user nor the agent knows that an adversary has compromised the package at its source. Once installed, that package reads host data through a mounted folder and sends it out to a known malicious endpoint. The Falcon sensor running inside the VM would detect it. This is exactly the type of malicious activity and potential data exfiltration the integration is built to detect as agents execute tasks. 
CrowdStrike’s sensor integration with the Cowork VM will deliver:
Visibility and detection where agents execute
: Process, package, and network activity inside the Cowork VM will no longer be a blind spot, so teams can detect and investigate threats with the same Falcon telemetry they use everywhere else.
The same visibility on macOS and Windows
: The VM runs the same Linux environment on both, so customers get consistent coverage regardless of the OS.
Deployment and control through the CrowdStrike Falcon® platform
: Admins will turn the integration on through their existing device management, the same way they deploy the Falcon sensor today, and the Falcon Linux sensor deploys inside the Cowork VM. From there, the team controls it through the Falcon platform so Claude Cowork comes under the same security control plane as the rest of the environment.
Built with Anthropic
CrowdStrike and Anthropic worked together to bring Falcon protection directly into Claude Cowork's execution environment. Anthropic enabled Falcon deployment within Cowork, while CrowdStrike engineered and tested the integration across installation, real-time protection, and ongoing updates. Through this beta integration, enterprises can extend the security they already trust from the Falcon platform to AI agents in Claude Cowork, alongside the virtual machine, permissions, and admin controls built into Cowork.
CrowdStrike’s Architectural Difference
AI agents don't operate in one layer, and neither does Falcon Guardian. Agents reach out over the network to communicate with LLMs, but they also execute processes locally on the workstations where they’re installed. These actions may never cross network boundaries. The Falcon sensor and Falcon Guardian see both agentic workstreams and fuse them together in a single view from CrowdStrike’s endpoint network inspection and OS-level visibility. This unified view, CrowdStrike® Agent Graph, shows analysts not only what agents were asked to do, but what they did at runtime. 
CrowdStrike also delivers agent-level enforcement controls via hook integrations for agents such as Claude Code, OpenAI Codex, GitHub Copilot, OpenCode, and Cursor.
The Claude Cowork integration extends Falcon Guardian coverage to a new place agents work. It takes Falcon Guardian’s runtime security foundation into the VM where Cowork runs its code, providing visibility and detection for what the agent executes, installs, and connects to across its lifecycle, from agent creation through job execution.
What's Next
Endpoint agents like Claude Cowork run their code inside a VM that host-only security can't see into. By running the Falcon Linux sensor inside the Cowork VM on macOS and Windows, this integration will close that gap. It will bring Falcon visibility and detection to where agents execute, it will be deployed and controlled through Falcon, and it will extend the runtime foundation of the three layers of AI security in Falcon Guardian.
The integration is focused on visibility and detection inside the VM. Available in beta on macOS, with Windows support expected later in November 2026, it enables customers to deploy the Falcon Linux sensor inside the Cowork VM through their existing device management tools. Their teams gain visibility and detection across the processes, packages, and network activity inside the VM.
