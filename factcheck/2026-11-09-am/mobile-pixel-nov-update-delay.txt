Android 17 QPR 2 ベータ版 7.1（2026 年 10 月）
このプラットフォームは 
Android 17 の初回リリース
を基盤として修正と改善を重ね、そのたびにサポート対象デバイスにロールアウトが行われます。
Quarterly Platform Releases
（QPR）から四半期にごとに行われるこれらのリリースは、
Feature Drop
 の一環として、AOSP と Google Pixel デバイスの両方に配信されます。
このアップデートには、アプリに影響する API の変更は含まれていませんが、最新の QPR ベータ版ビルドのイメージを提供し、必要に応じてそのイメージを使ってテストができるようにしています（たとえば、次回搭載される機能がアプリのユーザー エクスペリエンスに影響する可能性がある場合など）。
Android 17 QPR2 には、マイナー SDK リリースが含まれています。この増分アップデートでは、動作の変更は予定されていないため、互換性テストの必要性は最小限に抑えられます。現在の SDK の変更内容は、
API の差分レポート
で確認できます。
電話の転送詐欺に対するセキュリティの強化
Android 17 QPR2 では、不正行為からユーザーを保護するため、プログラムによる電話の転送に新しいセキュリティ制限が導入されています。
TelephonyManager.sendUssdRequest()
 API
 を使用して実行される、電話転送の USSD コード（
*21#
 など）を解析し、選択的に制限するようになりました。
API の制限:
CALL_PHONE
 権限のみを使用する電話転送コードでは、
sendUssdRequest()
 API にアクセスできなくなりました。標準アプリがバックグラウンドでこれらのコードを実行しようとすると、ブロックされ、
USSD_ERROR_NOT_ALLOWED
 コールバックを受け取ります。
システム確認:
 ソーシャル エンジニアリング詐欺に対抗するため、ユーザーがシステム ダイヤラーで電話の転送コードを手動でダイヤルすると、コマンドが実行される前に新しい OS レベルの確認ダイアログが表示されるようになりました。
電話の転送以外の USSD:
 電話の転送以外の USSD リクエスト（モバイル送金やアカウント確認など）は、この変更の影響を受けません。
対応策:
 アプリが影響を受ける場合は、
USSD_ERROR_NOT_ALLOWED
 失敗コールバックが適切に処理されることを確認してください。転送設定が必要なアプリで、免除対象のロールに該当しない場合は、
ACTION_DIAL
 インテントを使用してダイヤラーに事前入力し、ユーザーが手動でアクションを確認できるようにフローを移行してください。
セルフブロードキャストの配信を最適化
Android 17 QPR2 以降を搭載したデバイスでは、Android は
セルフブロードキャスト
をより効率的に配信して、システム ヘルスを改善します。自己ブロードキャストとは、コンテキスト登録されているかマニフェストで宣言されているかにかかわらず、すべてのレシーバがブロードキャストを送信したプロセスと同じプロセスで実行されるブロードキャスト（
sendBroadcast()
 で送信されるブロードキャストなど）です。
いずれかのレシーバが別のプロセスで実行されている場合、ブロードキャストはセルフ ブロードキャストではありません。システムは、自己ブロードキャストを送信プロセスに返します。送信プロセスは、メインスレッドで独自のレシーバに配信します。これにより、アプリが自身にブロードキャストを繰り返し送信してバックグラウンドで実行し続けることを防ぎます。この変更は、
targetSdkVersion
 にかかわらず、すべてのアプリに適用されます。
この変更は、アプリに次のような影響を及ぼします。
セルフ ブロードキャストを送信しても、プロセスの重要度は上がらず、キャッシュに保存されたプロセスがフリーズするのを防ぐことはできません。
プロセスがキャッシュに保存され、フリーズしている場合、送信されたセルフ ブロードキャストは、プロセスがフリーズ解除されるまで（ユーザーがアプリに戻ったときや、アプリの別のコンポーネントが起動したときなど）待機します。
まだ配信されていないセルフ ブロードキャストは、プロセスのメモリに保持されます。配信前にシステムがプロセスを強制終了すると、それらは失われ、再配信されません。
別のプロセス（同じアプリの別のプロセスを含む）にレシーバがあるブロードキャスト、別のアプリに代わって送信されるブロードキャスト（
PendingIntent
 を介して送信されるブロードキャストなど）、別のユーザー プロファイルに送信されるブロードキャストは影響を受けません。
アプリがバックグラウンドで動作するために自己ブロードキャストに依存していないことを確認してください。セルフ ブロードキャストをタイマーやキープアライブ メカニズムとして使用しないでください。バックグラウンド処理のスケジュールを設定するには、
WorkManager
 を使用します。特定の時間に実行する必要がある処理には、
AlarmManager
 を使用します。プロセス内の通信には、ブロードキャストではなく、コールバックや Kotlin フローなどの直接呼び出しを使用します。
