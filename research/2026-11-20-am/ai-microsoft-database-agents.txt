As part of the slew of product development updates out of Microsoft Ignite, Azure HorizonDB, a fully managed PostgreSQL database service from the tech giant that is designed to meet the security, resilience and scale requirements of the AI era, is now generally available.
Microsoft also unveiled Fabric HorizonDB, a version of the new database optimized to bring PostgreSQL into 
its Fabric platform
 for analytics and data management, in preview. 
PostgreSQL is distinguished by its flexibility and versatility, handling traditional relational database workloads as well as geospatial, time series, JSON and the 
vector database workloads that have become critical
 over the past few years due to their role helping enterprises index and operationalize unstructured data and data spread across disparate systems. Because of its adaptability, PostgreSQL is now 
the most popular database format
.
Other new Fabric capabilities include Database Hub, a single environment to monitor and manage databases across customers' Microsoft estates that is now generally available, and database agents, now in preview, to provide users with AI-assisted SQL and PostgreSQL capabilities for observing their database operations. 
While beneficial for Microsoft users, the new 
PostgreSQL database capabilities
 are not unique, according to Sanjeev Mohan, founder and principal of analyst firm SanjMo. However, Microsoft does distinguish its PostgreSQL capabilities from those of rivals such as AWS and Google Cloud through integrations with the broad Microsoft data and AI ecosystem.
"Every major vendor is converging on the same pattern: Postgres for operational data, an open lakehouse for analytics, and a semantic layer that gives agents business context," Mohan told TechTarget. "Microsoft's edge is integration by tightly connecting the database, OneLake, Power BI semantic models, Fabric Apps and Copilot."
Michael Ni, an analyst at Constellation Research, similarly noted that while the individual capabilities don't differentiate Microsoft from its competitors, the way it integrates them does create separation.
"Microsoft is keeping pace with … AWS and Google to deliver on converged database and AI technologies," he told TechTarget. "All are investing in bringing operational data, analytics, and AI closer together. Where Microsoft may have an advantage is how it packages these capabilities for enterprise customers. ... That could reduce the amount of new infrastructure and integration work required."
However, whether Microsoft can deliver simplicity in practice has not yet been proven, Ni added.
Prioritizing PostgreSQL for AI
Microsoft previously provided PostgreSQL database capabilities with Azure Database for PostgreSQL. Now, with the launch of HorizonDB, Microsoft is providing PostgreSQL database capabilities purpose-built for the unique demands of AI.
"We are reimagining the data layer," Microsoft CEO Satya Nadella said during the keynote address at Ignite. "Agents need databases that can keep up with the speed and scale while giving them the context they need for all of the reasoning and actions. That's why we are building HorizonDB."
HorizonDB, which is built to handle 128 terabytes of data per cluster to serve agents the data volume in real time that they require to 
deliver optimal results
, performed eight times faster than self-managed PostgreSQL in benchmark testing conducted by Microsoft -- independent, third-party test results were not provided.
"Microsoft's edge is integration by tightly connecting the database, OneLake, Power BI semantic models, Fabric Apps and Copilot."
Sanjeev Mohan
Founder and principal, SanjMo
By bringing HorizonDB into Fabric, Nadella noted that Microsoft is fully unifying previously separate transactional and analytical data for agents.
"With HorizonDB and Fabric coming together, agents now can reason over live transactions along with petabytes of historical records in real time," he said. "This vision that we have had for 20-plus years is now finally coming together for [customers] to build the next generation of systems."
Mohan likewise noted that HorizonDB's launch is a significant step for Microsoft as it builds the foundational capabilities enterprises need to 
develop and deploy agents at scale
. Previously, the tech giant merely provided a managed version of open-source PostgreSQL.
With HorizonDB, Microsoft is adding a cloud-native database purpose-built for the modern era rather than one when databases served as sources for data assets such as reports and dashboards.
"PostgreSQL has become the default database for new applications and, increasingly, for AI agents," Mohan said. "[HorizonDB] gives Microsoft customers a Postgres option built for enterprise scale and agentic workloads, not just a hosted copy of the community version."
The new capabilities in Fabric are similarly significant, according to Ni.
Fabric HorizonDB integrates PostgreSQL database capabilities with Fabric to copy tables into Fabric without requiring users to build complex and expensive data pipelines; it also unifies disparate data types to provide 
a foundation for both AI and traditional BI
. Database Hub is designed to help system administrators more easily oversee their swath of databases so they can identify potential problems, prioritize work and more easily apply governance. And database agents are built to help data teams move from reactive monitoring toward automating their database operations.
"The Fabric additions are significant because Microsoft is making it easier to build applications around the data and analytics they already have," Ni said. "Users can more simply create and manage applications that use trusted data, accept input and write changes back to operational systems. That's a practical step toward closing the gap between analyzing the business and acting on … analysis."
The test of their true efficacy will be how well the new features work with external operating systems enterprises use in addition to Microsoft capabilities, he added.
Context still a concern
Beyond launching HorizonDB and augmenting Fabric with new capabilities, Microsoft updated Azure DocumentDB with new deployment options to 
address data sovereignty
, added tools that enable developers to build AI applications in Azure Managed Redis, introduced capabilities designed to help users create purpose-built applications in Power BI, and made the Rayfin service for application development generally available.
Collectively, the new features move Microsoft closer to enabling customers to build agents that reason over massive amounts of data in real time, according to Mohan. However, Microsoft still needs to augment features such as Microsoft IQ and Agent 365 to 
better serve agents with relevant context
 in addition to data volume.
"Microsoft has a long track record of handling extreme scale without much fanfare, but scale isn't the hard part -- context is," Mohan said. "Agents need to know what the data means, whether it's current and whether they're allowed to act on it."
Mohan added that Microsoft IQ and Agent 365 need to keep 
semantic definitions
 and 
ontologies
 up to date as data changes, give customers control over what agents can do as well as what they can read, and clearly show customers how much
 it costs to run agents
 that process massive amounts of data.
Ni, meanwhile, noted that the new HorizonDB and Fabric capabilities complement Microsoft's existing foundation for real-time data processing through Fabric Real-Time Intelligence. But like Mohan, he suggested that what Microsoft needs to focus on is 
bringing context into the mix
.
"Microsoft is assembling many of the pieces, [but] the remaining challenge is bringing real-time signals, current operational state, business context and execution policies together for a particular decision," Ni said. "That's where enterprises will determine whether these capabilities can support reliable agentic operations."

From Microsoft Ignite
I’m here in San Francisco enjoying specialty lattes, fall-ish weather (I guess?), and all the excitement around Microsoft announcements at Ignite 2026. It’s a cool energy to be surrounded by so many people at organizations that are trying to innovate with AI for the era of AI. These applications are the apps that run our world, and how they advance (or don’t) will change their trajectories at those companies as well as likely have real impact on our day-to-day lives.
At Microsoft Ignite, our Microsoft SQL announcements focus on making the innovation path simpler: modernize existing applications, start new ones locally, and use better tools to develop, secure, and operate the database as the application grows.
Here’s what’s new across Azure SQL, SQL database in Fabric, SQL Server, and the tools you use every day.
Azure SQL Database Hyperscale: start here, stay here
Azure SQL Database Hyperscale is our modernization (and innovation!) target of choice. 
It brings the SQL engine you know to a cloud architecture that separates compute and storage, giving applications room to grow without making database replatforming the next milestone. A few months ago, we announced support for scale to zero (serverless auto-pause preview) making this a great solution for all sizes and types of workloads, starting at 10GB (read: Hyperscale is not just for big databases!).
There is 
no extra database software to procure, acquire, purchase, or manage
. You consume the managed Azure service rather than buying and operating a separate database software stack. I have to mention it is price-matched to AWS Aurora (based on a March 2026 list price comparison of provisioned per-core compute costs in US East regions for Azure SQL Database Hyperscale Standard Series Gen5 and AWS Aurora I/O optimized db.r7i.large).
Hyperscale cross-database querying is in preview!
 Cross-database queries help customers unblock SQL Server migrations by reducing the query rewrites and application redesign needed to move applications with cross-database dependencies. Customers can combine data across databases in the same Hyperscale elastic pool for reporting, analytics, and application workflows without building and maintaining extra data copies or pipelines solely to support those queries. They can preserve separate databases and per-database access controls, reuse familiar T-SQL skills, and simplify access to related business data. 
Get started today
.
Security
 in the era of AI is two-fold, how you set up security for your data, and how your data provider maintains security. Fortunately, Microsoft SQL is elite at both, constantly pushing updates to maintain what we consider the most secure database on the planet, but also providing customer capabilities so you can set your organization up for success. One update is 
Regex-based dynamic data masking (GA) 
which helps handle masking for variable-length values with more flexibility.  
AES keys support for Transparent Data Encryption (TDE) with customer-managed keys in Azure SQL Database (GA)
, provides an alternative to RSA keys for protecting data at rest and helping you prepare for the evolving quantum threat landscape and 
TDE encryption scan suspend and resume (public preview) 
gives administrators more control over when scan work runs. 
Database-level managed identity in Azure SQL Database (public preview)
 enables separate, passwordless access to external data for each database which strengthens customer and business-unit isolation while preserving shared-server economics.  
Recently a customer told me how great Microsoft SQL search options are, and we’re only getting better! 
Built-in fuzzy string matching (GA)
 helps applications compare inconsistent names or identify possible duplicates without moving that work out of SQL. Check out our 
YouTube channel
 for a recent episode on this topic.
Agentic modernization to Hyperscale
For existing SQL Server and hybrid estates, modernization starts with understanding the business and supported applications, because your database isn’t moving in isolation. With the evolution of AI, agents, and skills, modernizing to Hyperscale is getting easier. Our updates help bring assessment, application context and innovation, and migration closer together.
Modernize CLI (App+DB)
 delivers an end-to-end assessment that evaluates an application and its database dependencies as a single workload. It combines application-code modernization opportunities with SQL Server migration readiness, compatibility, and target recommendations in one consolidated report.
In 
Database Hub
, agentic assessment and migration as optimization (both public preview) bring migration readiness into everyday estate management: use the Copilot sidecar to view readiness at scale, start assessments, and review results, and use the 
Optimize
 card to spot migration opportunities and open the full assessment in the Azure portal.
Across 
SSMS, Azure Arc, and Azure Catalyst (Azure Migrate got an upgrade!)
, updated assessments add Hyperscale service-tier recommendations to target selection, clarify readiness after remediation, and provide instance-level elastic-pool recommendations so you can evaluate databases together.
When you’re ready to move, 
Azure Arc
 expands migration access to more Azure-registered and agentless server scenarios, building on September’s Arc-to-Hyperscale migration preview. 
DMS
 private networking adds VNet peering and custom DNS support for supported migration endpoints without exposing databases publicly, and 
SqlPackage 170.5 and SQL Projects SDK 2.3 (GA)
 add deployment versioning, pre-plan scripts, and a force-Azure-compatibility export option.
Start locally. Build toward Hyperscale.
This is something I’ve been dreaming about since I joined the Microsoft SQL team: an always up-to-date local container that I could use to simulate and understand Azure SQL Database features and behaviors, without deploying anything or spinning any meters. The
 Azure SQL Database local development container is now public preview
, so you can start doing exactly that! New container provisioning experiences in the VS Code MSSQL extension and SSMS bring container setup directly into familiar tools, making it easier to get started with local SQL development. In VS Code, 
Microsoft Entra authentication and expanded support for container runtimes and environments
, including Podman, WSL, and Apple Silicon, offer greater flexibility for local development.
When you’re ready for Azure, the 
Local-to-Cloud Deployment Wizard, now in public preview for the MSSQL extension for VS Code
, provides a guided path from a local database to a free tier Azure SQL Database with built-in deployment preparation and compatibility validation. Prefer working with AI agents? 
Microsoft SQL Agent skills
 continues to expand, with skills spanning local container development to cloud deployment, all easily installed as a plugin for your agent of choice.
Database Hub is generally available
Database Hub in Microsoft Fabric
 brings database discovery, monitoring, and optimization into one estate view, with real-time dashboards for Microsoft SQL, PostgreSQL, and Cosmos DB, improved filtering, and visibility into end-of-support, maintenance, and issues across database groups.
Copilot in Database Hub (public preview)
 helps you explore performance trends, investigate issues, and ask follow-up questions in natural language, grounded in Database Hub information. The 
Database Hub CLI skill

skills-for-fabric

Enhanced detection
 helps uncover potential problems, while 
AI-powered skills
 let you investigate queries, analyze execution plans, and explore solutions directly from an issue or through Copilot side chat. You can receive 
recommendations
 for query rewrites, hints, and indexes, each backed by evidence and clear explanations to help you understand the issue and determine the best next steps. Of course, AI is only used when you choose to invoke these skills, and you’re always in control of reviewing recommendations before making changes to your database.
Alerts for Azure SQL Database (public preview)
, powered by Fabric Activator, turn templates or performance charts into alerts across one or more databases, with actions such as Teams messages or Power Automate flows.
Other updates across Microsoft SQL

adds GA for the zone-redundant Next-gen General Purpose (GP) tier, with a flexible memory option, log throughput of up to 220 MB/s, and more storage per vCore. Azure SQL Dev Hub

Build on one PostgreSQL foundation, from Azure to Fabric 
At Ignite last year, we introduced 
Azure HorizonDB
 in preview. Today, Azure HorizonDB is generally available: a fully managed, PostgreSQL-compatible database service built for mission-critical and AI-powered applications. 
With Azure HorizonDB, teams can build AI applications directly on transactional data using built-in vector search, AI Functions and AI Pipelines that invoke models from SQL queries, along with built-in AI model management in preview. With the PostgreSQL extension for VS Code, developers can manage, tune, and monitor their databases with AI assistance in the same editor where they write their application code.
For critical workloads, multi-zone high availability and distributed storage support fast recovery to help keep applications running. Microsoft Entra ID, private endpoints, managed identities, and service- or customer-managed keys help protect sensitive data, bringing resilience and security together with HorizonDB’s AI capabilities.

Run translytical queries.

Full and partial pushdown allow a single query to join PostgreSQL tables with data in OneLake, with analytical queries running an order of magnitude faster than they would natively in PostgreSQL.

Modernize with a plan, accelerated by agents 
The applications that run your business hold your most valuable context, and modernizing them onto AI-ready foundations, with less migration friction, makes that context available to new intelligent experiences. Agents are changing how that work gets done, from discovery to code conversion.

AI-assisted migrations from Oracle to managed PostgreSQL on Azure
Some workloads ask more of that plan than others. For many organizations, Oracle workloads can be the hardest to move, because migrating the data is only half the job. The application code that depends on it must move, too. 
Two new previews address both halves
.
Oracle to PostgreSQL migration in Azure Database Migration Service
 now supports offline data migrations to Azure Database for PostgreSQL. Teams can configure connections, select schemas, and start and track the transfer in one experience, without building custom data-movement processes.
For application code, 
AI-assisted Oracle application conversion
 provides a plug-in that converts Oracle code to work with Azure Database for PostgreSQL. Available through GitHub Copilot CLI or Visual Studio Code, and directly within existing modernization workflows such as Modernize CLI, the skills identify Oracle-specific dependencies and propose code changes for PostgreSQL compatibility. Developers review and validate the changes before accepting them.
Together, they bring agentic assistance to the whole migration, not just the data. There's much more to the PostgreSQL story at Ignite – 
check it out

Build and deploy intelligent apps with Fabric apps 
Fabric apps are now generally available, giving developers and coding agents a simpler path to building and deploying complete business applications. They build with Rayfin, the open-source SDK and CLI that provides databases, authentication, functions, storage, and observability, and deploy to Fabric, connected to enterprise data and governance. In just five months of preview, builders created more than 100,000 apps with Rayfin and deployed them on Fabric. Fabric apps connect to existing semantic models, warehouses, and lakehouses, so teams can build on trusted data without recreating data models or access controls. Teams can also turn analytics into applications that move users from insight to action. Content Security Policy settings and private sites add more protection.
Builders can also start in familiar tools. With Microsoft Copilot, they can go from a simple prompt to a working application, using Fabric as a ready-made backend for databases, storage, and data APIs. Integrations with Power BI Pro and Power BI Desktop, both in preview, help teams turn trusted semantic models into interactive business applications. 
At Thomson Reuters, the Monthly Business Review now runs as a Fabric app, built on the same certified Power BI semantic models that ground the company's DeepVista AI framework.

Build locally, scale confidently with Azure SQL Database Hyperscale 
The SQL applications organizations trust most are ready for their next chapter: cloud-native scale, better economics, and AI. 
Azure SQL Database Hyperscale
 runs the SQL engine teams already know, on a cloud native distributed architecture that separates compute from storage, enabling applications to scale with demand. With relational, JSON, graph and vector data unified under familiar SQL security and governance, developers can build AI powered experiences grounded in real-time business data without a separate vector database. That makes Hyperscale the destination for modernizing SQL applications and the foundation for new AI applications.
Great applications start on a laptop, not in a provisioning queue. Azure SQL Database container, now in public preview, brings the SQL engine to local development without requiring an Azure subscription. Developers get familiar T-SQL, system views, and driver behavior, along with vector support and AI_GENERATE_EMBEDDINGS to prototype AI-powered applications. When ready to deploy, the new local-to-cloud deployment wizard in the MSSQL extension for VS Code, also in public preview, provides a streamlined path from the developer's laptop to Azure SQL Database Hyperscale.
Growing applications often split data across databases. Cross-database querying for Hyperscale, now in limited preview, lets developers use familiar T-SQL three-part names to query across databases in the same elastic pool from one connection, while each database enforces its own permissions. From laptop to cloud scale, it's the same SQL the whole way.
