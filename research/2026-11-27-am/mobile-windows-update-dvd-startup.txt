PxHlpa64.sys

目次
自分のPCが対象か調べる

この記事の2台と同じ起動設定です。表示だけで不具合の原因と決まるわけではありません。不要になった旧ドライバの扱いは、

旧DVDドライバを無効にする復旧手順
古いDVD書き込みソフトを使っていたPCで同じ症状が出たときは、まず 
PxHlpa64.sys

セーフモードで起動できる場合

Microsoftのセーフモードの開き方
セーフモードのデスクトップで［Windows］キーを押しながら［R］を押します。開いた画面に 
cmd
 と入力し、［Ctrl］と［Shift］を押したまま［Enter］を押します。
管理者のコマンド プロンプトが開いたら、次の1行を入力して［Enter］を押します。

VBSを一時的に止めて起動できたNECでの表示。上から2行目の

0 BOOT_START

結果の

0 BOOT_START

成功したら［スタート］→［電源］→［再起動］を選び、デスクトップまで進むか確かめます。

富士通 FMVA3101BPの回復画面。「PCは正しく起動できませんでした」と表示されました。

NEC LAVIE DA700/KAWはVBSと旧ドライバの設定変更で復旧
NEC LAVIE DA700/KAW（PC-DA700KAW）では、11月20日に任意のプレビュー更新

NEC LAVIE DA700/KAWに表示された自動修復の画面。
NECで行ったVBSと旧ドライバの設定変更
VBSは 
Virtualization-based Security
 の略で、日本語では「仮想化ベースのセキュリティ」です。仮想化の機能を使い、Windowsを守る処理をほかの処理から隔離して動かします。 
MicrosoftのVBSの説明
回復画面でVBSを一時的に無効化
NECはセーフモードでも起動できなかったため、回復画面のコマンド プロンプトから作業しました。［トラブルシューティング］→［詳細オプション］→［コマンド プロンプト］で開けます。 
MicrosoftのWindows回復環境の説明
回復画面では、Windowsが入っているドライブの文字が普段と違うことがあります。
dir C:\Windows\System32\Config\SYSTEM
 で設定ファイルがあるか確かめます。調べたときはNECが 
C:
、富士通は 
E:
 でした。暗号化されたドライブの回復キーを求められた場合は、BitLocker回復キーを使います。
内蔵ドライブにあるWindowsの設定（レジストリ）を編集するため、次のように 
SYSTEM
 ファイルを読み込みました。各行を実行し、成功したことを確認して次に進みます。
HKLM\NECVBSLIVE
 は読み込んだ設定に付けた一時的な名前です。 
Microsoftのreg loadの説明
reg load HKLM\NECVBSLIVE C:\Windows\System32\Config\SYSTEM
reg query HKLM\NECVBSLIVE\Select
NECの回復画面。
Select
 の上から2行目が 
Default
 です。
写真の上段にある 
Select
 の一覧では、上から2行目の 
Default
 の右端が 
0x1
 です。これは、通常起動で使う設定一式の番号が 
1
 という表示です。番号を3桁で表した

 が、実際に開いた設定の名前です。写真の下段にも、その名前が出ています。
一番下にある

 の右端にも 
0x1
 と出ています。この欄では、VBSが有効という意味です。別のPCを調べる場合は、

C:\DeviceGuard-before-vbs-trial.reg

0x0

VBSを一時的に無効にした直後の画面。設定行の右端が0x0に変わりました。
Windowsの更新状態はそのままでも、VBSを一時的に無効にすると正常に起動し、デスクトップが表示されました。ここで一時的に止めたVBSは、古いドライバの対処を済ませてから戻します。同じ確認を行っても起動しない場合は、回復画面で設定ファイルを開き、記録した元の値に戻します。
起動後にDVDドライバを無効化
起動後は、変更前の設定を保存してから旧DVDドライバを無効にしました。レジストリエディターから変更する場合は、［Windows］キーを押しながら［R］キーを押し、
regedit
 と入力して開きます。アドレスバーに次のパスを入力します。
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\PxHlpa64
右側にある 
Start
 の値を 
0
（起動時に読み込む）から 
4
（無効）に変更しました。これで次の起動から 
PxHlpa64.sys
 の読み込みが止まります。 
Microsoftのドライバ起動設定の説明
次に、DVDドライブが追加で使うドライバの一覧を、次の場所で確認しました。
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4d36e965-e325-11ce-bfc1-08002be10318}
一覧は

 という値に保存されています。このNECで登録されていたのは 
PxHlpa64
 の一行だけだったため、
LowerFilters
 の値を削除しました。ほかのドライバ名も並んでいる場合は、
PxHlpa64
 の行だけを取り除きます。
そのあと再起動し、古いドライバの読み込みが止まり、DVDドライブがエラーなしで認識されることを確認しました。
VBSを有効に戻して起動確認
DVDドライブが認識されたことを確認してから、管理者として開いたPowerShellでVBSの設定を元の 
1
 に戻しました。起動済みのWindows上では、現在使っている設定を

 から開けます。
$deviceGuard = 'HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard'

再起動後は通常どおりサインインでき、DVDドライブも認識されました。Windowsが報告するVBSの稼働状態は 
2
（有効で実行中）になりました。
GUIから確認する場合は、
msinfo32

MicrosoftのVBSの稼働確認手順
VBSと旧DVDドライバが起動時に干渉する理由
VBSは、仮想化を使ってWindowsの保護処理を隔離する仕組みです。その隔離環境で、ドライバなどがWindowsの中核部分で実行するコードを検査する機能が「メモリ整合性（HVCI）」です。 
MicrosoftのVBSとメモリ整合性の説明
メモリ整合性が有効な環境では、ドライバが使う同じメモリ領域を「書き換え可能」と「実行可能」にすることなどが制限されます。この条件に合わないドライバは、正常に読み込めなかったり、動作中に問題が生じたりすることがあります。Corelも、旧版の 
PxHlpa64.sys
 にメモリ整合性との互換性問題があることを案内しています。 
Microsoftのドライバ互換性の説明
 · 
Corelの互換性情報
今回の2台に残っていたのは、Corel製の 
PxHlpa64.sys
 バージョン 
3.01.01.0
 です。どちらも 
Start=0
（
BOOT_START
）で、Windowsの起動の早い段階に読み込まれる設定でした。DVDを使うときだけ読み込まれるわけではないため、ドライバの互換性問題が起動処理そのものに影響することがあります。 
Microsoftのドライバ起動設定の説明
NECでは、VBSを一時的に無効にすると起動し、
PxHlpa64
 を無効にしたあとはVBSを有効に戻しても起動しました。この結果から、
旧ドライバとVBSを使う起動環境との互換性問題が、今回の起動不良に関係していた
と考えられます。そこで、VBSを無効にしたまま使うのではなく、旧ドライバの読み込みを止め、保護機能を戻した状態で起動を確認しました。
更新の数日後、再起動で症状が出る理由
NECの記録では、VBSに関する設定項目が更新されたのは11月11日でした。その後、11月20日朝までの7回の正常起動はすべて高速スタートアップで、VBSが使う保護用のメモリ領域は使われていませんでした。システムを復元したあとも、VBSの有効設定は残っていました。
高速スタートアップでは、前回のWindowsの中核部分（カーネル）とドライバの状態を保存し、次の電源投入で再利用します。一方、［再起動］ではそれらを一から読み込み直します。この違いにより、
保護機能の設定変更の影響が、普段の電源投入ではなく再起動で表面化する場合があります。

今回のNECでも、11月20日の更新に伴う再起動が、VBSの有効設定と旧ドライバの互換性問題を表面化させたきっかけと考えられます。更新日と起動不能になった日が離れていても、再起動を境に症状が出た場合は、保護機能の設定と起動時のドライバをあわせて確認します。

再起動で表面化した可能性
NECのPCには興味深い記録が残っていた。VBSに関する設定が更新されたのは11月11日。11月20日の朝までの正常起動にはすべて高速スタートアップが使われており、VBSの保護用メモリ領域は使われていなかったという。

再起動で互換性問題が表面化した可能性
VBSの設定が変わった後に何度か電源を入れて正常に使えていたとしても、それだけで新しい設定の下での起動に成功したと判断するのは難しい。
電源投入と再起動の違い
が起動障害の原因を調べる上で重要になる。
Microsoftは互換性を事前に評価する方針
Microsoftは
10月のプレビュー更新KB5127936
に、対応するPCのメモリ整合性を自動的に有効化する変更を導入した。
11月のセキュリティ更新KB5132061
にもこの変更が含まれる。
メモリ整合性（HVCI）はVBSを利用し、Windowsの中核部分で実行されるコードの整合性を隔離された環境で判定する保護機能。Microsoftは
技術文書
で、一部のアプリやドライバとの互換性問題によってまれに起動障害が発生する可能性にも言及している。
Corelの
サポート文書
にも旧版の
PxHlpa64.sys
とメモリ整合性との非互換が記載されている。このドライバを含むライブラリはRoxio製品のほか、ライセンスを受けた他社のディスク書き込みソフトでも使用される。
修理した富士通のPCにはRoxio Creator LJとCorel WinDVDが、NECのPCにはRoxio BackOnTrack 4.6がインストールされていた。
Microsoftは
メモリ整合性の自動有効化に先立ち
、ハードウェアの能力や互換性、性能などを評価する方針を示している。利用者や管理者が既に無効化している場合は、その設定も維持すると説明している。
国内のシステム管理者が公開した別の実機記録では、Windows 11 25H2のHP ProDesk 405 G8でもKB5132061を適用した状態で旧ドライバを無効化して復旧していた。復旧後はVBSが稼働していたが、メモリ整合性は実行されていなかったという。
HPの事例では起動に失敗した時点で保留中だった更新の影響も切り分けられていない。富士通やNECの記録を含め、起動障害が発生した時点でメモリ整合性が稼働していたかまでは特定できていない。
旧ドライバを含めた
起動時の互換性
を自動有効化の前にどこまで確認できるかという問題は残る。とりわけ、実際に起動できなくなるまで利用者が問題に気付けない場合には、事前の判定が重要な役割を持つ。
仮想化機能を無効にして復旧した別の事例
11月26日には縄文堂商会が
自社PCの復旧事例
を公開した。FRONTIER製のPCで、CPUはAMD Ryzen 5 5600X、マザーボードはASRock B550 Phantom Gaming 4。自動修復を繰り返す状態からBIOSでCPUの仮想化機能（SVM）を無効化することでデスクトップまで復旧したという。
このPCには
PxHlpa64.sys
が入っていなかったという。仮想化機能を無効にして起動できたという結果から、富士通やNECのPCと原因を共通化することはできない。
CPUの仮想化機能を無効にすればVBSによる保護やWSL2の利用にも影響する。起動を取り戻すための一時的な対応と、
保護機能を維持できる状態

TROUBLESHOOT / 2026-11
Windows 11がロゴのあとで再起動を繰り返す
初期化の前に、古いDVDドライバ PxHlpa64.sys があるかを見る
メーカーロゴの直後に再起動する、回復画面の0xc0000001や自動修復から進まない。国内の修理店が調べた2018年モデル2台では、
このドライバの読み込みを止めると、データとアプリを残して起動しました
。
修理店の2台＋1台
Microsoftは未発表
まず設定を変えない確認
更新のあと、メーカーロゴの直後に再起動を繰り返す。回復画面で0xc0000001が出る、自動修復から先へ進まない。こうなると初期化やパーツの買い替えが頭に浮かびますが、その前に見るファイルが1つあります。古いDVD書き込みソフトが入れる 
PxHlpa64.sys
 です。
修理店が調べた2018年モデルの富士通とNECの2台では、このドライバが「Windowsの起動の早い段階で読み込む」設定（Start=0、BOOT_START）のまま残っていました。ファイルは消さず読み込みだけを止めると、どちらもデータとアプリを残したまま起動し、KB5132061を入れた状態で通常起動しています。同じ店は11月25日に、ロゴのあとで再起動を繰り返すDELLでも同じドライバを止めて起動した、と投稿しています。
ただし、ロゴ後の再起動や0xc0000001のすべてがこのドライバとは限りません。Microsoftは、この起動不能をKB5132061の既知の問題として載せていません。PCにこのドライバが無ければ、
KB5132061のあとに起動できないときの切り分け
に戻ります。
目次
症状
このドライバを疑うPCの条件
次の3つがそろうPCは、初期化の前に確認する価値があります。1つだけなら、ほかの原因も同時に疑います。
ロゴのあとで再起動する、または自動修復・0xc0000001で止まる
報告された症状は、メーカーロゴを過ぎてWindowsが起動する瞬間に再起動を繰り返す（DELL）、回復画面にエラー0xc0000001が出る（富士通）、自動修復を繰り返す（NEC）の3つです。DELLではBIOS（UEFI）が正常に動いていました。
DVDやBlu-rayを書き込む古いソフトを入れたことがある
修理店が確認した2台に入っていたのは、Roxio Creator LJ、Corel WinDVD、Roxio BackOnTrack 4.6です。
ソフト名が違っても、古い書き込みソフトが残っているPC
が候補になります。
更新のあとの再起動で止まった
富士通とNECは、更新が入ったあとの再起動で止まっています。NECは更新の数日後の再起動で初めて症状が出ました。DELLは、更新との時系列が投稿に書かれていません。事例のPCは富士通とNECが2018年モデル、DELLはIntel第8世代のCPUですが、
古いPCに限った症状とは確認されていません
。
事例
修理店の2台と、追加の1台で起きたこと
いずれも修理店の記録で、Microsoftが原因を確認したものではありません。条件の近い3台の結果です。
富士通 LIFEBOOK A748/TX（FMVA3101BP）
障害時は10月のプレビュー更新KB5127936が入っていて、回復画面にエラー0xc0000001が出ました。セーフモードでは起動できました。更新を取り消しても症状は続き、PxHlpa64.sysの読み込みを止めると起動しています。ドライバのバージョンは3.01.01.0で、仮想化ベースのセキュリティ（VBS）は有効に設定されていました。
NEC LAVIE DA700/KAW（PC-DA700KAW）
KB5132061が入っていて、11月20日に任意のプレビュー更新KB5132057の処理が始まったあと、自動修復を繰り返しました。システムの復元や更新の取り消しでは直らず、セーフモードも起動しません。VBSを一時的に無効にすると起動し、ドライバを止めたあとにVBSを元に戻しても起動しました。ドライバは同じ3.01.01.0です。
DELL（型番は不明）
ロゴを過ぎてWindowsが起動する瞬間に再起動が入り、これを繰り返しました。BIOSは正常で、CPUは第8世代のIntel Core i7です。PxHlpa64を確認して無効にしたところ起動した、とされています。ファイルのバージョンやVBSの設定は書かれていません。
別の記録もあります。HP ProDesk 405 G8（25H2）を管理する社内SEの報告では、VBSの設定値は1のまま、PxHlpa64のStartだけを4（無効）にして起動しました。こちらは1台の記録で再現試験はなく、保留中の更新も残っていたため、ドライバだけが原因と切り分けられてはいません。
修理店の2台は、読み込みを止めたあと、KB5132061を入れた状態で通常どおりサインインできました。NECはVBSが動いたままです。
確認
今起動できるPCは、設定を変えずに見るだけ
Windowsが起動できているPCでは、変更せずにこのドライバの登録だけを読みます。管理者権限のコマンド プロンプトを開き、次を入力します。
sc.exe qc PxHlpa64
START_TYPEが「0 BOOT_START」
Windowsの起動の早い段階で、このドライバを読み込む設定です。レジストリのStart値でいえば0x0（ブートローダが読み込む）にあたります。今起動できているなら変更は要りません。次の再起動に備えてBitLocker回復キーと回復ドライブを用意し、
Roxio Creator、WinDVD、BackOnTrackなどの古いDVDソフトが残っていないか
を見ます。
「FAILED 1060」
「指定されたサービスはインストールされているサービスとして存在しません」という意味のエラーで、
このPCにはPxHlpa64の登録が見つかりません
。修理店の2台と同じ条件ではないため、症状が出ているなら、ほかの原因を切り分ける記事に進みます。
START_TYPEがそれ以外（1 SYSTEM_START、2 AUTO_START、3 DEMAND_START、4 DISABLED）
修理店の2台とは読み込む時期が違います。1は起動の途中、2はサービスの自動起動時、3は必要になったとき、4は読み込まれません。0以外でも症状との関係を完全には否定できませんが、
2台と同じ条件ではない
ため、ほかの原因も並行して疑います。
PCが起動しないときは、この確認ができません。次の順で進めます。
手順
起動できないPCは、リセットの前にここまで
BitLocker回復キーを用意する
。回復環境の多くの操作で回復キーを求められます。別のスマホやPCでMicrosoftアカウントにサインインして確かめます。
更新プログラムのアンインストールとスタートアップ修復を試す
。データとアプリに影響しない操作です。回復環境への入り方と、システムの復元などの順番は、
KB5132061のあとに起動できないときの対処
にまとめています。修理店の2台では、更新を取り消しても症状は変わりませんでした。
それでも直らないとき、リセットや初期化の前にPxHlpa64の登録を見る
。回復環境のコマンド プロンプトから、Windowsの設定ファイル（SYSTEM）を読み込み、PxHlpa64の起動設定Startが0になっているかを確かめます。
Startが0なら、4（無効）に変えて読み込みを止める
。ファイルは削除しません。変更の前に元の登録を書き出しておき、再起動してデスクトップまで進むかを確かめます。登録が無い、またはStartが0でないときは、設定ファイルを閉じて別の原因を探します。
3、4番目の操作はレジストリを直接書き換えます。読み込む設定の番号（ControlSet001かControlSet002か）を取り違えると、起動の設定を壊します。修理店の手順は、Windowsが入っているドライブ文字の確認、設定ファイルの読み込み、通常起動で使うControlSetの番号の確認、元の登録の書き出し、Startの変更、値の読み返し、設定ファイルを閉じて再起動、の順です。変更しても起動しないときは、書き出した元の値に戻します。コマンドの全文と画面の例は、
渋川パソコンサポートの記事
にあります。自信がないときは、初期化の前に修理店やメーカーのサポートへ相談します。
!
先にやらないこと
PxHlpa64.sysの削除は勧められません。読み込みを止めるだけで起動した事例があり、削除すると復元にバックアップやソフトの再導入が必要になる場合があるためです。VBS、メモリ整合性、Secure Boot、仮想化の設定を先に切るのも避けます。NECは一時的にVBSを止めて起動しましたが、ドライバを止めたあとに元へ戻しています。保護機能を無効にしたまま使い続ける対処ではありません。
その後
起動したあとのDVDドライブと更新
読み込みを止めた直後は、DVDドライブがデバイスマネージャーでエラー32（ドライバのサービスが無効）になることがあります。富士通では、DVDドライブのLowerFilters（ドライブが追加で使うドライバの一覧）に、止めたPxHlpa64の登録が残っていたためでした。その行だけを外して再起動すると、ドライブが認識されています。
光学ドライブを使わないPCなら、この作業は後回しで構いません。まず起動できる状態を優先します。ほかのドライバ名が並んでいる場合は、PxHlpa64の行だけを取り除きます。
修理店は、読み込みを止めた状態で、富士通にはKB5132061を入れ、NECには修理中に取り消した同じ更新を入れ直し、2台とも再起動後に通常どおりサインインできたと報告しています。
範囲
分かっていることと、まだ分からないこと
Microsoftは起動不能を既知の問題にしていない
KB5132061の更新説明（2026年11月25日確認）にある既知の問題は、サーバーでのSQL Serverのリンクサーバー接続と、一部のPCでインストールが完了しない症状（0x80070306、0x800f0989、0x800f0993）です。起動不能やPxHlpa64の記載はありません。
原因の説明は、修理店の推測の段階
修理店は、VBSと古いドライバの相性が起動不良に関係したと考えています。更新が直接の原因とは確認されていません。更新から数日後に症状が出たNECの1台は、それまでの起動が高速スタートアップで、再起動で初めて症状が出たと記録されています。ほかのPCに当てはまるかは分かりません。
ほかの原因の起動不能は別
Microsoft Q&Aには、このドライバに触れていない起動不能の報告もあります。ストレージの故障やBIOS設定の変化でも同じ画面になります。
更新プログラムがインストールできない（Windowsは起動する）症状は、
KB5132061がインストールできない原因と対処
で扱っています。
FAQ
よくある質問
PxHlpa64.sysは削除してよいですか？
勧められません。修理店の2台は、ファイルを消さず読み込みだけを止めて起動しています。削除すると、そのドライバを使うソフトが動かなくなることがあり、戻すにはバックアップやソフトの再導入が必要になる場合があります。
初期化する前に、まず何をすればよいですか？
BitLocker回復キーを用意し、更新プログラムのアンインストールとスタートアップ修復を試します。直らなければ、リセットの前にPxHlpa64の起動設定を確認します。
sc.exe qc PxHlpa64でFAILED 1060と出ました。
PxHlpa64の登録は見つかりません。修理店の2台と同じ条件ではないため、KB5132061のあとに起動できないときの切り分けに進みます。
光学ドライブを使っていなくても、このドライバは残っていますか？
残っていることがあります。修理店の2台は、DVD書き込みやバックアップ用のソフトが入っていました。使っていなくても、登録が起動時読み込みのまま残るかは、確認コマンドで見られます。
VBSやメモリ整合性を切れば、起動しますか？
NECの1台は、VBSを一時的に止めて起動しました。ただし対処の本筋はドライバを止めることで、止めたあとにVBSを戻しても起動しています。保護機能を無効のまま使うことは勧められません。

VirtualizationBasedSecurityStatus の値は、Microsoft Learn の説明では、0 が「VBS は有効になっていない」、1 が「有効だが実行されていない」、2 が「有効で実行中」です。

PxHlpa64 を無効にするために使ったコマンド
2台目では、起動した後に PxHlpa64 を無効にしました。使ったスクリプトの中心は次の3行です。管理者として開いた PowerShell で実行します。
reg export "HKLM\SYSTEM\CurrentControlSet\Services\PxHlpa64" <保存先> /y
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\PxHlpa64" -Name Start -Value 4 -Type DWord
(Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Services\PxHlpa64").Start
1行目で、変更前の PxHlpa64 の登録内容をファイルに書き出します。<保存先> には、書き出すファイルの場所を指定します。2行目で Start を 4 に変更し、3行目で変更後の値を表示します。2台目は、実行後に再起動して、PxHlpa64 が Stopped、Disabled になったことを確認しました。
この操作も、Microsoft が案内している手順ではありません。Corel のサポート資料は、PxHlpa64.sys を入れたソフトを特定し、削除するか対応した版に入れ替えることを案内しています（Corel の資料で、Microsoft の資料ではありません）。
無効にした後の影響
Microsoft Learn の説明では、Start が 4 のドライバーは無効で、読み込まれません。ドライバーが無効になっている機器は、デバイス マネージャーで Code 32 と表示されます。
PxHlpa64 は、CD/DVD ドライブのクラスの LowerFilters に登録されていました。Microsoft のサポートページには、CD/DVD ドライブが認識されない場合に UpperFilters と LowerFilters を削除する手順があります。削除した後は、CD/DVD の書き込みソフトが正しく動かなくなることがあるとも書かれています。
調べた端末には DVD ドライブがなく、ドライブの認識や書き込みの動作は確認していません。PxHlpa64 を無効にした後に確認できたのは、Photoshop Elements 12 が起動することだけです。

：国内の記事には、起動用の領域の空き不足で起動用のファイルが消えていた事例や、BIOS で仮想化機能をオフにして起動した事例の報告もあります（第三者の情報です）。KB5132061 の後に起動しない端末が、すべてこの記事の組み合わせとは限りません。
スポンサーリンク
まとめ
項目
1台目の記録
起動しなかったときの状態
PxHlpa64 の Start が 0、EnableVirtualizationBasedSecurity が 1、保留中の更新あり
起動した操作
値は 1 のまま、PxHlpa64 の Start を 4 に変更
DeviceGuard キーが更新された時期
KB5132061 を適用した起動の約5分後
起動しなくなった時期
その次の再起動（5日後）
起動した後の状態
仮想化ベースのセキュリティは実行中。メモリ整合性は実行されていない
Microsoft の掲載
既知の問題としての掲載なし（2026年11月22日に確認）
PxHlpa64 がある PC で、再起動の前に見る値は次の2つです。
PxHlpa64 の Start
：0 なら、起動時に読み込む設定です。
EnableVirtualizationBasedSecurity
：1台目が起動しなかったときは 1 でした。
この記事の内容は、1台の記録から判断したものです。Microsoft の掲載状況は今後変わる可能性があります。
たまのSE
PxHlpa64 が入っている端末は、再起動の前に2つの値を見ておくと状況が分かります🔍
