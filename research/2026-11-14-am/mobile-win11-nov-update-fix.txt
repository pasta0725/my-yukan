Microsoft confirms Windows security updates installation issues
                            By 
Sergiu Gatlan
November 12, 2026
05:24 AM
2
Microsoft has confirmed reports that the November 2026 security updates are failing to install on Windows 11 systems with the October preview update.
This follows widespread 
reports
 that the 
KB5132061
 update 
fails to install
, with affected users seeing the installation process lock midway and then trigger 0x800f0989 or 0x800f0993 errors.
"When attempting to install the November 2026 Windows security update (the Originating KBs listed above), some devices might be unable to complete the installation. Affected devices might repeatedly attempt to install the update or display error code 0x80070306, 0x800f0989, or 0x800f0993," Microsoft said in a 
service update
 seen by BleepingComputer.
"This issue affects a limited number of devices that installed the October 2026 non-security preview update (KB5127936). Devices that did not install the October 2026 non-security preview update are not affected."
Microsoft also told IT administrators that the installation issues will resolve automatically for all affected customers by Friday morning and that end users do not need to take any action to receive the fix.
"All affected devices should be repaired in 24 to 48 hours starting from November 11, 2026, 10am PT. Once your device receives the repair, it will automatically download and install the November 2026 security update via Windows Update," it added.
The company also urged admins still receiving reports of installation issues after 48 hours to contact Microsoft Support.
This is not the first time Microsoft has had to address Windows update installation issues since the start of the year. In March, it had to 
pull a buggy Windows 11 non-security preview update
 (KB5079391) because of 0x80073712 errors during installation.
In May, it also fixed 
installation failures
 and 0x800f0922 errors when deploying the May 2026 Windows 11 security update (
KB5089549
).
More recently, in June, Microsoft warned users that they 
may encounter issues installing the latest monthly updates
 and see 0x80073712 or 0x800f0993 errors on some Windows devices upgraded to Windows 11 24H2 or 25H2.

 Users are having difficulty installing Microsoft's latest Windows patch.

 error code. Others say they received a

 error.

It's an important patch to install, since it addresses 
726 vulnerabilities
 in Windows alone, and the difficulties affected users face are less than ideal.

This is an early report.
 Microsoft is still rolling out the repair for the first issue and has not yet released the fix for the second. We wanted to get the word out now, and we will update this page as Microsoft updates its guidance.
What to do
Windows 11 devices that installed the October preview update, 
KB5127936
, may fail to install the November update, 
KB5132061
.
 Microsoft says devices connected to the internet and using Windows Update in Settings should be repaired automatically within 24 to 48 hours of November 11, 10am PT. That window ends Friday, November 13, at 10am PT; check for devices still failing after that.
If you run SQL Server linked servers to Oracle, PostgreSQL or other databases through OLE DB, watch for open connections building up.
 Microsoft says an out-of-band fix (an update released outside the monthly schedule) is coming in the next few days, and Microsoft Support for business has a mitigation now.
1. The November update might fail to install on some Windows 11 devices
Microsoft's 
support article for KB5132061
, the November 10 security update for Windows 11 versions 24H2, 25H2 and 26H2, now lists a known issue. Microsoft says some devices "might be unable to complete the installation. Affected devices might repeatedly attempt to install the update or display error code 0x80070306, 0x800f0989, or 0x800f0993."
Which devices
BleepingComputer reports
 that Microsoft told administrators in a service update: "This issue affects a limited number of devices that installed the October 2026 non-security preview update (KB5127936). Devices that did not install the October 2026 non-security preview update are not affected." BleepingComputer says it saw that service update. The sentence does not appear in Microsoft's public support article, so BleepingComputer is our source for it.
Microsoft's update history lists the October preview, KB5127936, for Windows 11 versions 25H2 and 26H2 (builds 26200.9818 and 26300.9818). Microsoft's article also lists the known issue in its section for Windows 11 version 24H2, which covers Enterprise and Education editions only. Microsoft's update history does not list KB5127936 for 24H2, and Microsoft has not said whether 24H2 devices are affected.
What admins are seeing
Windows Latest reports
 that in its tests the update reached 99% before it failed, and that retrying made no progress. Its readers described the same error codes, including failures on four PCs and on two virtual machines. 
BetaNews
 also covered Microsoft's confirmation. Windows Latest also suggests a workaround of its own. Microsoft has not published one, so we do not repeat it here.
The repair
Microsoft says the repair runs automatically on affected devices connected to the internet and using Windows Update in Settings: "No manual action from end-users is required to receive the repair. All affected devices should be repaired in 24 to 48 hours starting from November 11, 2026, 10am PT. Once your device receives the repair, it will automatically download and install the November 2026 security update via Windows Update."
Microsoft's article does not say how the repair reaches devices updated through WSUS or other managed deployment tools. For devices still failing after 48 hours, Microsoft says to "use Windows help and learning or contact Microsoft Support."

2. SQL Server linked server connections might remain open
Microsoft confirmed this issue on its 
Windows release health dashboard
 on November 11. Microsoft says that after the Windows updates released October 13, 2026, and later are installed on server devices, "connections created by SQL Server linked server queries might remain open after the queries complete."
Microsoft says: "This issue affects SQL Server linked server queries that use OLE DB providers to connect to external databases. Oracle and PostgreSQL connections are among those known to be affected." Microsoft says the open connections can slow or degrade server performance over time, and that administrators might see a growing number of open connections to external databases after the linked server queries have finished.
Affected platforms, per Microsoft
Server:
 Windows Server 2025, Windows Server 2022, Windows Server version 1809, Windows Server 2016, Windows Server 2012 R2 and Windows Server 2012.
Client:
 Windows 11 versions 26H2, 26H1, 25H2, 24H2 and 23H2, Windows 10 version 1809 and Windows 10 Enterprise LTSC 2019. Microsoft added version 26H2 on its 
26H2 release health page
 on November 12; its other release health pages had not been updated when we checked.
Microsoft describes the issue on server devices and also lists these client versions. Microsoft says the issue applies to updates released October 13, 2026, "and later", and its status is still Confirmed. The November 10 updates are in that range.
Workarounds and the fix, per Microsoft
Closing idle connections, or restarting the SQL service, relieves the load for a while. Microsoft warns these steps "can also interrupt active queries or transactions, and the problem can resurface again after sufficient operation time."
"A mitigation is available for affected enterprise devices. To apply this mitigation in your organization, contact Microsoft Support for business."
"We will address this issue with an out-of-band update that will be released in the next few days."

Summary
KB5132061 Won’t Install? Microsoft Says October’s Preview Update Is to Blame
Who should care:
 Windows 11 admins with devices stuck on KB5132061, especially anyone running an early or pilot update ring.
What could go wrong:
 November’s security fixes never reach your machines, while the dashboard shows “pending.”
Do this:
 Find every device that installed KB5127936 and watch its build number.
Worth remembering:
 Skipped the October preview? You’re not affected.
Introduction
Windows 11 admins spent Patch Tuesday watching the November security update fail, retry and fail again. Microsoft now says 
the November update, KB5132061, breaks on machines that installed October’s optional preview
, and a repair is already rolling out.
What Happened With KB5132061?
Microsoft released the update on 
November 10
 for Windows 11 24H2, 25H2, and 26H2. Within hours, forums filled up with reports of installs freezing partway through and rolling back. Some PCs got stuck in a loop. Others showed 0x80070306, 0x800f0989 or 0x800f0993.
On November 11, Microsoft confirmed the bug. The trigger is 
KB5127936
, the optional preview update from October 28. Devices that skipped it aren’t affected. Microsoft started pushing an automatic repair at 10am PT that day and expects to fix every affected device 
within 24 to 48 hours
. After that, Windows Update installs the November patch automatically.
This isn’t the first time this year that Windows patching stalled on Microsoft’s side. In July, 
a WSUS sync failure left patches stuck
 for a different reason.
What’s the Impact?
Until the repair lands, 
affected PCs stay on October’s code and miss November’s security fixes
. The gap hits the machines in your pilot ring and the eager users who updated first. It also burns helpdesk time: users report that resetting Windows Update components and installing manually from the catalog didn’t help.
How to Avoid This
Tag them:
 Find every device that installed KB5127936 and track them as one group.
Leave them online:
 Keep them connected to Windows Update so the repair can arrive. Don’t wipe update caches over and over.
Check builds:
 After 48 hours, confirm 
26100.9974
 (24H2), 
26200.9974
 (25H2) or 
26300.9974
 (26H2).
Ring fence previews:
 Keep optional previews in a small test ring and out of production.
Managed fleets:
 If you patch through WSUS or Intune, check Microsoft’s release health page for how the repair reaches your devices.
KB5132061 Indicators of Compromise (IOCs)
This is a bug in how Windows installs updates. 
No attacker is involved
, so there are no hashes, IPs or domains to block. Look for the three error codes above, the same install retrying repeatedly, and “2026-11 Security Update (KB5132061)” marked as failed in update history. Users have also reported 0x800f0922 and 0x800f0915, but Microsoft’s note doesn’t mention them.
One more warning: scammers love a broken patch, so 
only get fixes from Windows Update or the Microsoft Update Catalog
.
“Approved” Isn’t the Same as Installed
Your patch calendar says November is done. Some of your devices may still be on October’s code.
Secure.com’s AI teammates close that gap, under rules your team sets:
Track the real install state of each device, so a stuck install shows up as open exposure instead of “pending”
Group machines by what they installed last month, so preview ring devices get flagged together
Match November’s unpatched CVEs to the stuck machines and rank them by which ones an attacker can actually reach
Draft follow-up tickets for your team to approve, so nobody burns a day on registry resets
Recheck after the repair window and keep evidence that each device is patched
Attack. Harden. Prove. Repeat.
Conclusion
These failures only hit devices that took October’s optional preview, and Microsoft is fixing them remotely. Leave those machines online, skip the manual resets, and 
check the build number after 48 hours
. Anything still behind after that needs escalation.
FAQs
What is KB5132061?
KB5132061 is the November 10, 2026 security update for Windows 11 versions 24H2, 25H2, and 26H2. It fails to install on some devices.
Why won’t KB5132061 install on my PC?
Microsoft says the failure only hits devices that installed KB5127936, the optional preview update released on October 28. Devices that skipped that preview install the November update normally.
What error codes show up when the update fails?
Microsoft confirmed 0x80070306, 0x800f0989 and 0x800f0993. Some devices also retry the same installation repeatedly with no error shown. Users have also reported 0x800f0922 and 0x800f0915, but Microsoft has not listed them.
How do I fix it?
You don’t need to do anything manual. Keep the device online and connected to Windows Update. Microsoft is pushing an automatic repair and expects affected devices to be fixed within 24 to 48 hours, after which the November update installs automatically.
How do I know the repair worked?
Check the OS build. Patched devices show 26100.9974 on 24H2, 26200.9974 on 25H2, or 26300.9974 on 26H2. If a device is still on an older build after 48 hours, escalate it and check Microsoft’s release health page.
Is this a security attack?
No. It is a servicing bug, not an attack. The risk is that stuck devices miss November’s security fixes until the repair lands. Only get fixes from Windows Update or the Microsoft Update Catalog, never from third-party repair tools.
