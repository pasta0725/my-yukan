Security & Identity
Built for trust and control: Powering the next wave of AI agents across Google Workspace and Google Cloud
November 24, 2026
Chandu Thota
VP, Engineering, Workspace
Brad Calder
President, Google Cloud Platform & SRE
For over 20 years, we have protected 4 billion users and 13 million organizations in Workspace, and critical enterprise and government systems on Google Cloud. From personal and financial records to board materials, regulated workloads, applications, and AI models, those safeguards protect what matters most. Blocking >99.9% of spam, phishing, and malware, alongside encryption and data residency, follows one principle: your data is yours, and you should always know and decide who can access it.
That trust has powered one of the world’s largest developer ecosystems. Workspace APIs now handle more than 2.8 trillion calls a month, and public Google Drive API traffic alone is more than two-and-a-half times the volume of 2022. More than 18 billion reads from Drive each day come from API callers. Traditional REST APIs were built for human-paced apps where a valid OAuth token implied user intent. As AI agents shift from reading information to acting autonomously at machine speed across email, documents, datasets, and cloud infrastructure, a valid token is no longer enough. Policy checks, data boundaries, and human confirmation have to live in the request path. 
Today, Workspace MCP servers and the Workspace CLI are generally available alongside Google Cloud Agent Gateway and unified protections across Workspace and Google Cloud. Builders get modern, agent-ready interfaces, and organizations get the visibility and control to adopt AI agents with confidence.
Purpose-built interfaces: Workspace MCP servers, Workspace CLI, and Cloud Agent Gateway
To help developers build reliable agents faster without forcing security teams to compromise, we are bringing agent-native interfaces to Workspace and Google Cloud:
Workspace MCP servers
:
 Now generally available, dedicated remote servers for Gmail, Google Drive, Docs, Sheets, Slides, Calendar, Chat, and Tasks. Builders get one standard interface with built-in permission and DLP checks, and native human-in-the-loop (HITL) confirmations for sensitive actions. They also reject non-agent OAuth clients and work with Model Armor, Google Cloud’s prompt-injection screening service.
Workspace CLI
:
 Now generally available for local agents, terminal workflows, and automation, providing structured JSON outputs and scoped OAuth sign-in across Workspace services.
Google Cloud Agent Gateway
:
 A protocol-native gateway for LLM, MCP, and Agent2Agent (A2A) traffic on Google Cloud. It verifies Agent Identities against Agent Registry, enforces IAM policies and default-deny outbound rules, and screens requests with Model Armor.
Together, these interfaces give AI agents open, protocol-native paths built on standards like MCP and A2A. Permissions, confirmations, prompt screening, and audit logging happen automatically, while traditional apps continue to run on existing REST APIs.
Consistent controls across every agent workflow
Those interfaces sit on a unified security model across Workspace and Google Cloud, with core controls shipping today:
Policy checks on every request:
 Under our new 
Workspace AI Tools Addendum
, AI agents must use Workspace MCP servers or the Workspace CLI rather than existing REST APIs. Technical enforcement begins on February 1, 2027, giving builders time to transition. Every call is checked against your organization’s Workspace permissions, DLP rules, and classification labels. On Google Cloud, Agent Gateway enforces IAM and default-deny outbound rules at the protocol layer and routes custom checks through Service Extensions to Identity-Aware Proxy, your own policy engine, or third-party security tools.
Separate agent identities and limits:
 Admins and users need to tell an AI agent apart from a traditional app or a person, and cap what it can do. Agents connecting to Workspace must use dedicated 
OAuth client IDs
, paired with least-privilege scopes, time-limited approvals (coming soon), and 
usage quotas
 (billing begins on April 1, 2027). On Google Cloud, agents receive their own Agent Identity in Agent Registry with no shared or long-lived keys, bounded by IAM policies and organization, folder, and project quotas. Those identities can also carry user-delegated authorization into Workspace when accessing mail or files.
People stay in charge of high-impact actions:
 Routine work like creating drafts or summarizing documents runs autonomously, while critical changes require a person to sign off. In Workspace, MCP servers and the CLI enforce explicit user confirmation before agents send email, change Drive sharing permissions, or make bulk edits. On Google Cloud, policy can require multi-factor authentication or human approval before reading sensitive Cloud Storage buckets, changing IAM permissions, or modifying production infrastructure.
Clear visibility and revocation:
 A one-time consent screen is not enough when agents run continuously. Workspace administrators can view, audit, and revoke AI agents in the 
admin console
, and users will soon be able to view agent activity and revoke access to their emails and files. On Google Cloud, Security Command Center, Agent Observability, Cloud Audit Logs, and Wiz surface unusual behavior. Revoking a Cloud Agent Identity or OAuth grant stops access immediately.
Boundaries for your most sensitive data:
 Coming soon in Workspace, AI access restrictions extend Workspace DLP and client-side encryption protections to agents. This will allow admins and users to block agents from accessing messages in Gmail and specific files and folders in Drive. On Google Cloud, VPC Service Controls, Principal Access Boundaries, and Context-Aware Access keep sensitive data inside designated perimeters and verified devices.
Strict rules on your data afterward:
 Our new 
Workspace AI Tools Addendum
 sets clear boundaries for AI tools using Workspace APIs. It does not allow permanent raw storage, model training, extended retention of derived data, or API scraping. Derived and user data are removed within a defined window and when a user disconnects. On Google Cloud, Sensitive Data Protection masks sensitive fields before data leaves, and customer-managed or external encryption keys let you cut off access to Cloud agent memory stores immediately.
Getting started
Workspace developers:
 Start building with the 
Workspace MCP and CLI configuration guide
, implement 
user confirmations via MCP
 and prompt-injection protection such as Model Armor, and review the 
Workspace AI Tools Addendum
.
Workspace administrators:
 Review connected apps and agents, configure DLP policies for your users, and monitor OAuth activity logs in the 
admin console
.
Google Cloud customers:
 Register Agent Identities in Agent Registry, place Agent Gateway and Model Armor in front of agents and MCP servers, configure MFA or human approval for sensitive actions, and review IAM, VPC Service Controls, and quota limits.
With Workspace MCP servers and the Workspace CLI generally available alongside Google Cloud’s agent protections, developers have an open, modern platform to build on. Organizations get the visibility and control to scale AI agents with confidence.

Google、Workspace MCP サーバーと Workspace CLI の一般提供を開始。管理機能も拡充
2026
11/25
2026年11月25日
Masahide Omura
当サイトは Google Adsense、Amazon アソシエイト等 アフィリエイト広告を利用して収益を得ています.
Google は 2026 年 11 月 24 日 (現地時間)、AI エージェントを Google Workspace に接続するための Workspace MCP サーバーと Workspace CLI の一般提供を開始したことを
発表
しました。
同時に、API や MCP サーバー、CLI の使用量を Standard と Scaled の 2 つのティアに分け、2027 年 2 月 1 日からは AI エージェントによる Workspace データへのアクセスに MCP の利用を必須とします。
Scaled ティアを選んだプロジェクトには、2027 年 4 月 1 日から、1 日あたりの無料枠を超えた分の使用量に対して課金されます。
目次
Workspace MCP サーバーと公式 Workspace CLI の一般提供
開発者が独自の連携コードを書かずに AI エージェントを Google Workspace へ接続できる Google 管理の 2 つの手段として、Workspace MCP (Model Context Protocol) サーバーと Workspace CLI が一般提供されます。
Workspace MCP サーバー
: オープンな MCP 標準に基づく Google ホストのサーバー。クラウド型や Web ベースの AI エージェントから、Gmail、Google ドライブ、Google ドキュメント、Google スプレッドシート、Google スライド、Google カレンダー、Google チャット、Google ToDo リストの構築済みツールをすぐに呼び出し可能
Workspace CLI
: 開発者のターミナル、仮想マシン、コンテナ化されたサンドボックスなどのローカル環境で動作するコマンドラインツール。パッケージ化されたエージェントスキル、動的なコマンド検出、スコープ限定のログインを備え、Workspace データの読み取りや更新に対応
Workspace MCP サーバーは、今後 Google Keep にも対応する予定です。
従来の REST API があらかじめ決まったアプリからの呼び出しを前提としていたのに対し、この 2 つは動的なエージェントワークフロー向けに設計されています。Google がフルマネージドで運用するため、実行時にツールやスキーマを検出するエージェントは、コンテキスト取得や認証設定、ツール精度の改善を自動で取り込めます。
REST API で生データを 1 行ずつ取得する代わりに、MCP ツールは Workspace の境界内で要約した結果を返し、CLI はターミナル上で複数ツールを連携して処理できるため、トークンコストと遅延を抑えられます。
ユーザー確認や監査ログ、管理者制御を標準で備えているため、OAuth 検証やクラウドアプリケーションセキュリティ評価、企業のセキュリティ審査にかかる手間も軽減されます。
API の標準化使用ティアと 2027 年の適用期限
Google は 2026 年 5 月に発表した
標準化使用モデル
に基づき、MCP サーバーと CLI を含む Workspace API に 2 つの使用ティアを導入しました。
まずは Gmail、Google ドライブ、Google カレンダーから適用され、その他のデータアクセス手段も今後数か月かけて同様に更新されます。
Standard ティア
: 無料。公開済みの使用クォータ (レート制限) を適用
Scaled ティア
: より高い使用クォータが必要なプロジェクト向け。2027 年 4 月 1 日以降、1 日あたりの無料枠を超えた API または MCP の使用量に対してのみ課金
現在、アクティブな開発者の 99% 以上は Standard ティアの範囲内で動作しており、今後も追加費用なしで利用を続けられます。プライバシーやデータ損失防止 (DLP)、データ保護の基準はすべてのティアで共通です。
Google Cloud サポートを契約している場合、Workspace API は少なくとも 2027 年 12 月までサポート変動費の計算対象から除外され、変更時は 90 日前までに通知されます。
AI エージェントや類似のアクセスツールについては、Workspace REST API を直接呼び出すのではなく MCP を利用することが必須になります。
技術的な強制適用は 2027 年 2 月 1 日から始まるため、エージェント向けに高いクォータが必要な場合は MCP へ移行したうえで Scaled ティアを選択する必要があります。
組織向けの AI エージェント管理機能と新規約
AI エージェントの接続を容易にする一方で、企業や組織が自社データを管理し続けられるよう、従来の Workspace と同じガバナンス原則が AI エージェントにも拡張されます。主な制御は次のとおりです。
データ保持とスクレイピングの制限
: 新しい 
Workspace AI Tools Addendum
 により、Workspace API から取得した特定データの長期保存や、AI エージェントによる Workspace API のスクレイピングを禁止
一元的なアクセス管理
: 外部 AI エージェントに OAuth での自己識別と Workspace MCP サーバー経由の接続を求めることで、従来のアプリと同様に管理コンソールからアクセスを制御可能 
ヒューマンインザループ (HITL) 確認
: 下書き作成のような日常的な操作はそのまま維持しつつ、外部ファイルの読み取りやデータ共有といった機密性の高い操作でユーザーの確認を求めるルールを設定可能
DLP の自動適用と監査ログ
: 既存のユーザー単位の DLP ルールが AI エージェント利用時にも自動で適用され、エージェントの操作やユーザー確認の履歴を管理者の監査ログに記録
Google は今後数か月にわたり、より細かなエージェントポリシーと制御機能を追加していく予定です。
管理者と開発者が取るべき対応
今回の変更に伴い、管理者は管理コンソールでの制御設定と内部プロジェクトの指定を、開発者は MCP への移行準備と使用状況の確認を進める必要があります。
管理者向けの対応
管理者は管理コンソールの 
[セキュリティ] > [API 制御]
 から、外部 AI ツールや Workspace MCP サーバー、Workspace CLI、API のアクセス管理、HITL 確認ルールの設定、エージェント監査ログの確認を行えます。アクセス管理の詳細は 
Google Workspace 管理者ヘルプ
に記載されています。
自組織内だけで利用するプロジェクトについては、管理者が内部プロジェクトとしてマークすることで、Workspace サブスクリプションに含まれる高い上限をそのまま維持できます。
設定手順は
内部利用プロジェクトに関する開発者ガイド
で確認できます。
開発者向けの対応
AI エージェントを開発している場合は、2027 年 2 月 1 日の技術的強制適用までに REST API から Workspace MCP サーバーへ切り替える計画を立てる必要があります。
Google Cloud コンソールでは、AI エージェントが使用する OAuth 2.0 クライアントで「Use this client for an AI-powered agent (is_agentic)」を選択し、従来の非エージェント機能には別の OAuth クライアントを用意します。
設定方法は 
OAuth クライアントのドキュメント
 で確認でき、あわせて新しい Workspace AI Tools Addendum の確認も求められます。
既存プロジェクトの使用状況は、Workspace API の使用量を確認できる新しい開発者向けダッシュボードで、Standard ティアのレート制限や想定コストと照らし合わせて確認できます。すべてのプロジェクトが上限内に収まっていれば対応は不要です。
Standard ティアの上限を超えるプロジェクトや、すでに高い上限が割り当てられているプロジェクトは、2027 年 4 月 1 日までに以下のいずれかを実施する必要があります。
自組織内だけで使用するプロジェクト
: Workspace 管理者に依頼し、プロジェクトを内部としてマーク
それ以外のプロジェクト
: Cloud 請求先管理者に依頼し、請求先アカウントのリンクと Scaled ティアへの切り替えを実施
2027 年 4 月 1 日までに対応しなかった場合、プロジェクトの上限は追加費用なしで自動的に Standard ティアのレート制限へ切り替わります。
AI エージェントについては、それに先立つ 2027 年 2 月 1 日から MCP 必須化が適用されます。
展開スケジュールと対象
今回のアップデートは、すべての Google Workspace ユーザーおよび開発者が対象です。
即時リリースドメインと計画的リリースドメインの双方で、Workspace MCP サーバー (GA)、Workspace CLI (GA)、管理コンソールのエージェント制御や HITL、監査ログ機能、Workspace API の使用量を確認できる開発者向けダッシュボード、Scaled ティア選択は 2 週間ですべてのドメインに展開される予定です。
今後の主要な期限は以下のとおりです。

: AI エージェントに対する MCP 利用必須化の技術的強制適用を開始
2027 年 4 月 1 日
: Gmail、Google カレンダー、Google ドライブ API および Workspace MCP サーバーで Scaled ティアの課金を開始し、未対応の高上限プロジェクトを Standard ティアの上限へ自動移行
影響を受けるプロジェクトの Google Cloud 請求先管理者およびプロジェクトオーナーには、プロジェクトごとの詳細と次の手順を記載したメールが Google から送信されます。

What Google’s pages say
MCP servers and gwscli are GA today
The 24 November blog post says Google is “making Workspace Model Context Protocol (MCP) servers and the official Workspace CLI generally available”. The MCP setup guide, last updated 19 November, still carries a Developer Preview banner and lists Preview Program membership as a prerequisite.
8 servers: Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, Tasks
The blog post names the same eight and says Keep is coming soon. The setup guide’s server table also lists People, Classroom and a Universal Search server, and doesn’t list Tasks.
Free tier: 5,000 req/day per product
Google’s Calendar MCP page says Standard tier GA MCP servers are “capped at 5,000 no-cost requests per day, per project”. The Gmail and Drive quota pages I read list per-minute limits only.
Built-in human-in-the-loop for send and share
The CLI guide says approval prompts cover sending messages, sharing content externally, trashing items and deleting data. Other write actions run without asking once scopes are granted.
1-click Personal mode, no Enterprise plan or billing card
Personal mode makes a single-user OAuth client and skips consent screen setup and app verification. Google’s Standard tier “never produces charges”. The setup steps in the guides don’t ask for a billing account, which only the paid Scaled tier needs.

Two ways in
Google describes two managed routes to Workspace data. The MCP servers are Google-hosted and suit cloud and web agents, with one URL per product such as 
https://gmailmcp.googleapis.com/mcp/v1
. 
gwscli
 is a binary for developer terminals, VMs and containerised sandboxes, and it ships with packaged agent skills. It covers Calendar, Chat, Docs, Drive, Gmail, Sheets, Slides and Tasks, plus People in Developer Preview.
Same project, same sign-in, two routes. Pick by where your agent runs.
Don’t confuse it with the 
googleworkspace/cli
 repository on GitHub. That one installs a tool called 
gws

gwscli

Google’s quota pages list each server’s tools. Gmail has

The approval gate covers four actions. Everything else is down to the scopes you grant.
In an organisation, admins get more. The Admin console’s Security, API Controls page manages external AI tools, the MCP servers and the CLI, sets confirmation rules and shows agent audit logs. Existing data loss prevention rules apply to agent use automatically. Since 11 November, Google’s release notes say, the MCP servers reject OAuth clients that aren’t marked “Use this client for an AI-powered agent”.
The free tier, and what changes in 2027
The Standard tier costs nothing and never produces a Google Cloud charge. Google says over 99% of active developers sit inside it. The 5,000 a day is a request count, so an agent that searches mail and then reads three threads to answer one question spends four of them. That sum puts the ceiling near 1,250 questions a day per project.
The cap counts requests, not questions, so chatty agents reach it sooner.
Projects that need more can enrol in the Scaled tier, and Google’s Calendar page says Scaled Calendar MCP usage is charged from the first request, with no daily allowance, from 1 April 2027. Projects that already have higher limits keep them until 1 April 2027, then drop to Standard limits unless they switch to Scaled or an admin marks them internal. After 1 February 2027, agents calling REST directly are held to Standard limits whatever their tier. A new Workspace AI Tools Addendum also bars using agents to scrape Workspace APIs or to store certain derived data for long periods.

Security and telemetry
Google’s setup guide has a prompt injection warning: an agent that reads a hostile email or shared file can be steered into changing or deleting data. 何が変わったか
MCP（Model Context Protocol）は、AIが社外のサービスとやり取りするための共通の接続方式です。Googleは、AIエージェント（指示を受けて自分で操作まで進めるAI）がGoogle Workspaceのデータを扱うための「Workspace MCPサーバー」と、開発者向けの「Workspace CLI」を一般提供にしたと発表しました。MCPサーバーで扱えるのは Gmail・ドライブ・ドキュメント・スプレッドシート・スライド・カレンダー・Chat・ToDoリスト（Tasks）で、Keepは「近日対応」とされています。
管理担当者にとっての本題は、管理コンソールの「セキュリティ」>「APIの制御」で次の3つを扱えるようになる点です。
●
どのAIを通すか：社外のAIエージェントはOAuth（Googleアカウントでのログイン許可の仕組み）で自分がAIエージェントだと名乗り、MCPサーバー経由で接続する。管理者は従来のアプリと同じように、管理コンソールで接続の可否を管理できる
●
重い操作の前に本人の確認を挟むルール：下書き作成のような日常の操作はそのまま通し、社外のファイルを読む・データを共有するといった操作の前にユーザーへ確認を出すルールを管理者が設定できる
●
エージェントの監査ログ：AIエージェントが行った操作と、ユーザーが確認した記録が管理者の監査ログに残る。ユーザー単位で設定済みのDLP（情報漏えい防止）ルールも、AIエージェント経由の操作に適用される
もう1つ、期限のある変更があります。Googleは、AIエージェントはWorkspaceのREST API（プログラムから直接データを読み書きする窓口）を直接呼ぶのではなくMCPを使わなければならないとし、
2027年2月1日から技術的に強制する
と発表しています。
利用量にも枠が設けられました。無料で決められた上限まで使える「Standard」と、上限を超えて使う「Scaled」の2段階で、まずGmail・ドライブ・カレンダーから適用されます。Scaledを選んだ場合、2027年4月1日から1日の無料分を超えた利用に課金が始まります。Googleは、利用中の開発者の99%以上はStandardに収まり追加費用はかからないとしています。社内だけで使う仕組みは「社内用」として登録すれば、高い上限もWorkspaceの契約に含まれると説明しています。

「つなぐのはいいが、共有の前には本人に確認させる」
