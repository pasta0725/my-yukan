偽のフォーム・なりすましに注意
話題のサービスのテスター募集では、公式をまねたアカウントや偽の応募フォームが出回ることがあります。検索結果やリプライ欄に出てくるリンクから応募せず、必ず公式アカウントの投稿を起点にしてください。パスワードやクレジットカード番号を求めるフォームは、テスター応募としては不自然です。
テスト版に入れる情報に気をつける
テスト中のアプリは、不具合や仕様変更、データの消去が起きることがあります。これは一般的なテスト版の性質です。今回のアプリの規約は、まだ公開されていません。
参考になるのはSakana Chatの扱いです。公開情報によると、Sakana Chatでは入力したデータがAIの学習に使われる場合があり、設定でオプトアウト（学習に使わせない設定）ができます。個人情報の入力は規約で禁止されていて、会話履歴は国内のGoogle Cloudに保管されます。メモリ機能のMy Fishは初期設定でオンになっていて、設定画面の「メモリ」からオフにできます。
アプリでも同じ扱いになるとは限らないため、テスト中は次のものを入れないのが無難です。
氏名・住所・電話番号などの個人情報

まだ公開していない仕事の情報
業務で使えるか：テスト版は個人の試用にとどめる
Sakana AI App（仮）のテスト版を仕事で使うのは避けたほうがよいです。規約やデータの扱いが公開されておらず、会社として利用を認める判断材料がそろっていないからです。
Sakana AIの技術を会社で使いたい場合は、法人向けの窓口が別にあります。2026年10月28日にアーリーアクセスが始まったSakana API Platformは、入力データを学習に使わないと公式に明記しています。社内の業務フローに組み込みたいなら、アプリではなくこちらを検討するのが筋です。
社内のシステムにAIを組み込むときは、どのモデルを使うかより先に、どの業務を対象にするか、どのデータを渡すか、PoC（小さく試す段階）から本開発にどう進めるかを決めておくと、見積もりがぶれにくくなります。費用の目安は

Sakana AI は、どんな会社として知られてきたか

モデルとサービスを、役割で整理する
Sakana AI のラインアップは名前が多く、最初は関係が見えにくいかもしれません。そこで先に、一行ずつの役割で全体を見渡します。

次の節から、一つずつ見ていきます。
Fugu は、複数のモデルを束ねて一つのモデルとして出す
最初に Fugu です。平たく言うと、世の中にある複数の強い AI モデルを束ねて、あたかも一つのモデルのように使えるようにする基盤です。ここでは位置づけが大事なので、先に押さえておきます。
同社は Fugu を「Multi-Agent System as a Model」と位置づけています。マルチエージェントシステム（複数の AI が役割を分担して働く仕組み）を、一つのモデルとして提供する基盤、という意味です。Fugu が一つの巨大なモデルだという意味ではありません。
仕組み
Fugu の中身は、強力で多様なモデルの集まり（プール）です。そのプールのモデルを動的に組み合わせ、協調させて性能を引き出します。
特徴は、次の三つです。
モデルの編成、役割分担、処理の進め方を、学習によって獲得します。人が設計したワークフローには頼りません
特定のクローズドモデル（中身が非公開のモデル）が使えなくなっても、止まらずに動き続けます。単一のベンダーに依存しない設計です
プールに加えるエージェントを選べます。データ、プライバシー、コンプライアンスの要件に合わせて、特定のプロバイダーやモデルを除外できます
4つのモデル
Fugu には4つのモデルがあります。いずれも OpenAI 互換 API（外部のプログラムからモデルを呼び出すための窓口）から利用できるため、連携の仕組みを変えずに切り替えられます。
Fugu：性能とレイテンシ（応答の速さ）のバランスを取った、日常の作業向けの標準モデルです
Fugu Ultra：最高性能のモデルです。より広い専門エージェントのプールを連携させ、難しい問題で回答の品質を最大にします
Fugu Max：コストと性能のバランスを重視したモデルです。最大のモデルプールを束ねます。NVIDIA との協業による Nemotron ファミリーも含みます
Fugu Cyber：サイバーセキュリティに特化したモデルです。セキュリティ分析、脆弱性調査、脅威調査などに向きます
裏付けとなる研究
中心になるのは、ICLR 2026 に採択された2本の論文です。
TRINITY：軽量な進化型のコーディネーターが、複数の LLM（大規模言語モデル）に Thinker（思考役）、Worker（実行役）、Verifier（検証役）の役割を割り当てる仕組みです
Conductor：強化学習（試行錯誤を繰り返しながら学ぶ方法）によって、自然言語による協調の戦略そのものを学習する手法です
料金の例として、Fugu Max の API 料金は、入力が100万トークンあたり $2、出力が $6 です（トークンは、モデルが文章を処理するときの数え方の単位です）。これは API の料金であり、新しいアプリの料金ではありません。
公式ページはこちらです。

One model to command them all
sakana.ai
Namazu は、日本語と日本の業務に合わせた単一モデル
Fugu が複数のモデルを束ねる基盤なら、Namazu はその対極にあたる一つのモデルです。
何者か
Namazu は、日本語に特化した LLM です。オープンモデル（中身が公開され、誰でも利用できる形で配布されているモデル）の Kimi K2.6 をベースに、同社独自のデータで、日本語と日本の業務に合わせた追加学習（公開済みのモデルに自社のデータを学ばせ、目的に合わせて育て直すこと）を行いました。完成したのは、単体で動作する自社のモデルです。
仕組みと使い方
敬語や商習慣を踏まえた自然な日本語で、業務文書やメールを処理できます
Web 検索とコード実行を標準で備えています。一度頼めば、モデル自身が Web を調べ、コードを書いて動かしながら、タスクを最後までこなします
OpenAI 互換 API で提供されます（モデル名は sakana-namazu）。接続先の設定を変えるだけで、既存のコードやツールから使えます
Fugu との違い
公式 FAQ は、二つを次のように対比しています。
Fugu：複数のフロンティアモデルを編成して、性能を引き出すサービス
Namazu：独自に追加学習した単一の自社モデルが、単体で動作する API サービス
料金は従量制で、月額はありません。公式ページの表示では、入力が100万トークンあたり $0.95、出力が $4.00 です。Web 検索は1,000回あたり $7、コード実行は1時間あたり $0.12 かかります。なお、2026年12月1日から、入力 $1.90、出力 $6.00 に改定されることが、公式ページに表示されています。
公式ページはこちらです。

LLM with Japanese Vibes
sakana.ai
Marlin は、戦略リサーチを担うエージェント
ここまでの Fugu と Namazu はモデルそのものでした。Marlin は、モデルそのものではなく、仕事そのものを引き受けるエージェント（頼まれた仕事を、調べ物をしたり道具を使ったりしながら、自分で進めていく AI）です。
何者か
Marlin は、戦略リサーチを引き受ける自律型のエージェントです。キャッチコピーは「Your Virtual CSO（あなたの Virtual CSO）」です。CSO は最高戦略責任者のことで、その役割とチームが数週間かけるような本格的な戦略リサーチを、肩代わりすることをうたっています。
動き方と成果物
テーマを設定すると、人手を介さずに、次の流れを自分で繰り返します。
仮説を立てる
情報を集める
Web を探索する
食い違う情報の矛盾を解消する
この推論は、最大8時間にわたって連続し、自律的に進みます。基盤技術は AB-MCTS です。
成果物は、要約ではありません。因果関係を読み解いて構造化した、戦略の選択肢です。参考文献を備えたレポートに加えて、PowerPoint のスライドまで自動で作られます。
誰向けか
Marlin は事業者向けのサービスで、公式 FAQ によれば、一般消費者としての利用は想定されていません。この記事では、Sakana AI の全体像を知るための例として紹介しています。

Pro：月額 ¥150,000
Team：月額 ¥400,000
Enterprise：個別見積もり
