Remixで、自分の画面だけ見た目を変えられます
158の中心的な追加が「Remix」（Web Remix）です。公式リリースノートは、対応するウェブページを、用意された見た目の操作、または自然言語の依頼によって自分向けに変えられる、と説明しています。変更は利用者のブラウザ プロファイルだけに残り、一時停止や削除の操作も用意されています。
Microsoftサポートの「
Microsoft Edge の Web リミックス
」によると、アドレスバーのリミックス アイコンから次のどちらかを選べます。
外観（Appearance）：
ダークモードのオン、背景色の変更、フォントの種類とサイズの調整。この種類は端末の中だけで動き、ページのデータはMicrosoftに送られない、と説明されています
ユーザー設定（Custom）：
「レシピの手順だけを表示する」「価格をすべてユーロに換算する」といった文章の指示で、ページの見え方を変えます。リミックスは、サイト全体（ドメイン）にも、個別のページにも適用できます
公式サポートは、長い記事を読みやすくする、詳細ページに要約を足す、レシピを買い物リストに変える、価格を現地通貨に換算する、ページの外観を更新する、といった使い方を例に挙げています。11月17日の
Microsoft Edge公式ブログ
は、古い社内アプリや、開発の手が回っていないダッシュボードなど、使いにくいページの余分な表示を減らしたり、見た目を変えたりできる、と紹介しています。プリセットのテーマやフォントを選ぶか、普通の言葉でカスタムのRemixを指示します。保存は端末の中で、オンとオフは切り替えできます。
日本の業務サイトや社内ツールでも、公式が示している範囲で使うなら、次のような場面が考えられます。文字が小さくて読みにくい管理画面でフォントを大きくする、背景を変えて長時間の確認作業を見やすくする、長いマニュアルやヘルプから手順だけを残す、海外サービスの料金表示を円に換算する、といった使い方です。公式が強調しているのは、元のウェブサイトやサーバー上の内容は変わらないこと、ほかの人の画面には反映されないこと、すでに表示されている内容だけを対象にすることです。ペイウォールやログイン、有料登録を迂回する機能ではない、とも明記されています。
Remixを適用した公式のデモ画面。アドレスバーに「Remix active」と表示され、現在のページ向けのRemixをオン・オフできる。出典：
Microsoft Edge公式ブログ「Edge for Business becomes the most used enterprise browser and unveils Ignite 2026 innovations」
（掲載の公式デモ動画より）
カスタムのRemixを作るときは、ページのURLとドメイン、ページの内容、入力した指示がMicrosoftに送られ、リミックスの生成にだけ使われる、とサポートページは説明しています。処理が終わると、そのデータはMicrosoftのサーバーから破棄され、できたリミックスは端末の中に保存されます。保存済みのパスワード、オートフィル、支払い情報にはアクセスしないこと、生成に使った内容をAIモデルの学習には使わないことも書かれています。一方で、カスタムのRemixは試験的な機能であり、結果が不正確だったり、安定しなかったりする可能性がある、とも注意されています。機密の個人情報（財務、健康、身分が分かる情報など）が含まれるページでは使わないよう、公式は呼びかけています。
提供範囲については、公式の案内に差があります。安定版158のリリースノートはRemixを機能更新として案内し、企業向けにはRemixAvailabilityポリシーで制御できるとしています。11月17日の公式ブログも、Edge for Business向けに「Generally available」（一般提供）と記しています。一方、Microsoftサポートの説明ページ（本稿の確認時点）には、コンシューマー向けでMicrosoftアカウントでのサインインが必要であること、現在はEdge Beta向けの限定的な外部実験であり、ほかのバージョンではまだ広く利用できないこと、が書かれたままです。利用できる国やプランを一覧した公式の表は見つかりませんでした。導入の判断は、自社のEdgeの版と、管理ポリシーの設定を確かめたうえで行ってください。
管理者はRemixAvailabilityで制御できます
企業や学校向けの制御は、ポリシー「
RemixAvailability
」（Control Remix availability）です。対象はWindowsとmacOSの158以降で、AndroidとiOSは対象外です。必須ポリシーとして設定でき、推奨ポリシーとしては使えません。グループ ポリシーの場所は「Administrative Templates/Microsoft Edge/Remix settings」、Windowsのレジストリは 
SOFTWARE\Policies\Microsoft\Edge
 のDWORD値 
RemixAvailability
 です。
0（Disabled）：
Remixを使えなくします。設定も無効になり、ツールバーに出ず、別の入り口からも起動できません
1（Force enabled）：
Remixを使えるようにし、ツールバーに固定します。利用者はオフにしたり、ツールバーから外したりできません
未設定：
利用者が、ツールバーにピン留めするかどうかを選べます
機密データが多い社内システムや、見た目を変えてほしくない業務画面がある場合は、0で無効化する判断が考えられます。逆に、読みやすさの調整を標準の機能として配りたい場合は、1でツールバーに固定できます。公式のポリシー文書は、RemixAvailabilityがRemixを無効にしているときは、ほかの関連ポリシーで有効には戻せない、とも記しています。
なお、公式ドキュメントには、次の159以降を対象とする細かいポリシーも載っています。特定のドメインでRemixを禁止する「
RemixDomainBlocklist
」、カスタムのRemix自体を許可するかどうかの「
RemixCustomRemixesAllowed
」、カスタムのRemixによる画像やリンクなどの一括抽出を許可するかどうかの「
RemixBulkExtractionAllowed
」です。158の時点で使える中心のスイッチは、RemixAvailabilityです。
詐欺・悪性サイトからの通知を自動で止めます
158では、悪意のあるウェブ通知への対策も強化されています。通知の先が、Microsoft Defender SmartScreenによって詐欺、フィッシング、マルウェアのページと判断された場合、Edgeはその通知元からの以降の通知を自動で止め、利用者にも知らせます。止めたサイトの確認や再開は、
edge://settings/privacy/sitePermissions/allPermissions/notifications
 からいつでもできます。
ブラウザの通知許可を、いつの間にかオンにしていたサイトから、偽の警告や口座情報を求める画面へ誘導される、といった被害を減らすための機能です。自動で止まった通知元を、業務で使う正規のサイトだと確認できた場合は、同じ設定画面から戻せます。
Windowsでは、設定からいつでもGoogleアカウントのデータを取り込めます
Windows版では、パスワード、ブックマーク、履歴、オートフィルのデータを、Edgeの設定画面から、セットアップ後の任意の時点でGoogleアカウントから取り込めるようになりました。これまでは、初回セットアップのときに限られていました。今回の更新で、Google Chromeからの取り込みと、Googleアカウントからの取り込みが、設定の一つの入り口にまとまります。公式リリースノートは、この機能の対象をWindowsデバイスとしています。macOSやモバイルでの可否は、158のリリースノートには書かれていません。
ワークスペースの切り替え、ピン留め、絵文字
仕事用と調べもの用など、用途ごとにタブをまとめるワークスペースにも、158で操作が足されています。
ウィンドウ内での切り替え：
ワークスペースごとに別ウィンドウを開かず、今のウィンドウの中で切り替えられます
ピン留め：
よく使うワークスペースをピン留めし、画面上に出し続けられます
絵文字：
ピン留めしたワークスペースに絵文字を付けられます。一覧を読まなくても、クリックして切り替えられます
一方、古い「Workspaces V1」は158で既定オフになり、159で完全に削除されます。Edge 150以降を開いた利用者は、すでにV2へ移っている、と公式は説明しています。159の削除までに移行が終わっていないと、V1のワークスペースにはアクセスできなくなります。V2の機能の詳細は、公式の
Microsoft Edge Workspaces
を参照してください。
サイト運営者が確認したいこと：159でXSLTが既定オフになります
158そのものでは、安定版のブラウザ標準XSLTはまだ既定オンのままです。ただし公式リリースノートは、次の予定を改めて案内しています。
Microsoft Edgeは、ブラウザ標準のXSLT（Extensible Stylesheet Language Transformations）を廃止する方針です
対象は、
XSLTProcessor
 のJavaScript APIと、XSLTスタイルシートを参照するXMLの処理命令です。CSSスタイルシートを参照する処理命令は影響を受けません
157：Canary、Dev、Betaでは、すでに既定オフです
159：安定版でも既定オフになります
サイト運営者にとって分かりやすい影響の一つが、XMLサイトマップです。多くのサイトは、
sitemap.xml
 に 
<?xml-stylesheet type="text/xsl" href="sitemap.xsl"?>
 のような処理命令を付け、ブラウザで開いたときに一覧しやすいHTMLとして見せています。これは、XSLTスタイルシートを参照するXMLの処理命令そのものです。159以降、安定版のEdgeで同じファイルを開くと、これまでどおりの見た目に変換されず、XMLのまま表示される可能性があります。検索エンジンの読み取り（クローラー）は、このブラウザ側の変換とは別の話ですが、人がブラウザでサイトマップを確認する運用や、社内向けのXMLをブラウザで見やすくしているシステムは、影響を確認した方がよい、と公式の仕様から言えます。
公式が管理者とサイト所有者に勧めている対応は、次のとおりです。
XSLTProcessor
 や、XSLTを指定したXMLの処理命令を使っている、社内の重要なアプリや公開サイトを洗い出す
ブラウザ標準のXSLTをオフにした状態で、動きを確かめる
変換を、サーバー側、JavaScript、またはほかの対応済みの方法へ移す
開発ルール、サポート文書、テスト計画を更新し、関係者と利用者に変更を伝える
移行が間に合わない場合の一時策として、管理者はポリシー「
XSLTEnabled
」でXSLTを明示的にオンにできます。未設定なら、ブラウザの既定の動作に従います。サイト所有者は、XSLT廃止のオリジン トライアルに登録し、対象オリジンだけ一時的にオンのままにすることもできます。公式は、このポリシーもオリジン トライアルも一時的で、Microsoft Edge 176で機能しなくなる予定だと明記しています。サードパーティーのポリフィルや拡張機能も案内されています。テナント管理者向けの追加情報は、Microsoft 365管理センターのメッセージ センター（MC1509789）にあります。互換性への影響をまとめた公式ページは、
Site compatibility-impacting changes coming to Microsoft Edge
です。
Edge 158の主な変更点と、サイト運営者・管理者が確認したいこと。公式リリースノートをもとにAB通信が作成。出典：Microsoft Edge Stableチャネル リリースノート（158.0.4370.33）

Remixやワークスペースの追加と同時に、次の機能は役割を終えます。
エクスプレスチェックアウト：

廃止に向かっています。関連ポリシー「PerformanceDetectorEnabled」は非推奨で、164で機能の廃止とポリシーのobsoleteが予定されています

LIFE TOPICS 編集部
当ページのリンクには広告が含まれています。
Microsoftは2026年11月19日（米国時間）、パソコン版「Microsoft Edge」の新しいメジャーバージョン「Edge 158」（158.0.4370.33）を安定版として公開しました。目玉は、表示中のWebページの文字・色・レイアウトを、ボタン操作や「こうしてほしい」という文章の指示で作り変えられる新機能「Remix」です。あわせて、詐欺やフィッシングと判定されたサイトからの通知を自動で止める仕組み、Googleアカウントのデータを設定からいつでも取り込める機能などが加わりました。一方で「Express checkout」は廃止されています。
Edgeは Windows に最初から入っているブラウザなので、ふだん意識せずに使っている人も多いはずです。この記事では、Microsoftの公式リリースノートと Remix の紹介ページをもとに、Remix で何ができるのか、実際の使い方、使えない場面、そして Remix 以外の変更点と更新の手順を順に説明します。

目次
Edge 158で何が変わった？
① 表示中のページを好みの見た目に変える新機能「Remix」が登場（個人用・職場のMicrosoftアカウントでサインインしたパソコン版で利用。提供状況は国・地域で異なる）
② 詐欺・フィッシング・マルウェアと判定されたサイトからの通知を自動で停止し、知らせてくれる
③ Googleアカウントのパスワードやお気に入りを、初回設定のあとでも設定画面から取り込める（Windows版）

新機能「Remix」とは？
Remix は、いま開いているWebページの見た目を、自分のブラウザの中だけで作り変える機能です。Microsoftの紹介ページでは、できることとして大きく3つが挙げられています。
見た目を変える
：フォント、文字の大きさ、色、レイアウトを読みやすく整える
道具を足す
：チェックリスト、タイマー、ワンクリックでコピーできるボタンなどをページに加える
不要なものを隠す
：読むのに邪魔な要素を非表示にする
変更されるのは自分のブラウザでの表示だけで、元のWebサイトや、同じページを見ている他の人の画面には影響しません。作った Remix は保存しておけるので、同じページを開くたびに好みの見た目で読めます。

「外観」と「カスタム」の2種類

詐欺サイトからの通知を自動で停止
Webサイトの「通知を許可しますか？」に許可を出すと、ブラウザを閉じていてもパソコンの画面の隅にお知らせが届くようになります。この仕組みは、偽の警告で不安をあおって詐欺サイトに誘導する手口にも使われてきました。Edge 158 では、通知から開いたページが Microsoft Defender SmartScreen によって詐欺・フィッシング・マルウェアのページと判定された場合、そのサイトからの以後の通知を自動で止め、止めたことを利用者に知らせます。
止められたサイトの一覧は、アドレスバーに 
edge://settings/privacy/sitePermissions/allPermissions/notifications
 と入力すると確認でき、誤って止められた場合は元に戻せます。ついでに、身に覚えのないサイトに通知を許可していないかも見直しておきましょう。
Googleアカウントのデータをいつでも取り込める（Windows版）
これまで Google アカウントのパスワード、ブックマーク（お気に入り）、履歴、自動入力のデータを Edge に取り込めるのは、初めて起動したときの設定だけでした。Edge 158 では、Windows版に限り、設定画面からいつでも取り込めるようになりました。Chrome から乗り換えたいけれど、最初の設定で取り込みを飛ばしてしまった、という人に便利です。
ワークスペースの使い勝手が向上
作業ごとにタブをまとめる「ワークスペース」は、別のウィンドウを開かずに、いまのウィンドウの中で切り替えられるようになりました。よく使うワークスペースはピン留めでき、ピン留めしたものには絵文字を付けて見分けやすくできます。なお、古い方式のワークスペース（V1）は Edge 158 で既定で無効になり、Edge 159 で完全に削除されます。Edge 150 以降を一度でも起動していれば新しい方式（V2）に移行済みですが、長く起動していないパソコンがあれば早めに開いておくと安心です。
Express checkout は廃止、XSLT は次のバージョンで無効に
通販サイトの支払いを手早く済ませる「Express checkout」は廃止され、設定画面の項目もなくなりました。また、XMLファイルを見やすく表示する古い仕組み「XSLT」は、安定版では Edge 159 から既定で無効になります。ふだんWebサイトを見るだけの人にはほとんど影響しませんが、会社の古い業務システムで使われていることがあるため、Microsoftは管理者に移行の準備を呼びかけています。Chrome でも同じ変更がすでに行われています。

よくある質問
Q. Remix は無料で使えますか？
A. Edge の機能として提供されており、使うには個人用の Microsoft アカウントか職場のアカウントでのサインインが必要です。有料プランが必要という案内はありませんが、提供状況は国・地域によって異なります。
Q. Remix で変えた見た目は、ほかの人にも見えますか？
A. 見えません。変わるのは自分のブラウザでの表示だけで、元のWebサイトや他の人の表示はそのままです。
Q. ネットバンキングのページでも使えますか？
A. サインインのページ、支払いのページ、自動入力を使うフォームでは動作しないと案内されています。InPrivate ウィンドウやゲスト ウィンドウでも使えません。
Q. スマホ版の Edge でも使えますか？
A. 公式の案内ではパソコン版の Edge が対象です。スマホ版での提供は発表されていません。

Microsoft Edge 158 reached the Stable channel on November 19, 2026. Edge now stops a website from sending you more notifications once one of its pop-ups leads you to a page that Microsoft flags as dangerous, such as a phishing or scam page.
The update also adds Google account imports from Settings and new ways to work with Workspaces.
Fake browser alerts are one of the most common ways scammers reach people. A site gets permission to send notifications, then floods your screen with fake virus warnings or prize offers. Edge 158 aims to break that loop without you having to dig through settings.
At a Glance
Edge 158 (version 158.0.4370.33) shipped to Stable on November 19.
Sites whose notifications lead to blocked scam pages lose notification rights.
Google passwords, bookmarks, history and autofill can be imported from Settings.
Express checkout is gone, and Workspaces V1 is turned off by default.
How the Scam Notification Block Works
Microsoft says the feature relies on Microsoft Defender SmartScreen, the reputation check already built into Edge. If you click a website notification and SmartScreen blocks the page it opens as a phishing, malware or scam site, Edge automatically unsubscribes you from that sender. No more pop-ups arrive from that source.
Edge also tells you that it took this step, so a site does not just go quiet without explanation. If you think Edge got it wrong, you can review the blocked sites and turn their notifications back on. The list lives under site permissions for notifications in Edge’s privacy settings.
Import From Your Google Account Whenever You Want
Until now, Edge only offered a Google import while you first set up the browser. If you skipped that step, there was no simple way back. With version 158, the option sits in Edge Settings and works at any time.
You can bring over saved passwords, bookmarks, browsing history and autofill entries. Microsoft says Chrome imports and Google account imports now share one entry point in Settings. This option is listed for Windows devices.
Workspaces Changes and Retired Features
Workspaces, the Edge feature that groups tabs for a project, gets three upgrades. You can now switch between workspaces inside your current window instead of opening a new one for each. You can pin the workspaces you use most, and you can give each pinned workspace an emoji so it is easy to spot.
In this release Microsoft switches off Workspaces V1 unless it is turned back on, and it plans to remove V1 completely in Edge 159. Anyone who launched version 150 or newer was already moved to the newer version, but anyone who has not migrated will lose access to old V1 workspaces.
Express checkout, a shopping feature tied to Edge’s wallet, has also been retired and its settings entry removed. The release also includes Remix, which lets you change how supported pages look with built-in controls or plain-language requests, with changes kept to your own profile.

What This Means for You
If you use Edge, the scam notification block works in the background, so you do not need to turn anything on. It only reacts after SmartScreen flags a page, though, so it will not catch every shady site. The best defense is still to say no when a site you do not know asks to send notifications.
It is worth opening the notifications list in your Edge site permissions once in a while. Remove any site you do not recognize.
If you keep important tabs in old Workspaces, open Edge and make sure they have moved over before version 159 arrives. Strong, unique logins help too, and a 
free password generator
 makes them easy to create.
How to Get Edge 158
Edge updates itself, but you can speed things up. Open the menu, go to Settings, then About Microsoft Edge, and let the browser check for updates. Restart when asked.
The release also ships the latest security fixes for the Stable channel, so updating soon is a good idea. You can read about the last update in our story on 
Microsoft Edge 157 changes
.
Conclusion
Edge 158 is a practical update rather than a flashy one. Its new block on scam site notifications closes a common path to fake alerts, the Google import option fixes a setup gap, and Workspaces becomes easier to use. Update the browser, check your notification permissions, and move any old workspaces before Edge 159 removes them.

Retiring legacy sign-in implementation on Windows
. Microsoft Edge plans to retire its legacy direct-WAM sign-in implementation on Windows in version 157, completing the transition to OneAuth. OneAuth continues to use Windows Web Account Manager (WAM) internally; WAM itself is not being deprecated.
The vast majority of users have already transitioned automatically with no interruption. For remaining profiles that have not yet migrated, the transition will complete upon updating to version 157. In rare cases, some users may need to sign in to Microsoft Edge again.
Action recommended for administrators:
Check 
edge://signin-internals
 under Edge Auth Library Information → Library to see if any managed profiles still show WAM.
Organizations wishing to validate early or test profiles that previously disabled the transition can launch 
msedge.exe --enable-features=msForceOneAuthWAM
. Close all Microsoft Edge processes, including background processes, because the flag does not take effect if Microsoft Edge is already running.
Report any sign-in issues to Microsoft Support prior to the Microsoft Edge 157 release.
Update allow lists to *.cloud.microsoft before the Copilot URL redirect
. Review your organization's allow/block list configurations for Microsoft 365 Copilot Chat in Edge. Tenant admins can find additional details in the Message Center section of the Microsoft 365 Admin Center under MC1462915.
Microsoft Edge is deprecating browser-native Extensible Stylesheet Language Transformations (XSLT)
. Microsoft Edge will disable the 
XSLTProcessor
 JavaScript API and XML processing instructions that reference XSLT stylesheets by default. XML processing instructions that reference CSS stylesheets are not affected.
Rollout timeline
Microsoft Edge 157:
 Browser-native XSLT will be off by default in the Canary, Dev, and Beta channels.
Microsoft Edge 159:
 Browser-native XSLT will be off by default in the Stable channel.
The existing 
XSLTEnabled
 policy can explicitly enable or disable XSLT regardless of the browser default. If the policy is not configured, XSLT follows the browser default behavior. Site owners can temporarily use the 
XSLT deprecation origin trial
 to keep browser-native XSLT enabled for a registered origin. Both mitigations are temporary and are planned to stop functioning in Microsoft Edge 176.
Action recommended for administrators:
Identify internal and business-critical applications that use the 
XSLTProcessor
 JavaScript API or XML processing instructions that reference XSLT stylesheets.
Test affected applications with browser-native XSLT disabled.
Migrate browser-side transformations to server-side transformation, JavaScript-based transformation, or another supported implementation.
Update internal development guidance, support documentation, and test plans.
Inform application owners, helpdesk teams, and affected users about application-specific changes.
If migration cannot be completed before the deadline, administrators can temporarily enable the 
XSLTEnabled
 policy. Third-party polyfills and browser extensions are also available.
Tenant admins can find additional details in the Message Center section of the Microsoft 365 Admin Center under MC1509789.

Feature Updates
Improvements to site permissions user interfaces
. Site permissions are changing to better align with user expectations. They now look and work consistently both on websites that request permissions and in Settings. On a website that is requesting permissions, there are changes to the Omnibox and the Page Info dialog, and permissions are easier to see and modify in Settings.
Enhanced Autofill
. For desktop users, Microsoft Edge can now autofill additional document types—including passports, driver's licenses, and other specialized forms—on top of your saved addresses.
Enhanced Key Icon with Credential Details, Copy Actions, and Notes
. The key icon in Edge's address bar now lets users select any saved credential to view a detailed panel. From there, users can copy a username, reveal and copy a password, and add personal notes to each login. Keep track of security questions, account purpose, or recovery details alongside credentials without opening Settings or the full password manager.
Autolaunch opt-in experience for managed devices
. Microsoft Edge will introduce an opt-in experience that allows users on managed devices to choose whether Edge launches automatically when Windows starts. Administrators can also manage this behavior through the 
LaunchEdgeOnWindowsStartupEnabled
 policy with opt-in, opt-out, and user-choice configurations. 
Note:
 This is a controlled feature rollout. If you don't see this change, check back as we continue the rollout.
PDF Viewer NewPDFReaderEnabled Enterprise Policy Deprecation
. As part of the transition to the new PDF viewer experience, Microsoft Edge version 156 marks the 
NewPDFReaderEnabled
 enterprise policy as deprecated. The policy becomes obsolete at the earliest with Microsoft Edge version 162. For more information, refer to the 
FAQ
.
