脆弱性の発見、修正、検証におけるAIの活用
脆弱性の報告は、外部の研究者やパートナーに加え、Microsoft社内のエンジニアリングチームやセキュリティチームからも寄せられる。報告の受付、更新情報の提供、連携した対応の中心となるのがMicrosoft Security Response Centerだ。エージェント型コードスキャナーのMDASHは、複数のAIモデルと専門エージェントを使って脆弱性の候補を特定・検証し、その後、セキュリティチームとエンジニアリングチームが調査結果を確認し、対応方法を決定する。
Microsoftの
Codename MDASHのプレビュー版ドキュメント
によると、このパイプラインは4段階で構成される。まず、コールグラフ解析とコード複雑度の指標を使ってファイルに優先順位を付け、次に、優先度の高いコードを100を超える専門エージェントと複数の大規模言語モデルでスキャンする。検証では、汚染解析、型解決、複数モデルによる議論を通じて信頼度を調整し、誤検知を排除したうえで、重複する調査結果を統合する。スキャナーは信頼度スコアも割り当て、Defender CLIを通じてコード修正を生成することもできる。
修正支援の対象は、影響の評価、影響を受けるWindowsのバージョンと関連するコードの派生形の特定、修正方法の検討、バックポートの計画、セキュリティテストと回帰テストの作成にまで及ぶ。作業内容の確認、意思決定、最終成果物への責任は、引き続きエンジニアが担う。リリースの検証では、社内での段階的な試験提供、機能面とセキュリティ面の概念実証テスト、アプリケーション互換性テストに加え、ハードウェアパートナー、セキュリティベンダー、ソフトウェアベンダー、顧客による外部検証も行う。AIは、テストの選定、作成、トリアージ、分析、報告も支援する。
任意で適用できるセキュリティ以外のプレビュー更新プログラムも、確認の機会となる。組織は、その内容が翌月のセキュリティ更新プログラムに含まれる前に、選択したデバイスへインストールできる。
修正件数の増加と、脆弱性悪用の開発期間の短縮
Microsoftは、10月の件数増加は、Windowsのセキュリティ低下ではなく、調査対象となったコードと修正された脆弱性が増えたことを示すものだとしている。同社はSecurity Update Guideを通じて、深刻度、影響、悪用可能性に関する情報を公開している。さらに、機械可読形式のCommon Security Advisory Framework勧告、Vulnerability Exploitability eXchange文書、脆弱性管理・コンプライアンスシステム向けAPIも提供している。Windowsのセキュリティ更新プログラムは累積的であるため、優先順位を決める際は、個々の修正プログラムの適用対象を選ぶのではなく、インターネットに接続するシステム、ID基盤、価値の高い資産から順に、どのデバイスを先に更新するかを判断すべきだ。
緊急性の理由は、公開後に何が起きるかにある。修正プログラムが公開されると、根本にある脆弱性の情報が明らかになり、攻撃者が悪用方法を開発する材料となる可能性がある。

Microsoftは、サポート対象のWindowsバージョンの使用、速やかな更新、セキュリティベースライン、エンドポイント検出、利用可能な緩和策、インシデント対応と復旧の実践を推奨している。Windows AutopatchはIntuneを通じて段階的な展開とレポート機能を提供し、対象となるWindows 11およびWindows Server 2025のシステムでは、ホットパッチにより再起動を減らせる。リリース後は、自動化システムが診断、展開、サポート、フィードバックに関するシグナルの相関分析を支援する。エンジニアは、ガイダンスの改訂、回避策、Known Issue Rollback、帯域外更新プログラムで対応できる。

Microsoft is putting AI into every stage of Windows vulnerability management
 – finding bugs earlier, helping engineers remediate them, validating fixes at scale, and pushing organizations to deploy patches faster. The company says AI helps defenders and attackers alike, so the time between a published fix and a patched device now matters more than ever.
The update comes from 
Nuno Costa
, Partner Director for Windows Servicing and Delivery, on the Windows Experience Blog (November 5, 2026). It covers discovery through MDASH, AI-assisted remediation, validation, transparency, and the practical tools IT teams can use on Windows 11/10 and Windows Server.

Finding and fixing vulnerabilities with AI
Microsoft still receives disclosures from researchers and partners, and its own security and engineering teams find issues internally. Those paths meet at the 
Microsoft Security Response Center (MSRC)
.
AI is now a larger part of that pipeline. One example is 
MDASH
, an agentic code scanner that uses multiple AI models and specialized agents to find and validate potential vulnerabilities. Humans still review the findings and decide what to do. The goal is earlier, more actionable discoveries – not a raw flood of false positives.
The same idea applies to remediation. AI helps engineers assess impact, map affected Windows versions, spot variants in related code, plan backports, and build security and regression tests. Engineers keep ownership of the final decisions and output.

Validation, then transparent Patch Tuesday
More discoveries need stronger validation. Windows still combines internal flighting, functional testing, security proof-of-concept tests, app compatibility checks, and the 
Security Update Validation Program (SUVP)
 with OEMs, security vendors, ISVs and customers. AI assists with test selection, test creation, triage, analysis and reporting.
Optional non-security preview updates remain part of the path. Organizations can put those builds on selected devices before the same content lands in the next month’s security update, giving Microsoft more real-world signal across hardware, apps and configurations.
The October 2026 monthly security update addressed 
more than 1,100 CVEs
 for Windows. Microsoft is clear that a higher CVE count does not mean Windows is less secure. It means more issues were found – by AI, by researchers, and by internal teams – and closed. Details ship in the Security Update Guide and in machine-readable 
CSAF
, 
VEX
 and API feeds so security tools can track what each device still needs.
Why speed matters after Patch Tuesday
Once a fix is public, attackers can analyze it. Microsoft cites Anthropic research showing large language models can help develop N-day exploits in hours, not days. That turns slow patch rollout into a measurable exposure window.

fewer than half

one in four
 still had not after four weeks. Microsoft cannot finish the lifecycle alone: protection only counts once it is on the device.

Stay on supported versions
 of Windows and Windows Server, and install security updates promptly after release.

A new standard for vulnerability management in the AI era
							Written By
								Nuno Costa
																	– 
Partner Director, Windows Servicing and Delivery
							published
							November 5, 2026
Windows is evolving vulnerability management as advances in AI make it possible to discover and analyze security vulnerabilities faster and at greater scale.
AI is accelerating vulnerability discovery on both sides. It can help defenders find and fix vulnerabilities earlier. It can also help attackers search for vulnerabilities before fixes are available and analyze published fixes after release. All of this increases the importance of timely protection.
Our approach is straightforward: lead across the vulnerability management lifecycle. We’re using advances in AI to find and fix vulnerabilities earlier, while maintaining a high-quality bar so you and your organization can deploy updates with confidence. We’re promptly publishing information about what we fix so security teams can take action. Just as importantly, we’re strengthening the systems that help organizations deploy updates quickly and respond when issues arise.
Since our 
last communication on this topic
, we have continued to advance this work across vulnerability discovery, remediation, validation, and deployment.
Finding vulnerabilities earlier
Identifying vulnerabilities before they can be exploited remains the best opportunity to reduce exposure. Microsoft receives vulnerability findings through responsible disclosure from security researchers and partners, while our engineering and security teams find issues internally. These paths come together through the 
Microsoft Security Response Center
 (MSRC), which serves as Microsoft’s central hub for vulnerability reporting, security updates and coordinated response.
We are increasingly using AI to help security and engineering teams identify vulnerabilities and act on them more efficiently. One example is 
MDASH
, an agentic code scanner that uses multiple AI models and specialized agents to find and validate potential vulnerabilities. Security and engineering teams then review the findings and determine the appropriate response, keeping human judgment and accountability central to the process.
The objective is not simply to find more issues. The goal is to identify meaningful vulnerabilities earlier and make the findings more actionable. By using AI-assisted capabilities, we can distinguish relevant findings from false positives. We can give our engineers better information. As vulnerability discovery accelerates, these capabilities help us focus engineering resources on vulnerabilities that have the potential to affect customers more efficiently.
Moving from discovery to remediation faster
Finding vulnerabilities more quickly only helps if engineering processes can keep pace. We are applying AI assistance across the remediation process to help engineers assess impact, determine which versions of Windows are affected, identify variants in related code, evaluate remediation options, develop backport strategies for different versions of Windows, and build security and regression tests. Engineers remain responsible for reviewing the work, making the engineering decisions, and owning the final output. This distinction matters. Our goal is to use automation and AI to help engineers investigate and remediate issues more efficiently, not to remove engineering judgment from security decisions.
Strengthening validation
Increased discovery and remediation also require validation systems that can operate at greater scale. Windows validation combines multiple sources of evidence. Today, it’s internal flighting, functional testing, security proof-of-concept testing, application compatibility testing, and validation with OEMs, security vendors, ISVs, and customers through the Security Update Validation Program. We also apply AI-assisted capabilities to areas including test selection, test creation, triage, analysis, and reporting. Together, those signals provide evidence for engineers making release-quality decisions.
Optional non-security preview updates
 remain an important part of this process. Organizations can install these updates on select devices before the content becomes part of the following month’s security update, providing additional real-world validation across devices, applications, hardware and configurations.
Making vulnerability discovery actionable
AI-assisted discovery is helping us find more vulnerabilities, across more code and earlier in the development process, so we can address more of them through Windows security updates. In fact, the October 2026 monthly security update addressed more than 1,100 Common Vulnerabilities and Exposures (CVEs) for Windows.
The number of CVEs doesn’t tell the full story, though. We are using AI to examine more code, more deeply. The research community continues to find and report vulnerabilities. And we are prioritizing fixes in real time as vulnerabilities are identified. A higher number of CVEs does not mean Windows has become less secure. It means more vulnerabilities have been discovered and closed, reducing the opportunities attackers have to exploit them.
Transparency makes those fixes more actionable. We publish CVE information for the vulnerabilities we address, whether they are reported by external researchers or identified by our own teams and AI systems. The 
Security Update Guide
 provides details on severity, impact, exploitability, and guidance for each CVE. We also make this data available in machine-readable formats, including Common Security Advisory Framework (CSAF) advisories, Vulnerability Exploitability eXchange (VEX) documents, and API, so it can flow straight into your vulnerability management and compliance tools.
Security teams can use CVE information to:
Track which vulnerabilities are addressed on each device.
Prioritize which devices receive updates first based on exposure, starting with internet-facing systems, identity infrastructure, and high-value assets.
Measure protection in days from release, not in patch cycles.
Because Windows security updates are cumulative, prioritization should decide which devices update first, not which fixes get deployed.
When protection becomes available, the clock starts
On Patch Tuesday, Microsoft releases monthly security updates and the 
information and resources
 you need to evaluate and deploy them. This includes release notes, vulnerability information (available in the 
Security Update Guide
), cumulative updates (through Windows Update and other deployment channels), and updated servicing media.
Releasing an update changes what information is publicly available. Before an update is released, vulnerabilities are triaged through coordinated disclosure. Once the update and associated guidance become public, the fix itself can be analyzed. That means attackers might be able to use a published fix to better understand the underlying vulnerability and develop an exploit—potentially within hours.
That’s why our work doesn’t stop when an update is released. We monitor diagnostic data and rollout reporting, customer support and inquiries, and feedback from social channels and forums. Automated systems help us correlate those signals and identify patterns for engineering investigation. Engineers investigate potential issues, validate their cause, and determine the appropriate response. Depending on the cause and impact, that response can include updated documentation or guidance, a workaround, 
Known Issue Rollback (KIR)
 to mitigate an affected change, or an 
out-of-band update
.
This is the lifecycle in practice: discover vulnerabilities earlier, develop and validate protections, publish them transparently, monitor their performance after release, and respond quickly when needed. But there is one part of that lifecycle Microsoft cannot complete alone: getting those protections onto devices.
Reducing your exposure window
Microsoft engineering systems are one half of the equation. Deployment is the other.
The time between an update becoming available and reaching your devices is part of your security posture. A recent article by Anthropic
1
 noted that N-day exploits (the time between when vulnerabilities are disclosed but only patched on some devices) is a “patch gap”, as large language models now accelerate developing N-day exploits in hours not days as in the past. This has created a heightened risk threat for devices in the “patch gap”.
Yet some organizations still take weeks to deploy updates. 
Diagnostic data
 from August 2026 showed that, among a measured Windows enterprise sample, fewer than half of devices had installed the security update two weeks after release, and about one in four still had not installed the update after four weeks. That gap between available protection and deployed protection is the exposure window we need to close.
We are seeing organizations move in the right direction, accelerating rollout, moving to supported versions of Windows, and adopting newer update management and servicing capabilities. But 
faster deployment
 needs to become the standard, not the exception.
Organizations should focus on four practical areas: 
Stay on supported versions and install updates promptly after they are released.
Reduce unnecessary exposure and use 
security baselines
 to implement well-tested, industry-proven configurations.
Maintain endpoint detection and apply available mitigations.
Establish effective response and recovery practices.
Of those, staying current is foundational. Shortening the time between when Microsoft publishes a fix and when devices receive it reduces how long a known vulnerability remains unpatched. Newer, supported versions of Windows and modern management tools provide capabilities designed to make updating faster and less disruptive.
For Windows 11, Windows Autopatch provides update management through Microsoft Intune, including staged deployments and reporting. For eligible devices, hotpatching can apply monthly security updates without a restart, while standard cumulative baseline updates are required periodically.
Hotpatching
 also provides a path to faster protection for Windows Server while reducing restart requirements. Windows Server 2025 supports hotpatch updates
2
 across eligible Azure, Azure Local, and Azure Arc-connected environments, with Azure Update Manager providing patch orchestration.
Organizations running older supported versions of Windows client or Windows Server should continue to keep those environments current and use the update management capabilities available to them. Where extended security updates are necessary, treat them as a bridge while moving to a supported version, not as a substitute for modernization.
The goal is simple: turn an available fix into deployed protection as quickly as possible. Reduce the update deployment window wherever possible instead of treating security updates as a task that can routinely wait.
Leading at the pace of change
AI is changing the pace of vulnerability management. It gives defenders new ways to find vulnerabilities, analyze code, and develop protections. At the same time, it can shorten the time between public disclosure and potential exploitation.
At Microsoft, our commitment is to stay ahead of that change. We are expanding AI-assisted vulnerability discovery, helping engineers move more efficiently from validated findings to fixes, strengthening validation, and monitoring updates after release. We are also investing in the tools and servicing capabilities that help organizations deploy protection faster. As we apply AI across this lifecycle, human judgment and accountability remain fundamental to how we build and service Windows.
Our request of every organization is to 
move with urgency
. Stay on supported versions, maintain layered protections, monitor security guidance, and make reducing the time from release to deployment a security priority.
Vulnerability management will continue to evolve as AI advances. We intend to lead that evolution, share what we learn along the way, and give customers the information and tools they need to act. But protection ultimately depends on both sides moving quickly: our ability to find, fix, validate, and publish protections, and your ability to deploy them.
