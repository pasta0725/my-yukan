画像：AIエージェントナビ編集部
資料を読み込ませて調べものをするGoogleのAIツール「Gemini Notebook」（7月にNotebookLMから改称）を、AIエージェントから直接使いたいという声は多くありました。Googleは、Gemini Notebookをプログラムから操作できるAPIと、AIエージェントをつなぐ公式のMCPサーバーを、正式提供前の試験版（Public Preview）として開発者向けに公開しました。
本記事では、今の試験版でできること・まだできないこと、使うための条件を解説します。
Gemini Notebook APIでできること
Gemini Notebook APIは、ノートブック（資料をまとめる単位）と、そこに入れる資料（ソース）をプログラムから作成・管理するための仕組みです。資料として追加できるのは、公開されているWebページ、YouTube動画、貼り付けたテキスト、Markdown形式の文章の4種類です。
APIとMCPサーバーで使える操作は、次の7つです。
ノートブックの作成・取得・一覧表示・名前などの更新
資料（ソース）の追加・取得・一覧表示
資料の取り込みは時間差で進むため、追加したあとに状態を確かめ、「ACTIVE（使える状態）」になるのを待つ流れになります。
公式MCPサーバーでAIエージェントから操作
MCP（Model Context Protocol）は、AIエージェントと外部のツールをつなぐための共通の決まりごとです。Googleは公式のMCPサーバーを用意しており、Claude CodeやCursorなどのAIエージェントに登録すると、会話の中からノートブックを作ったり資料を追加したりできます。
設定の指示文も公式に用意
Googleの説明ページには、Claude CodeやCursorに貼り付けると、Google Cloudの準備からログイン、MCPサーバーの登録までを進めさせる指示文が載っています。Claude Codeの場合は、コマンド1行でMCPサーバーを登録する方法も示されています。ただし、ログインで発行される鍵（アクセストークン）は1時間で切れるため、切れたら取り直す必要があります。
まだできないことと利用の条件
今の試験版では、ノートブックに質問して答えを受け取ることはできません。AIエージェントからGemini Notebookの要約や回答を引き出す使い方はまだできず、資料をそろえる作業までが対象です。
質問やPDFの追加は「今後の予定」
Googleが公開している予定表（ロードマップ）には、ノートブックからの情報の取り出し、成果物の生成、PDFなどのファイルのアップロード、ノートブックや資料の削除、Googleドライブの資料の追加、Google Workspaceアカウントへの対応が並んでいます。予定表は変わる可能性があると明記されており、時期も示されていません。
個人のGoogleアカウントだけが対象
試験期間中に使えるのは個人のGoogleアカウントだけで、Google Workspaceのアカウントでは使えません。また、使う前にそのアカウントでGemini Notebookに一度ログインしておく必要があり、Google Cloudのプロジェクトも必要です。説明ページによると、Workspaceのアカウントで呼び出すと「403」の拒否エラー、一度もログインしていないアカウントではノートブックの作成が「404」エラーで失敗します。
まとめ
GoogleがGemini Notebook（旧NotebookLM）のAPIとMCPサーバーを試験版として公開。
ノートブックの作成・管理と、Webページ・YouTube動画・テキスト・Markdownの資料追加ができる。
ノートブックへの質問、PDFの追加、削除はまだできず、予定表に載っている段階。
使えるのは個人のGoogleアカウントだけで、Google Workspaceのアカウントは対象外。
💡 編集部の見解
当メディアが1月に紹介したNotebookLMとAIエージェントをつなぐ方法は、非公式の道具が頼りでした。今回はGoogle公式の接続口ができましたが、できるのは資料を集める作業までで、ノートへの質問はまだできません。
非公式の道具との違い
：1月の記事で紹介した非公式の道具は、ブラウザのログイン情報を使い、2〜4週間ごとに切れるものでした。公式版はGoogle Cloudの正式なログインで動き、Googleの説明ページに設定手順も載っています。
会社のアカウントでは拒否される
：試験期間中は、会社や学校で配られるGoogleアカウントで呼び出すと「403」の拒否エラーが返ります。普段は会社のアカウントで使っている人は、個人のアカウントで試すことになります。

Google ships Gemini Notebook API in public preview: REST and MCP server, source ingestion only
TL;DR
Google has released a public-preview REST API and MCP server for Gemini Notebook (formerly NotebookLM) that work with personal Google accounts. They can create notebooks and add web, YouTube, text and Markdown sources, but cannot yet query notebooks or generate outputs.

Google has published a public-preview (pre-GA) REST API and an MCP server for Gemini Notebook, the product formerly called NotebookLM, for use with personal Google accounts. According to Japanese-language outlet @IT (Deep Insider Brief), which tested it hands-on, the API automates adding sources such as web pages and YouTube videos, but cannot yet ask questions of a notebook or generate outputs.
The source reports that Gemini Notebook was renamed from NotebookLM in July 2026. Before this release, individuals had no official API. Programmatic access required either the paid Enterprise API or browser-automation tools. Google's documentation was updated between October 29 and November 2, and @IT infers the release timing from those dates. Google has also published a roadmap with planned features.
What the API can do
Notebooks:
 create, list, get and rename.
Sources:
 add four types: web page URL, YouTube video URL, pasted text and Markdown text.
Ingestion status:
 ingestion is asynchronous. A source moves through PROCESSING, ACTIVE or FAILED, and the client polls until it is ready.
Authentication:
 OAuth 2.0 with the scope 
https://www.googleapis.com/auth/notebook
. A standard 
gcloud
 login token does not include this scope, so calls fail without it.
Samples:
 Python, JavaScript and curl examples are in the documentation.
Shortened YouTube URLs (youtu.be) are normalized by the API to the 
www.youtube.com/watch?v=
 form.
MCP server
The MCP endpoint is 
https://notebook.googleapis.com/mcp
, using Streamable HTTP (JSON-RPC 2.0). It exposes seven tools: 
create_notebook
, 
get_notebook
, 
list_notebooks
, 
update_notebook
, 
create_source
, 
get_source
 and 
list_sources
.
Requests carry two headers: an 
Authorization: Bearer
 OAuth token and 
x-goog-user-project
 with a Google Cloud project ID. Tokens expire after one hour and must be reissued. The documentation includes a prompt to hand to a coding agent, which automates project selection, API enablement, scoped authentication and MCP server registration.
Hands-on results
The @IT writer passed that prompt to Codex and added three YouTube videos to a notebook through MCP. Each reached ACTIVE in 4 to 6 seconds. A web page took about 9 seconds and Markdown text about 6 seconds. These timings are client-side observations that include tool-call intervals and network time. The sources displayed in the browser with titles, thumbnails and links, as if added manually.
Not yet supported
Querying a notebook and retrieving answers
Generating outputs such as video or audio overviews
Deleting notebooks or sources (returns HTTP 501 Not Implemented)
Uploading binary files such as PDFs
Google Drive or Google Docs URLs as sources (returns an error)
Google Workspace accounts (returns HTTP 403 Forbidden)
Google lists these as planned on its roadmap, which @IT describes as short, about six items, with no order or timing. Google states the roadmap is informational and may change.
Prerequisites and caveats
Users must sign in once to notebook.google.com beforehand, or calls return HTTP 404. A Google Cloud project and the 
gcloud
 CLI are required, and notebook and per-source word limits apply. As a pre-GA release, support is limited and incompatible changes are possible. This is separate from the paid Gemini Notebook Enterprise API.
What this means
For individual users, source ingestion can now be scripted or delegated to an MCP-capable agent without browser automation. @IT's author argues that fixed API calls are easier to constrain than an agent driving a browser UI, so the scope of delegated operations is narrower and safer. The missing query and generation endpoints mean end-to-end pipelines still need manual steps in the browser. @IT's author says he hopes the API coverage widens.
