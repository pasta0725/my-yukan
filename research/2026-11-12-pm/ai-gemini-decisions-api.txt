Today, we’re introducing the Gemini Decisions API, a new endpoint for fast, closed-set decisions powered by our new Gemini Decision 1 model (gemini-decision-1), available through the 
Gemini API
 in 
Google AI Studio
.
The Decisions API gives you purpose-built primitives for bounded choices like tool selection, policy checks, model routing, and context grading. You can pass one multimodal input across text, images, audio, video, and PDFs (up to 256K tokens) along with up to 1,000 independent questions. Rather than generating answer text token by token, Gemini Decision 1 scores your candidate options in a single forward pass, returning probabilities and confidence scores in 150-250 ms end-to-end latency at $0.10 per 1M input tokens with zero output tokens billed.
Strong performance and calibration
On benchmarks spanning agent routing, reasoning, ranking, and multimodal understanding, Gemini Decision 1 leads across the suite, with the lowest calibration error.
Gemini Decision 1 scores options without token-by-token decoding, keeping median latency 50-100 ms of model compute (150-250 ms end-to-end), across multimodal inputs and contexts up to 16K tokens, remaining nearly flat from 1 to 100 questions per request. With zero output tokens billed, Gemini Decision 1 with the Decisions API is nearly 5x cheaper across the shared benchmark suite than Gemini 3.5 Flash-Lite with the Interactions API.
Native multimodal evaluation across three decision types in one pass
Built on Gemini’s native multimodal architecture, Gemini Decision 1 can process text, images, audio, video, and PDFs directly in a single forward pass. You can combine modalities in one shared input, such as pairing a call recording with account metadata or a scanned PDF claim with damage photos, and tune resolution on image and video inputs to control visual detail and token cost.
You can evaluate multiple questions against that shared input in a single request, mixing yes/no checks, multiple choice, and rubric scores. Every answer includes a confidence score (from 0 to 1) so your code can route ambiguous cases to a fallback or human reviewer:
noul (Yes/No):
 Estimates the probability that a yes/no condition holds, with optional true and false description criteria.
choice (Multiple Choice):
 Selects from 2 to 255 choices, returning the winner and normalized probabilities for every candidate.
score (Ordered Rubric):
 Grades inputs across an ordered rubric (starting at 0), returning a continuous weighted score and per-level probabilities.

Interactions API

How teams are building with the Decisions API
Teams across Google are already using the Decisions API as a low-latency control plane, shipping features simply by defining options rather than training custom classifiers or waiting on generative calls:
Dynamic model routing in Gemini Notebook:
 Gemini Notebook uses the Decisions API as a real-time router to instantly direct incoming queries to the optimal model tier and thinking level for each request. The Decisions API classifies intent in milliseconds to serve everyday queries with up to 40% lower latency while reserving deep reasoning models for complex tasks.
Rapid design iteration in Stitch:
 The new 
rapid canvas experiment in Stitch
 uses the Decisions API to generate playable wireframes of a product flow in seconds and to apply edits made by voice or tap almost instantly. When the flow feels right, one click hands the screens off to the full Stitch experience for deeper design polish.
Emoji selection in CC:
 CC from Google Labs uses the Decisions API to pick the right emoji reaction from a palette of more than 200 options in a fraction of a second, so reactions appear instantly without adding latency.
Safety layer for MCP tools in Search
: Google Search uses the Decision API to detect adversarial behavior and content against adversarial evals with high efficacy within the latency envelope.
Stitch Rapid uses the Decisions API to design an entire product flow in seconds (1x speed).

Google DeepMind、確率と確信度だけを返す判定用AI「Gemini Decision 1」を公開

執筆: 
AI産業通信 編集部
　公開: 2026年11月12日 08:29　更新: 2026年11月12日 10:48
Google DeepMind
は2026年11月11日、文章を書かず、写真やメモを渡すと「どの答えに当てはまりそうか」の確率と、その答えへの自信の度合いを示す確信度（0〜1の数字）だけを返すAI「
Gemini Decision 1
」を公開した。問い合わせをどの担当に回すか、社内ルールに違反していないか、休憩室の写真の汚れがどの程度かといった、あらかじめ決めた選択肢から答えを選ぶ判定に使う。開発者向けの「
Gemini API
」に新しい接続口「
Gemini Decisions API
」として加わり、1回のリクエストで最大1,000問をまとめて判定できる。
目次
文章を書かず確率と確信度だけ返すAI
判定専用のAIとは、文章を書かず、写真やメモを渡すと「各選択肢に当てはまる確率」と「確信度」の数字だけを返すAIのことだ。使い道は、問い合わせの振り分け、ルール違反の判定、書類や写真の審査など、選択肢から選ぶだけの処理である。これまでは、生成AIに文章で答えさせるか、専用の分類用AIを学習させるかの二択だった。Googleは、これを「選択肢を定義するだけ」で済ませる方向を打ち出した。同社はDecisions APIを、分類用AIの学習や文章生成の待ち時間なしに機能を出せる「低遅延のコントロールプレーン（全体の判断を担う司令塔）」と説明している。
ChatGPTのような生成AIは、答えを文章として1語ずつ書き出す。Gemini Decision 1は違い、マークシートの各選択肢に「どれくらい当てはまりそうか」の点数を付けて返すAIだ。Googleによると、回答文を生成せず、候補をまとめて1回の計算で採点する。
この仕組みが、
出力課金ゼロ
の理由になる。AIの利用料は入力と出力の両方にかかるのが一般的だが、このモデルは文章を書き出さないので、出力にあたるものがほぼ生じない。
質問の形式は3種類あり、1回のリクエストに混在させられる。
Yes/No判定：Yes・Noそれぞれの確率を推定する。原文の表記は「noul」だが、説明はYes/No判定の内容になっている
多肢選択（choice）：2〜255個の選択肢から選び、全候補の確率を、合計が1になるよう調整して返す
段階評価（score）：0から始まる順序付きの採点基準で評価し、全体の点数と各段階の確率を返す
入力はテキスト、画像、音声、動画、PDFを1つにまとめて渡せる。上限は
256Kトークン
だ。
それぞれの回答には、0〜1の「確信度」が付く。AIが自分の答えにどれだけ自信を持っているかを示す数字だ。Googleは、確信度が低い曖昧な案件を、別の処理や人間のレビューに回す使い方を想定している。
【編集部の見立て】確信度があれば、自動で処理する案件と人が見る案件の境目を数字で決められる。たとえば「0.9未満は人が確認する」と線を引ける。審査やコンプライアンスのように人の確認が欠かせない業務で意味が出るだろう。ただし、その数字が実際の確からしさと合っているかは、Googleのベンチマーク上の主張にとどまる。自社のデータで確かめる必要がある。
Googleが挙げる用途は、選択肢があらかじめ決まった判定で、業務の言葉にすると次の4つになる。
ツール選択：依頼に対し、どの道具やシステムを使うかを選ぶ
ポリシーチェック：社内ルールや規約に違反していないかを判定する
ルーティング：問い合わせや処理を、どのAIや担当に回すかを振り分ける
コンテキスト採点：渡した情報が、目的にどれだけ役立つかを評価する
Google AI Studio
（ブラウザで使えるGoogleの開発用ツール）でAPIキーを取得すればすぐ試せる。説明資料はPython、JavaScript、RESTの3形式で用意されている。
写真とメモを渡し、最大1,000問をまとめて判定
実際に何を渡すと何が返るのか、公式サンプルで見る。
サンプルはオフィスの休憩室だ。渡すのは休憩室の写真1枚と、状況を書いたテキストのメモ。聞くのは3つで、「液体がこぼれているか」（Yes/No）、「次に何をすべきか」（選択肢）、「汚れはどれくらいひどいか」（段階評価）である。この3問が
1回のリクエスト
で済む。開発者向けの補足をすると、入力欄は既存のInteractions APIと同じ「Contentブロック」という形式だ。
返ってくるのは文章ではない。汚れの段階を「0＝きれい、1＝軽い汚れ、2＝ひどい汚れ」と決めておくと、段階ごとの確率と確信度が数字で返る。「0が10%、1が60%、2が30%」といった具合だ（数字は仕組みを説明するための編集部の例で、公式サンプルの出力ではない）。
写真、音声、動画、PDF、文章をまとめて渡し、そこに最大1,000問を付けられる。
【編集部の見立て】業務に置き換えるなら、コールセンターの通話録音と契約書のPDFをセットで渡し、「解約の意思表示はあるか」「特定の条項はあるか」と聞く場面が想像しやすい。これは編集部が仕組みから考えた例で、Googleが示した導入事例ではない。
価格・速度と、発表された制限
この章では、料金と速度の数字、それぞれの条件、使う側が押さえておくべき制限を見る。
料金は入力100万トークンあたり
0.10ドル
だ。トークンは、AIが文章を処理するときの単位で、文字数に近い量の目安になる。出力にあたるものがほぼ生じないので、費用は何を読ませたかでほぼ決まる。【編集部の試算】1回あたり平均1,000トークンの入力を100万回送ると、入力は10億トークンで、単純計算で
100ドル
になる。質問ごとの指示文や、画像・動画をトークンに換算した分は含めていない目安だ。
Googleは、
Gemini 3.5 Flash-Lite
（Interactions API）とGoogleが選んだ共通ベンチマーク上で比べ、
約5倍安い
としている。実際の費用は入力の量や質問の数で変わる。
質問が増えても遅延は横ばい
結果が返るまでの時間は、Googleによるとエンドツーエンド（リクエストを送ってから結果が戻るまで）で
150〜250ミリ秒
だ。このうちモデルの計算そのものは、中央値で0.05〜0.1秒とされる。
1回のリクエストに付ける質問を1問から100問に増やしても、待ち時間はほぼ一定だとGoogleは説明している。文章を1語ずつ書き出すAIなら質問が増えるほど待ち時間が積み上がるが、このモデルは書き出さないのでそうならないとみられる。ただし、ほぼ一定とされているのは100問までだ。上限の1,000問まで同じかどうかは、発表からは分からない。
Googleはこのモデルを自社でも使っており、Gemini Notebookでは入力された問い合わせを最適なモデルの階層と思考の深さに振り分けるルーターとして使い、日常的な問い合わせの遅延を
最大40%
短縮したと説明している。
発表で示された3つの制限
Googleが制限として列挙したものではなく、記載から読み取れる注意点だ。
判定の範囲が決まっている
：用途は、選択肢が閉じた判定だ。多肢選択の選択肢は2〜255個まで、質問は1リクエストあたり最大1,000問まで。文章で説明を書かせたい用途には向かない。
速度の数値は条件付き
：入力は最大256Kトークンまで受け付ける。一方、遅延の数値は
16Kトークンまで
の条件での測定と記載されている。長い書類や動画で同じ速さが出るかは示されていない。
数字はGoogleによる説明
：エージェントのルーティング、推論、ランキング、マルチモーダル理解のベンチマークで首位、確信度の正確さを示す較正誤差（自信の度合いと実際の正答率のずれ）が最小という点も、Googleによる説明だ。本稿の執筆時点で、第三者の検証や報道は確認できていない。
日本向けの提供条件や、日本語の入力での性能については、発表に記載がない。
【編集部の見立て】3つの条件は、数字が間違っているという意味ではない。Googleの数字が自社の業務データにそのまま当てはまるかは別の話で、自社の書類の長さと質問の数で測れば、実際の費用と速さが見える。
