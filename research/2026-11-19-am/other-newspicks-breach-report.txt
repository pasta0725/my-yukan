① ログイン前の穴から管理者になりすます
CVE-2026-72898 は、パスワード再設定のための窓口（
/api/session/reset_password
）に細工したリクエストを送ると、
ログインせずに Metabase 内部のデータベースへ好きな SQL を実行できてしまう
脆弱性です。ここから管理者の権限を取られます。
ログインの仕組みそのものを飛び越える
ので、多要素認証も権限の絞り込みも同時に効かなくなりました。
② 管理者の API キーでデータを持ち出す
管理者になった攻撃者は、
管理者権限の API キーを作り
、それを使って Metabase がつないでいたデータベースからデータを取り出しました。API キーは画面からのログインと別に使えるため、
本体を更新した後も、キーを消すまで出入りできる
状態が続きました。
③ 気づくまでに約2か月かかった
Metabase の操作記録は残していたものの、

② 更新の前にバックアップを取る
Metabase の公式の手順では、更新の前に
アプリケーションデータベース（Metabase 自身の設定やユーザーを保存している DB）をバックアップ
します。初期設定の 
H2（ファイルのデータベース）のまま
動かしている場合は、Metabase を止めてからファイルをコピーします。Postgres などを使っている場合は、その DB のバックアップを取ります。
③ 修正版に更新する（Docker / JAR）
Docker では、
止める → 新しい版のイメージを取る → 同じ設定で起動する
だけで、起動時に Metabase が自動で更新処理をします。公式は 
latest
 より
版を指定したタグ
を勧めています。有料版は 
metabase/metabase-enterprise
 を使います。
ターミナル（Docker で動かしている場合）
docker stop metabase
docker rm metabase
docker pull metabase/metabase:v0.58.41
docker run -d --name metabase -p 127.0.0.1:3000:3000 \
  -v metabase-data:/metabase-data \
  -e MB_DB_FILE=/metabase-data/metabase.db \
  metabase/metabase:v0.58.41
-v
 や 
-e
 の部分は、
今までの起動に使っていたものをそのまま
使います。ここを変えると、別の空のデータで起動してしまいます。
JAR（Java の実行ファイル）で動かしている場合は、サービスを止めて JAR を置き換え、起動し直します。
ターミナル（JAR を systemd で動かしている場合）
sudo systemctl stop metabase.service
curl -fLo metabase.jar https://downloads.metabase.com/v0.58.41/metabase.jar
sudo systemctl restart metabase.service
ダウンロードした 
metabase.jar
 は、
今まで使っていた JAR と同じ場所
に置き換えます（場所は環境ごとに違います）。

再発防止策：多要素認証、権限の制御、脆弱性への迅速な対応といった、侵入を防ぐ対策を強化する。そのうえで、防御が突破されうる前提で、突破された場合にも被害を最小限にとどめ、即座に検知・遮断できる体制を整える。管理ツールへのアクセス制限などは実施済みで、保持データのルール整備や監視の強化などは、順次進めていて、2026年中に完了する見込み、と書かれています。
