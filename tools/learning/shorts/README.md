# ショート1本ごとの作業記録と振り返り（2026-11-21〜、ユーザーの依頼）

ねらい：1本作るたびに記録をとり、反省して次の1本を **軽く・速く（時間とトークンを減らす）、品質は下げずにできれば上げる**。

## 置き場所
- `tools/learning/shorts/<名前>.md`：1本ごとの記録（書式は `_template.md`）。自動でも手作りでも必ず作る。
- `tools/learning/shorts/next.md`：**次の1本で守る改善のリスト（最大5つ）**。制作の最初に読むのはこの1枚だけ（過去の記録は読み直さない）。

## 手順（毎回。省かない）
1. **始める前**：next.md を読む（短い）。今回どれを試すかを決める。
2. **作っている間**：工程の操作をするたびに、その場で1行足す（あとから思い出して書かない）：
   `python3 tools/short_record.py <名前> --note "工程｜何を・どうやって（動かした作業・設定・道具）→結果｜なぜ"`
   - 何を・どの順で・どう設定して行ったか、やり直しなら何が悪くて何を変えたか、を書く。次の AI がこれを読んで「どの手順を変えれば速く・軽くなるか」を見つけるため。
   - 書くのは判断とやり直しがあった操作だけでよい（決まりどおりで問題なかった操作は、下の「操作の流れ」に自動で残る）。
   - コミットの説明は何を直したか分かる言葉で書く（「直した履歴」と「やり直しの前に直したこと」はコミットの説明から自動で作る）。
3. **投稿が終わったら（通知・HANDOFF の前）**：
   1. `python3 tools/short_record.py <名前> --write`（時間・**工程ごとの表（道具・機械・回数・やり直し・分・やり直しの前に直したこと）**・**話す動画を Colab と Modal のどちらで作ったか（Modal なら理由）**・直した履歴（コミットの一覧）・**操作の流れ（会話の記録から、動かした作業と設定・書き換えたファイル・コミットを時刻順に）**・同じファイルの読み直し・Claude の使った量を自動で集めて記録に入れる。自分で数え直さない）。**必ず投稿したその日の作業の中で動かす**（話す動画の置き場などは公開後にドライブへ移って消えるため、あとからでは分からなくなる）。
   2. 記録の残り（やり直し・つまずき・品質・次の改善1〜3個）を短く書く。
   3. **next.md を書き換える**：今回効いた改善は、決まりの文書（shorts_rules.md・auto_short.md など）の同じ話題の行に移して next.md から消す。効かなかったものは消すか直す。新しい改善を足す。全部で5つまで（足し続けない）。
   4. 記録と next.md を main に push（ショートの記録のコミットと一緒でよい）。
4. 通知とユーザーへの報告に「今回の振り返り：<一番大きい改善1行>」を1行入れる。

## 比べる目安（前の記録と比べて良くなったか）
- 時間：最初のコミット〜投稿。目安 60分以内（11/20 の Anthropic上場が約59分）。
- 書き出し（short-build）：1〜2回。読み上げ：1〜2回。
- Claude の使った量：「新しく読んだ」と「操作」の回数が前の数本より減っているか。
- 品質：確認で見つかった問題の数、公開後の再生（週1回の見直しで見る）。品質のために量が増えたときは、それでよい（理由を書く）。

## 週1回の見直しとの関係
- 週報（tools/learning/README.md）は、その週の記録の「数字」と「次の改善」をまとめて表にし、2本以上で同じつまずきがあれば提案にする。
