# 星餓りな ショート動画の作り方メモ（次回以降に必ず守る）

岡野タケシ弁護士の人気ショート20本の構成解析レポートの型に合わせる。
2026-11-06 の「AIがAIを作る時代」を振り返って、足りなかった点を追記した。

## 長さと情報量（2026-11-08 ユーザー決定）
- 「まとめます」のあとは**50秒〜1分を使い切る**（最大1分。冒頭のつかみと登場を足すと動画全体は1分と少し）。原稿は「まとめます」のあとで約330〜380字が目安。
- これまでの動画は要点を絞りすぎて情報量が少なかった（ユーザー指摘）。1本になるべく多くの情報を入れる：
  - 何が・いつ・どこで・誰が、に加えて、数字（価格・性能・人数・金額・日付）、これまでとの違い、使い方や対象（誰が・いつから・どの国で・いくらで使えるか）、背景（なぜ今か・競合の動き）、注意点、りなの見方。
  - 1文に1つの事実を詰め、つなぎの言葉や言い換えの繰り返しは削る。絵は3〜4秒ごとに切り替えるので、場面数も15前後に増やす。

## 構成
1. 0〜4秒 つかみ：挨拶なし。一番強い絵＋結論を**4秒以内の1文で言い切る**（「〜かもしれません」でぼかさない）。冒頭のテロップはタイトル・サムネイルと同じ約束にそろえる（ショートはタイトルより冒頭1〜2秒で見るか決まる。2026-11-09 調査）。
2. 4〜6秒 登場：星餓りなが大きく出て「このニュース、◯◯でまとめます」。◯◯＝この台詞のあと話し終わるまでの長さを10秒単位で切り上げた数で、**最大1分**。60秒のときだけ「1分」と言い、それ以外は「40秒」のように言う（最後のロゴ画面は数えない。tools/short_plan.py の {SEC} で自動計算。60秒を超えたら終了コード4なので台本を削る。2026-11-08 ユーザー決定）。
   - **りなは手でその数字を作る**：50秒→指5本、40秒→指4本、30秒→指3本、1分→指1本（plan の fingers）。ポーズは channel/rina_poses/rina_fingers_<本数>.png（2026-11-09 に可愛い型へ描き直し：少し前かがみ・首をかしげる・笑顔・胸の前で指）。
   - **いつもの立ち絵から動いて、「1分／◯秒」と言う瞬間に指のポーズになる**（2026-11-09 ユーザー指示）。セリフを「このニュース、」と「◯◯でまとめます」に分け、前半は base_green、後半は指のポーズで口の動きを作り、読点の間を動きのコマ（フレーム補間）でつなぐ。手順の詳細は channel/rina_poses/README.md。指の本数と動きの自然さは書き出し後に必ず目で確かめる。
   - ロゴも、頭の上の見出しの文字も出さない（2026-11-07 ユーザー指示）。字幕はふつうのテロップ。
3. いつ・どこ・誰：日付、国・地域、会社名を画面に出す。
4. 経緯：**3〜4秒ごとに絵を切り替える**（別カット、ズーム、図解の段階表示）。
   - 新機能・新製品のニュースは「これまで → これから」の対比で、何が進化したのかを必ず言う。機能の一部（例：表を作る）だけ見せると「それだけ？」に見える（2026-11-07 ユーザー指摘）。
5. 反転：「ただし」「ところが」＋赤スタンプ＋重い効果音。
6. 結末：数字や結論カードで言い切る。
7. 終わり：最強の一言 → 声なしロゴ約2秒（ロゴを出すのはここだけ）。登録のお願いはしない。

## 画面と字幕
- **星餓りなのロゴは最後のロゴ画面だけ**。隅のロゴや登場場面の大きなロゴは出さない（ショートの画面にはチャンネル名とアイコンが最初から出るので重複になり、図解の場所も取る）。
- 字幕は全部の発言に付ける（吹き出しの中）。1画面5〜15字、**0.5〜1秒で切り替え、1本で40〜50回を目安**に細かく切る。
- 色の意味を固定：オレンジ＝数字・重要語・結論、赤＝注意・反転だけ、青＝会社名・人物・事実。
- **画面の形（2026-11-07 ユーザー決定：吹き出し型）**：1080×1920 で、
  - 上：図解・絵は x 70〜1010・y 300〜1270 の中で、場面ごとに一番大きくなるよう自動で拡大する（short.html の measureFits／FIT）。YouTubeでは左右が約50pxずつ切れ、y 約180〜280 に検索の虫眼鏡が出るので、そこには何も置かない（上の「登録チャンネル」などのボタンは一時停止したときだけ出るので気にしなくてよい、2026-11-09 ユーザー）。 場面は中身の座標で x 150〜930・y 355〜1160 の縦長に組む（横長に組むと幅で拡大が止まり上下が余る）。
  - 左下：りな（ふつうの頭身・ステッカー風の絵 small_sticker を0.56倍、左上 x 62・y 1280（頭のすぐ上まで図解、吹き出しのしっぽは口の高さ BY+94〜150）。吹き出しと間をあけ、体を太ももまで見せて細く見せる。左右が切れても欠けない位置）。体はYouTubeのタイトル表示と重なってよい（2026-11-09 ユーザー決定）。
  - 右下：**字幕はりなのセリフとして吹き出しに入れる**。吹き出しは安全な範囲いっぱい（x 400〜915・y 1300〜1575（りなの頭の高さにそろえる）、右のボタン列とタイトルにかからない）。しっぽはりなの顔に向ける。白地・青（ブランド色）の太い枠、文字は紺で数字はオレンジ。
  - 吹き出しの字幕は単語の切れ目で改行し、助詞・小さい字・「た」「だ」から行を始めない。数字と単位（5秒・10言語）、カタカナ語・英単語の途中、ひらがなどうしの間（まと|めます）でも切らない。2行が基本、長いときは3行。
  - **りなを大きく見せる場面（登場・結論）は吹き出しにしない**。りなの胸のあたり（y 約1330）に、白い縁取りのふつうのテロップを出す。
  - 吹き出しの白い地と青い枠は1本の輪郭で描く（しっぽの付け根に線が入らないように）。
  - 作り方の見本：shorts/_template/short.html（canvas の bubble()・bubbleText()・wrapJa()）。
- 絵は公式の画像・動画を優先する（.github/workflows/fetch-media.yml で media/<名前>/ に取り込む。urls.txt に「ファイル名 URL」）。アプリ画面の動画はスマホの枠に入れ、セリフに合う場面を選んで見せる（細かい所は拡大）。
- 音声・画像・動画は main に入れず、ブランチ work に置く（tools/work_branch.py の get / put。2026-11-12〜。詳しくは auto_short.md「素材の置き場」）。
- 生成画像・生成動画には必ず「※画像はイメージです」、実際の画像には出典を小さく表示する。出典は見出しと重ねず、絵の右下に白い小札で置く。
- 引用（申請書の言葉、関係者のセリフ、ネットの反応）は別の声にする。

## 声
- **息継ぎなしで話す（岡野タケシ風、2026-11-07 ユーザー指示）**：「。」のあとは息継ぎせずに次の文へ（間0.04秒、行と行のあいだも0.03秒）。「、」では息継ぎしてよい（間は最大0.3秒）。小さい「っ」などの短い無音（0.14秒未満）は削らない。tools/short_plan.py の period_pause=0.04・comma_max=0.30・gap=0.03、速さ speed は1.15前後。
- 声11（Leda・気だるい・です／ます）を使う。話す速さは1分あたり約350〜380字。
- 原稿の「っていう」など、声の言い方に字幕を合わせる。
- 音声ができたら各セリフの長さを数字で確かめる（同じ文を2回読んでいることがある。そのときは1回目だけ切り出す）。
- Gemini の読み上げは無料枠が1モデル1日10回（2026-11-09 に判明）。1文1回で頼むとすぐ尽きるので、4文ほどを改行でつないで1回で作り、tools/split_tts.py で1文ずつに分ける。尽きたら別のモデル（gemini-3.1-flash-tts-preview など、声 Leda は同じ）で全文を作り直す（1本の中でモデルを混ぜない）。分けたあと、各文の頭とお尻に別の文の切れ端が付いていないかを確かめる（文の中に0.6秒以上の無音があれば怪しい。2026-11-10 Fable 5.2で、外した文の「料金は2倍です」が次の文の頭に残った）。文を外して作り直すときは特に注意。
- 読み間違えやすい数字＋助数詞は、読み上げ用の文（say）だけひらがなにする（例：8日間→ようかかん、1日→ついたち。2026-11-10 「ようとうかん」と読まれた）。字幕（show）は数字のまま。

## パソコンなしで作る道具（2026-11-09）
- ウェブページ：.github/workflows/fetch-to-branch.yml で GitHub 側が取得し、ブランチ fetched に置く（作業中にサイトの許可確認を出さない）。公式の画像・動画は media/<名前>/urls.txt（fetch-media）。
- サムネ：.github/workflows/codex-images.yml（頼み方の JSON を渡すと、ブランチ generated に画像が届く）。
- 大きいりなの話す動画：.github/workflows/longcat-colab.yml（入力フォルダに jobs.json・絵・<名前>.wav、約2.5秒の音声ごとに1区切り・数分）。区切り数は音声の長さに合わせる。（作った動画から絵を作るのは tools/big_clip.py。1.5倍の大きさで抜いて輪郭をなめらかにする）

## りなの動かし方（2026-11-09 ユーザー決定）
- PNGTuber方式にするのは左下の小さいデフォルメりなだけ。話す動画の生成（LongCat）を小さいりなには使わない。
- 左下の小さいりなは**デフォルメのりな**を「PNGTuber方式」で動かす：基本の立ち絵1枚に、口（閉じ・あ・い・う・え・お）と目（開き・半目・閉じ）を差し替え、音声の口のデータで口を動かし、3〜5秒ごとにまばたき、体はゆっくりした呼吸の上下だけ（口に合わせて体を動かすと小刻みに震えて見えるのでしない）。絵はステッカー風（太い黒ふち、channel/rina_puppet/src/chibi_sticker_raw.png、2026-11-09 ユーザー選択）。口と目は単純な形なので、絵の道具で描いてよい。
- 登場と最後の大きいりなは、今の頭身のりな（ブランドの顔）を LongCat で話す動画にする（2026-11-09 ユーザー決定）。コマを選んで並べ替えず、セリフの音声1本からそのまま1本の動画を作る。
- 登場「このニュース、◯◯でまとめます」は、最初から指のポーズの絵で1本の続いた話す動画にする（途中でポーズを切り替えてつなぐとカクカクする）。秒数（10秒〜1分）ごとに一度作ったら音声と動画を channel/rina_intro/ に保存し、次の動画からは同じものを使い回す（GPU代の節約）。指の本数も秒数ごとに違うので、秒数ごとに1本ずつ。
- 大きいりなの話す動画は .github/workflows/longcat-colab.yml で作る（2026-11-10〜、ユーザー決定）：まず Colab の A100 80GB（--high-mem を付けたときだけ80GB版が来る。付けないと40GB版で LongCat には足りない。2026-11-10 colab-check で確認）、だめなら G4 を、30秒ごとに最大20分借り直し（H100 と G4 の --high-mem はこのアカウントでは使えない）、取れなければ自動で Modal（tools/modal_avatar.py、LongCat、A100 80GB）で作る。1本あたり Colab は約2.8単位・約20分（Google AI Pro の枠、2026-11-10 の試験で A100 80GB を1回目で借りられた）、Modal は約0.7ドル（毎月30ドルの無料枠、使いすぎ防止の上限はユーザーが設定済み）。結果はブランチ generated、どちらで作ったかは via.txt。立ち絵に口を貼る方法（PNGTuber）や、立ち絵を部分ごとに動かす・過去の映像を繰り返す方法は、口と表情が数段落ちるので締めには使わない（2026-11-09 ユーザー判断。試作は tools/rina_idle_warp.py・tools/rina_loop_clip.py）。
- 素材は使い回す：動画ごとに必要なら新しい表情・ポーズを足し、channel/rina_puppet/ に一覧（index.json）と一緒に保存する。新しく作る前に、今ある素材で足りないか確かめる。

## 作業の手分け（2026-11-07 ユーザー決定）
- 同時に進める：事実確認（元記事・公式・別メディアを分担）、場面ごとの絵・図解、セリフごとの音声、投稿準備（サムネ・タイトル・概要欄・タグ・英訳・字幕）、最終チェック（作った本人以外）。単純な作業は Sonnet のサブエージェント。
- 順番どおり：台本 → 音声 → short_plan.py → 口の動き → 書き出し。レイアウト・色の判断は1か所でまとめて行う。
- 書き出しは shorts/_template/render_par.js で分割して同時に描く（N=CPUの数）。

## 事実確認
- 断定する内容は、元記事（一次情報か大手メディア）で必ず確かめる。数字は2つ以上の記事で裏を取る。
- **サイトの許可確認を出さない手順（2026-11-09 ユーザー指示）**：会話に出てきていないURLを WebFetch で開くと許可確認が出る（サブエージェントも同じ）。
  1. 元記事・公式ページ・参考記事は、最初に fetch-to-branch.yml でまとめて取得し、ブランチ fetched のテキストを読む（自分で WebFetch しない）。
  2. サブエージェントへの指示に URL を書かない。サイト名と調べることだけ伝え、WebSearch から辿らせる（検索結果に出たURLだけ開く）。取得済みのテキストを渡すのもよい。
  3. 開けないページは推測で補わず、fetch-to-branch で取得してから確かめる。

- 結論の場面：上の2枚のカードは y 約290〜550、大きいりなはその下（髪の上端 y 約700）。図解・カードとりなを重ねない（2026-11-09 ユーザー）。
