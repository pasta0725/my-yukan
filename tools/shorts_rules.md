# 星餓りな ショート動画の作り方メモ（次回以降に必ず守る）

岡野タケシ弁護士の人気ショート20本の構成解析レポートの型に合わせる。
2026-11-06 の「AIがAIを作る時代」を振り返って、足りなかった点を追記した。

## 長さと情報量（2026-11-08 ユーザー決定、長さは 2026-11-16 更新）
- **動画全体を55秒前後に（最大60秒、最後のロゴなし）**。原稿は全体で約320〜360字が目安（2026-11-16 まで：「まとめます」のあと50秒〜1分＋最後のロゴ約2秒で、全体は1分と少しだった）。
- これまでの動画は要点を絞りすぎて情報量が少なかった（ユーザー指摘）。1本になるべく多くの情報を入れる：
  - 何が・いつ・どこで・誰が、に加えて、数字（価格・性能・人数・金額・日付）、これまでとの違い、使い方や対象（誰が・いつから・どの国で・いくらで使えるか）、背景（なぜ今か・競合の動き）、注意点、りなの見方。
  - 1文に1つの事実を詰め、つなぎの言葉や言い換えの繰り返しは削る。絵は3〜4秒ごとに切り替えるので、場面数も15前後に増やす。

## 構成
- **全体の流れ（2026-11-17 ユーザー決定。岡野タケシさんの実際の構成）**：①掴みの強い事実を端的に言い切る（「何それ気になる」と思わせる）→ ②「1分で要約します」の宣言 → ③①について詳しい情報の要約（いつ・どこ・誰・経緯・反転・結末）→ ④ネット上の声 → 冒頭につながる締めの一言。
1. 0〜4秒 つかみ（2026-11-15 更新。人気ショート68本の冒頭解析〔Grok Bot 調べ〕にもとづく。挨拶なし）：
   - **0秒：見せる「物」を1つ画面の真ん中に**（話題の製品・実物の写真や公式画像・アプリ画面・りなの顔のどれか）。ロゴだけ・表だけ・ぼんやりした背景で始めない。
   - **声は0.2秒以内に始める**（無音やジングルから入らない。読み上げの頭の無音は削る。spec.json に "lead": 0.1 と書くと最初の声が0.1秒から始まる。書かないと short_plan.py の既定0.25秒）。
   - **1コマ目から特大テロップ**（4〜20字、画面の中央から下、強調語1つだけ色を変える）。掴みの強い事実を短く言い切る文でよい（例「Xの画像上限 10年ぶり5倍に」）。問いの形にしてもよい。
   - **「はい／いいえ」で終わる問いにしない**（2026-11-16 最新3本の解析〔Grok Bot〕：「〜って知ってます？」は答えて終わり、続きを見る理由が残らない）。「何？」「いくら？」「どうなる？」のように答えを伏せる問いか、損得・意外さの言い切り（「今の会員も12月から最大300円上がります」）にする。
   - **いちばん強いネタといちばん気になる絵を0秒に置く**：中盤の「実は〜」「今の会員も〜」のような一番の驚きを、冒頭に持ってくる（例：modsは0秒を赤い「Storm 77%」から、Whiteboardsはぐちゃぐちゃのメモが整理される絵から）。
   - **0秒の画面はスマホで一瞬で読めるもの**：細かい料金表のスクショ・アイコンだけ・文字の塊がいくつも重なる画面はだめ。読ませたい数字は大きなテロップに起こし、0秒の文字の塊は1つ（＋特大テロップ）まで。
   - **冒頭の型を毎回変える**：直前3本と同じ問い方・同じ構図・同じ言い回しにしない（下の5つの型と、0秒の絵の種類を回す）。
   - **最初の一文は「掴みの強い事実を端的に言い切る」**（2026-11-17 ユーザー決定。岡野タケシさんの冒頭は問いではなく、驚く事実を一言で言い切って「何それ気になる」と思わせている）。言い切りを基本にし、問いにするなら答えを伏せる問い（「何？」「いくら？」）にする。11-15 の「問いにして答えは伏せる」の型（疑問・指示語・逆張り・有名な固有名詞・数字×異常）は、言い切りの文を作るときの切り口として使う。
   - **0.5〜1秒ごとに画面を変える**（テロップの切り替え・矢印・ズーム）。最初の3秒で最低1回は大きく変える。
   - **映像（同じ解析から）**：
     - **0秒は「冒頭でいちばん掴みが強い映像」＋特大テロップ（掴みの一言）の2つだけ**（2026-11-17 ユーザー決定。岡野タケシさんは最初から本人を出さない。11-16 の「0秒から大きいりな」は、Grok Bot の「0秒で顔が見えた90%」がニュースの人物の顔も数えていたと思われるため取りやめ）。映像は本物（公式の製品写真・アプリ画面・出来事の写真や動画）でも、生成した画像や動画でもよい。どれがいちばん「何これ？」と思わせるかで選び、画面いっぱい（横幅いっぱい・縦も大きく）に置く。りなは0秒に出さなくてよい（いちばん強い絵がりなの表情のときだけ0秒に出す）。0秒に小さい画像・札・字幕を足さない（11-16 の自動ショートで4つ重なり目線が散った）。
     - **生成した画像・動画を使うとき**：画像は codex-images.yml（Codex の画像生成）で作り、隅に「※画像はイメージです」。実在の製品を写真のように描いたり、実在の人物の顔を作ったりしない（本物と間違える絵は作らない）。出来事の場面・比喩（例：画像が20枚あふれ出すスマホ、嵐のマークが出た画面のイメージ）に使う。動画の生成の仕組みはまだないので、それまでは静止画にズーム・パン・揺れなどの動きを付けて動画らしく見せる。
     - **大きいりな（LongCat の話す動画）は2文目＝「1分で要約します」の宣言で登場**：大きいりなが表情豊かに言う（spec のその行に "big": true、場面名 hook）。表情も変える（jobs.json の言葉で「身を乗り出して」「得意げに」など。いつもの笑顔のままにしない）。目線はカメラ（見る人）に向ける。
     - **大きいりなの構図の数値**（1080×1920）：big_clip.py の絵（1080×1920）を1.6倍、顔の中心 x 540・目の高さ y 980（左上 x −332・y 366、幅1728・高さ3072。顔の幅 約430px）。その場面のテロップ＝y 約640〜900（110〜130px、白の太いふち、髪に重ねてよい）、字幕＝胸のあたり y 1330。0秒は何もフェードインさせない（1コマ目から全部見える）。見本は shorts/rina_newfmt_trial/short.html の hook（0秒にりながいる古い形なので、構図の数値だけ参考にする）。
     - 0.5〜1秒ごとに画面を動かし、最初の3秒で、本物の画像（読める大きさ）・生成の絵・大きいりなを切り替えて見せる。作った図解だけで続けない。
     - **見る所を指さす**：赤い矢印・丸囲み・ラベル（「ここ」「新機能」など）、左右に並べた比較で、0〜3秒の視線を1点に集める。
     - **縦画面いっぱい**に使う（上下に大きな無地の余白や、横長の映像を小さく置くだけの構図にしない）。
     - 1コマ目がサムネイルと同じ「表紙」でもよいが、その後0.5秒の一言で引き込む。
   - つかみの次は「1分で要約します」の宣言（構成2）。
   - やってはいけない：「○○によりますと」のような原稿読み・テーマ名だけ（「今日は○○について」）・主語のあいまいな文・身内の話・無音スタート。
   - 型が同じでも、題材（誰もが知っている名前・損得・はっきりした異常事態）が弱いと伸びない。題材選びが先。
   - 冒頭のテロップはタイトル・サムネイルと同じ約束にそろえる。
2. 約3〜5秒 「1分で要約します」の宣言（2026-11-17 ユーザー決定で戻す。岡野タケシさんも使っている）：
   - 大きいりなが「このニュース、1分で要約します」のように**短く**言う（1.5秒ほど。言い回しは毎回少し変えてよい。動画全体が60秒以内なので「1分」と言ってよい。{SEC} の計算や指のポーズは使わない）。
   - **画面は止めない**（11-16 の Grok Bot の指摘：全身の立ち絵に切り替わって2〜3秒情報が止まっていた）。宣言の間も、大きいりなの横や上で、掴みの事実の絵・数字のテロップを動かし続ける。
   - 2026-11-16 まで：「このニュース、{SEC}でまとめます」＋指のポーズ（channel/rina_poses/・channel/rina_intro/ の使い回し、spec の {SEC}・sec・fixed_wav）。11-16〜11-17 は宣言をやめて「続きを見る理由」の一文にしていた。
3. いつ・どこ・誰：日付、国・地域、会社名を画面に出す。
4. 経緯：**3〜4秒ごとに絵を切り替える**（別カット、ズーム、図解の段階表示）。
   - 新機能・新製品のニュースは「これまで → これから」の対比で、何が進化したのかを必ず言う。機能の一部（例：表を作る）だけ見せると「それだけ？」に見える（2026-11-07 ユーザー指摘）。
   - **答えの文字は、絵の動きと一緒か後に出す**（2026-11-17 ユーザー指摘：rina_x20 で「これから 20枚」の文字が先に出て、画像が20枚に増えるアニメが後から来た）。数や結果を絵で増やす・並べる・動かすときは、その結果を表す文字（「20枚」「5倍」「990円」など）を最初から置かない。絵が増えるのに合わせて数を数え上げる（4→20）か、絵が出そろった瞬間に出す。セリフで数を言うタイミングにもそろえる。
5. 反転：「ただし」「ところが」＋赤スタンプ＋重い効果音。
6. 結末：数字や結論カードで言い切る。
6-2. **ネット上の声**（2026-11-17 ユーザー決定。岡野タケシさんの構成④）：締めの前に、記事に付いている「Xの声」（data/x/<号>.json のその記事の分）から2〜3件を、要点だけの短い言い換えでカードにして見せ、りなが読む（「ネットでは『〜』『〜』という声も」）。名前・アカウント・アイコンは出さない。賛成と反対・期待と心配が両方あれば両方。暴言・個人攻撃・真偽の分からない噂は使わない。画面には「Xの声（要約）」と書く。その記事に Xの声が無ければ、この場面は省く。
7. 終わり（2026-11-16 更新）：最強の一言 → **冒頭につながる一言で締める**（ループで見返されるように。例：最初の問いが「この天気マーク、何だと思います？」なら「次にこう聞かれても、もう答えられますね。」）。大きいりなが最後まで話し、声が終わったら0.15秒で動画が終わる（spec "tail_logo": 0。最後のロゴ画面・無音はなし）。最後の一言の間に、りなを0秒の構図（顔を大きく）へ寄せ、0秒の本物の画像を戻すと、ループの継ぎ目が目立たない（見本：shorts/rina_newfmt_trial の verdict）。登録のお願いはしない。（2026-11-16 まで：最後に声なしロゴ約2秒）

## 画面と字幕
- **1場面に乗せる情報は少なく**（2026-11-17 ユーザー指摘：星餓りなは1場面の情報量が多すぎる。例：Whiteboards の「これまで→これから」は、見出し＋カード2枚に文字が9個＋吹き出しで、「これまで」「これから」が3回ずつ出ていた）。
  - **1場面＝言いたいことは1つ**。画面の文字は「大きい見出しかテロップ1つ＋吹き出しの字幕」まで。絵の中のラベルは合わせて3つまで、1つ2〜6字。
  - 同じ言葉を見出しとカードで繰り返さない。りながセリフで言うことを、絵の中にもう一度細かく書かない（文字ではなく絵で見せる）。
  - 説明の絵は大きな絵1つ（またはアイコン1〜2個）にする。小さな部品をたくさん並べた図にしない。手順や流れは、1場面にまとめず、場面を分けて1つずつ見せる。
  - 「これまで → これから」は、①これまで（大きな絵1つ＋一言）→ ②これから（大きな絵1つ＋一言）と続けて見せるか、並べるなら左右それぞれ「絵1つ＋2〜6字」だけにする。
- **ショートの画面にはロゴを出さない**（2026-11-16〜 最後のロゴ画面もなし。隅のロゴや大きなロゴは、ショートの画面に最初から出るチャンネル名とアイコンと重複し、図解の場所も取る）。
- 字幕は全部の発言に付ける（吹き出しの中）。1画面5〜15字、**0.5〜1秒で切り替え、1本で40〜50回を目安**に細かく切る。
- 配色は shorts/_template/pal.js（明るい背景・数字はオレンジ）をそのままコピーして使い、ショートごとに変えない。check_fit.js が違いを PALETTE で知らせる（2026-11-14、空の pal.js で紺の背景・黄色の数字になった）。
- 色の意味を固定：オレンジ＝数字（値段・日付・数量などの値だけ。PS5・Switch 2・iPhone 17 のような製品名の中の数字は色を変えない。2026-11-14 ユーザー決定）・重要語・結論、赤＝注意・反転だけ、青＝会社名・人物・事実。
- **画面の形（2026-11-07 ユーザー決定：吹き出し型）**：1080×1920 で、
  - 上：図解・絵は x 70〜1010・y 300〜1270 の中で、場面ごとに一番大きくなるよう自動で拡大する（short.html の measureFits／FIT）。YouTubeでは左右が約50pxずつ切れ、y 約180〜280 に検索の虫眼鏡が出るので、そこには何も置かない（上の「登録チャンネル」などのボタンは一時停止したときだけ出るので気にしなくてよい、2026-11-09 ユーザー）。 場面は中身の座標で x 150〜930・y 355〜1160 の縦長に組む（横長に組むと幅で拡大が止まり上下が余る）。
  - 左下：りな（ふつうの頭身・ステッカー風の絵 small_sticker を0.56倍、左上 x 62・y 1280（頭のすぐ上まで図解、吹き出しのしっぽは口の高さ BY+94〜150）。吹き出しと間をあけ、体を太ももまで見せて細く見せる。左右が切れても欠けない位置）。体はYouTubeのタイトル表示と重なってよい（2026-11-09 ユーザー決定）。
  - 右下：**字幕はりなのセリフとして吹き出しに入れる**。吹き出しは安全な範囲いっぱい（x 400〜915・y 1300〜1575（りなの頭の高さにそろえる）、右のボタン列とタイトルにかからない）。しっぽはりなの顔に向ける。白地・青（ブランド色）の太い枠、文字は紺で数字はオレンジ。
  - 吹き出しの字幕は単語の切れ目で改行し、助詞・小さい字・「た」「だ」から行を始めない。数字と単位（5秒・10言語）、カタカナ語・英単語の途中、ひらがなどうしの間（まと|めます）でも切らない。2行が基本、長いときは3行。
  - **りなを大きく見せる場面（つかみ・結論）は吹き出しにしない**。りなの胸のあたり（y 約1330）に、白い縁取りのふつうのテロップを出す。
  - 吹き出しの白い地と青い枠は1本の輪郭で描く（しっぽの付け根に線が入らないように）。
  - 作り方の見本：shorts/_template/short.html（canvas の bubble()・bubbleText()・wrapJa()）。
- 絵は公式の画像・動画を優先する（.github/workflows/fetch-media.yml で media/<名前>/ に取り込む。urls.txt に「ファイル名 URL」）。アプリ画面の動画はスマホの枠に入れ、セリフに合う場面を選んで見せる（細かい所は拡大）。
- 音声・画像・動画は main に入れず、ブランチ work に置く（tools/work_branch.py の get / put。2026-11-12〜。詳しくは auto_short.md「素材の置き場」）。
- 生成画像・生成動画には必ず「※画像はイメージです」、実際の画像には出典を小さく表示する。出典は見出しと重ねず、絵の右下に白い小札で置く。
- 引用（申請書の言葉、関係者のセリフ、ネットの反応）は別の声にする。

## 声
- **息継ぎなしで話す（岡野タケシ風、2026-11-07 ユーザー指示）**：「。」のあとは息継ぎせずに次の文へ（間0.04秒、行と行のあいだも0.03秒）。「、」では息継ぎしてよい（間は最大0.3秒）。小さい「っ」などの短い無音（0.14秒未満）は削らない。tools/short_plan.py の period_pause=0.04・comma_max=0.30・gap=0.03、速さ speed は1.15前後。
- 声11（Leda・気だるい・です／ます）を使う。話す速さは1分あたり約350〜380字。
- 原稿の「っていう」など、声の言い方に字幕を合わせる。
- 音声ができたら各セリフの長さを数字で確かめる（同じ文を2回読んでいることがある。そのときは1回目だけ切り出す）。
- Gemini の読み上げは無料枠が1モデル1日10回（2026-11-09 に判明）。台本全部（15文まで）を改行でつないで1回で作り、tools/split_tts.py で1文ずつに分ける（2026-11-12 の試験：12文・約80秒を1回で作り、全文正しく分けられた。4文ずつより枠が4分の1で済む）。分けたら必ず `python3 tools/check_split.py <lines.json> <分けたフォルダ>` で1文ずつ文字起こしして、台本と比べる（LOOK の文は切れ目を直す。split_tts.py の CHECK は見逃すことがある。2026-11-13 Issue #16）。1文だけ作り直すときは、前後の文と一緒に2文以上で頼む（1文だけだと声の指示文まで読み上げた。Issue #16）。直す文だけ作り直すときも同じモデルで。別のモデルには切り替えない（同じ声 Leda でも、モデルが違うと声の高さ・速さ・気だるさが変わる。2026-11-12 ユーザー決定）。枠が尽きたら17時ごろの回復を待つ。もっと本数が要るときは、Google AI Pro の毎月の Cloud クレジット（月10ドル、1本約5円）で有料に切り替える（読み上げ専用のプロジェクトを作る。支払いの登録はユーザー）。分けたあと、各文の頭とお尻に別の文の切れ端が付いていないかを確かめる（文の中に0.6秒以上の無音があれば怪しい。2026-11-10 Fable 5.2で、外した文の「料金は2倍です」が次の文の頭に残った）。文を外して作り直すときは特に注意。行の頭が「おすすめ1、」のような短い語＋「、」だと、その語が前の文のお尻に付きやすい（2026-11-16 Issue #25。無音の位置で手で切り直し、spec の wav で固定した）。
- 読み間違えやすい数字＋助数詞は、読み上げ用の文（say）だけひらがなにする（例：8日間→ようかかん、1日→ついたち。2026-11-10 「ようとうかん」と読まれた）。字幕（show）は数字のまま。
