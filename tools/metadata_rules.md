# 星餓りな ショート投稿時の項目設定ルール（AI自動入力用）

調査レポート「YouTubeショートの概要欄・タグ・設定と再生数」（2026年11月）をもとにしたルール。
再生数を決めるのは主に「冒頭1〜2秒でスワイプされないか」「最後まで見られるか」。設定は「何の動画かを正しく伝える」「規約違反・量産判定を避ける」「海外の入口を増やす」ためのもの。3か月ごとに公式ヘルプと照らし合わせて見直す。

## タイトル（2026-11-09 調査をもとに更新）
- 前提：ショートがフィードで見られるかは冒頭1〜2秒でほぼ決まり、タイトルが効くのは検索・関連動画・チャンネルページ。だからタイトルは「検索で拾われる言葉」と「具体的な事実」を優先し、冒頭テロップとサムネと同じ約束にそろえる。
- 全角28字以内（目標20〜26字）。主役の固有名詞を最初の10字以内に置く。知名度の低い名前には有名な親ブランドか説明を添える（例：「Metaの新アプリSpaces」）。
- 人が検索する言葉を1つ入れる：製品名＋「新機能」「料金」「使い方」「比較」「とは」「いつから」など。
- 「｜」の後ろの一言は、数字・事実で具体的に（「上限2倍」「無料で」「月額○円」「来月から」）。「もうすぐ？」のようなぼかしや、疑問で締めるのを基本にしない（疑問で終わる形は平均より弱いというデータ。疑問形は本当に未確定な話＝リークなどに限る）。
- 型（毎回同じにせず、内容に合うものを選ぶ）：
  1. {主役}が{何をした}｜{数字・事実}
  2. {主役}の新機能{N}つ｜{誰に効くか}
  3. {A}と{B}｜{何が}どっちが{上か}
  4. {主役}の{制限など}が{変化}｜{何倍・いつから}
  5. {製品}は{価格}｜{発売・開始日}
  6. 【速報】{主役}{出来事}｜{要点を1つ}
  7. {用語}とは｜{N}秒で分かる{要点}
  8. {製品}が変わる｜{生活で何が変わるか}
- 【】は【速報】（発表から24時間以内）【まとめ】【比較】だけ、1タイトルに1つまで。絵文字なし。#shorts とハッシュタグはタイトルに入れない。
- 誇張（死亡・終了・崩壊・ヤバすぎ等）や、動画が届けない約束は禁止（ニュース・時事の釣りはYouTubeの取り締まり対象）。数字は事実の数字だけ。
- 投稿後にタイトルを変えるのは、検索から見られている動画に限り、投稿2〜3日後に検索語を足す程度にする。

## 概要欄（300〜600字）
```
{1行目：何が起きたかを40字前後で。主役の固有名詞を含める}
りなの見方：{日本の利用者への影響・りなの見解}

▼ポイント
・{要点1}
・{要点2}
・{要点3}

▼出典
{媒体名}（{YYYY年M月D日}）
{URL}
{媒体名}（{YYYY年M月D日}）
{URL}
※ショート動画では、概要欄のURLはタップできません

▼星餓りなについて
毎日1本、AI・テックのニュースを1分で解説しています。

#{主役} #AIニュース #星餓りな
```
- 出典は2つ以上（一次情報を優先）、媒体名と日付を文字で書く。キーワードの羅列は禁止。
- 「AIで作っている」ことは書かない（ユーザーの方針）。

## ハッシュタグ
- ちょうど3個、概要欄の最後に、半角#・スペースなし：#{主役} #AIニュース #星餓りな（主役が決まらなければ #テックニュース）。
- #shorts・#viral・関係のない流行タグは禁止。

## タグ欄（5〜8個、500文字以内）
- 星餓りな, {主役の英語表記}, {主役のカタカナ}, {関連製品名の英語/カタカナ}, AIニュース, {話題の用語}。表記ゆれ・誤字対策が目的。

## 固定の設定
- カテゴリ：科学と技術
- 動画の言語・タイトルと説明の言語：日本語
- 子ども向け：いいえ／年齢制限：なし／有料プロモーション：案件のときだけ「はい」
- AIの使用（AI use）：原則「いいえ」（アニメ調キャラ・汎用AI音声・イラスト調のAI図解は対象外）。
  「はい」にする条件：写真のようにリアルなAI画像・映像／実在の人物の顔や声を模した／AI生成の音楽が主役／実際の映像や写真をAIで改変。迷ったら「はい」。
- ライセンス：標準／埋め込み：許可／登録者に通知：オン／リミックス：動画と音声を許可／高評価数：表示
- コメント：オン、管理「標準」（不適切なものは保留）
- 再生リスト：「毎日1分AIニュース」に必ず追加（テーマ別リストは本数が増えてから）
- 関連動画：同じ主役の過去のショート（あれば）

## 字幕・多言語
- 台本のテロップ（plan.js の tel）から日本語SRTを作り、字幕ページの日本語トラックに「ファイルをアップロード → タイムコードあり」で上書き公開する（channel/captions/）。
- 英語の翻訳タイトル（60文字以内）と翻訳概要欄（要約2〜3行＋出典＋ #Anthropic #AINews #星餓りな の形）を毎回入れる。
- 多言語音声（自動吹き替え）は保留。試すときは英語だけ1か月、言語別の再生時間で判断。

## 投稿・運用（2026-11-09 調査をもとに更新）
- 投稿時刻そのものはショートでは決め手にならない（YouTubeのショート責任者・ヘルプとも「最適化の対象ではない、ただしニュースは鮮度が大事」）。大事なのは「発表からどれだけ早く出すか」と「冒頭で離脱されないか」。
- **できたらすぐ公開する（鮮度優先）**。夜のうちに出た海外の発表は、朝7:00に予約公開してよい（7:00＝夜の間のニュースの締め切り）。昼に出たニュースを翌朝まで寝かせない。
- 急ぎでないネタ（解説・まとめ・比較）は、時刻のテストに使う：7:00／12:15／20:30 を日ごとに順番に回し、各時刻10〜15本たまったら比べる（公開7日後の再生の中央値。2割以上の差が前半・後半とも続けばその時刻に固定、1割未満なら時刻は気にしない）。日本のネット利用は夜21時台が最多、昼12時台が2番目、朝7時台が3番目（総務省 2025年調査）。
- 本数：原則1日1本（自分たちの決まり。YouTubeの規則ではない）。速報なら2本目もよい。前の1本と3〜4時間以上あけ、同じネタの言い換えにはしない。
- 毎回 channel/shorts_log.csv に記録する（公開日時・タイトルの型・文字数・数字の有無・時刻テストの枠・24時間/7日後の再生・視聴された割合・検索からの割合）。1週間に変える要素は1つだけ。
- 登録者1,000人を超えたら、アナリティクスの視聴時間帯とテスト結果で見直す。
- 固定コメント：「{視聴者への質問}／出典：{媒体名}」（投稿前にユーザーに文面を確認）。最初の24時間のコメントには返信かハート。
- 見る指標：視聴された割合（Viewed vs. Swiped＝冒頭の評価）、流入元のYouTube検索の割合（タイトルの評価）、平均視聴率、登録者の増減。再生回数そのものだけでは判断しない。

## 量産判定を避ける必須チェック（投稿前）
- 台本に、りな独自の見解（なぜ重要か・日本への影響・予想）が1つ以上ある。
- 冒頭のフックの文が、直近7本と同じ型でない。図解・構成も毎回変える。
- 出典2つ以上、日付を確認済み。タイトル・概要欄の主張が動画と一致。
- 1日1本を守る。

## YouTube Studio の操作メモ
- 内蔵ブラウザの Studio は、右上のアカウントから「アカウントを切り替える → 星餓りな」にしてから操作する（チャンネルID UCDIg0hL5OV6xB5V8GtV-g9A）。「わかばのぱすた」のまま操作すると、再生リストなどがそちらに作られてしまう。
- カスタムサムネイルとコメントの固定は、星餓りなチャンネルの確認（電話番号・ワンタイム認証）が終わるまでできない（確認はユーザーが行う）。
- コメントは youtube.com 側も右上のアカウントで「星餓りな」に切り替えてから、通常の動画ページ（/watch?v=）で投稿する。
- タイトル・概要欄は contenteditable に execCommand('insertText') で入力できる。タグ欄は入力欄をクリックして「,」区切りで入力し Enter。
- 字幕：字幕ページで日本語行の鉛筆 →「トラックの上書き」続行 → エディタ右上の︙ →「ファイルをアップロード」→「タイムコードあり」→ 公開。英語のタイトル・説明は「言語を追加 → 英語」の行の鉛筆から。英語の説明欄は textarea なので、focus → select → execCommand('insertText') で入れる（form_input や type だと途中に挿入されて崩れる）。
- ファイル（動画・字幕・サムネ）は、ファイル選択ボタンを押す前に HTMLInputElement.prototype.click を差し替えて、raw.githubusercontent.com から取ったファイルを入れる。差し替え後のクリックは反映が数秒遅れることがあるので、すぐに別の入力欄へファイルを入れ直さない（2026-11-08、動画をサムネ欄に入れてしまった）。
- 公開ボタンのあと「動画を保存できませんでした。再試行します」と出続けても、公開・タイトル・説明は保存されていることがある。動画の詳細ページ（/video/<ID>/edit）を開いて、公開状態とサムネを確かめる。
- 投稿画面は横幅が狭いと要素が隠れるので、内蔵ブラウザの表示を 1300x900 にしてから操作し、終わったら元に戻す。

## 完成動画の保管（2026-11-09 ユーザー決定）
- 完成動画は GitHub に残さない（作り直すたびに履歴に残り、容量が増え続けるため）。保管場所は Google ドライブの「星餓りな ショート動画」フォルダ（ID 1qTyAGlQurDbu4FrZrxZWua7EoKmPvDCu、pastachannel0725）。
- 投稿の流れ（2026-11-09〜、PC不要）：完成版を使い捨てのブランチ upload-tmp に置く → GitHubの自動作業 youtube-upload.yml（name=<名前>, video=<ファイル名>, comment=固定コメントの文面）で、タイトル・概要欄・タグ・サムネ・日本語字幕・英語の翻訳・再生リスト・コメントまで入れて投稿 → ドライブ「星餓りな ショート動画」にも保存 → upload-tmp を空にする。鍵は GitHub の YT_CLIENT_ID / YT_CLIENT_SECRET / YT_REFRESH_TOKEN（Googleのプロジェクト rina-youtube、本番環境）。Googleの審査が通るまでは動画が「非公開」で上がるので、ユーザーがスマホのStudioアプリで公開にする。コメントの固定はブラウザで。
- 作り直しの途中の版はコミットしない（shorts/*/short_v*.mp4、channel/uploads/ は .gitignore 済み）。
- 公開したら、その動画の素材（media/<名前>、narration/<名前>*、shorts/<名前> の画像・動画・音声、channel/thumbs のサムネ）をzipにして同じドライブの「素材と試作の保管」フォルダ（ID 1-zsIlQf3Azjbql2WJyQro7MvBxDoaGQ1）へ移し、GitHubからは消す（台本・ページなど文字のファイルは残す）。作り直すときはzipから戻す。
- 作業用ブランチ（generated・fetched・upload-tmp）は、中身を取り出したら消す（次に使うワークフローが作り直す）。
- りなの絵（channel/rina_puppet）は可逆のWebPで保存する（PNGより約3割小さく、画質は同じ）。
