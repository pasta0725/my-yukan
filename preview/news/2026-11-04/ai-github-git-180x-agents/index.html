GitHub、AIの大量書き込みに備えGitを刷新、180倍

AI11月4日（水）の号出典：Publickey

3行でわかる

  1. GitHubがAI向けにコード保存の基盤を作り替える
  2. 1つの置き場への書き込みが、従来の180倍（Publickey）
  3. 全員の移行は来年初めの予定。使い方は変わらない見込み

GitHubは10月末の開発者向けイベントで、AIの大量の書き込みに耐えるため、コード保存の基盤を作り直すと説明しました。

なぜ基盤を作り直すのか

AIエージェント（人に代わって作業するAI）が、コードを大量に書き込むようになったためです。GitHubによると、今年だけでCPUのコアを400万個、高速な保存容量を160PB、通信の太さを50Tb/s増やしました。

The RegisterとTechzineによると、Gitの操作回数は2025年9月の月2182億回から、2026年8月の4733億回へ倍増しました。2026年9月のコミット（変更の記録）は73億8000万件で、前年同月の5倍です。

180倍という数字の中身

Publickeyによると、5000体のAIエージェントが1つのリポジトリ（コードの置き場）へ同時に書き込む試験で、毎秒7200回をこなしました。従来の約180倍です。従来は毎秒数十回が上限でした。

GitHubで最も活発なリポジトリの24時間分の通信を、1分に縮めて流す試験も余裕で通ったそうです。GitHubの公式ブログ記事に、180倍という数字は書かれていません。10月上旬の報道では、社内試験の結果は35倍とされていました。

仕組みはどう変わるか

これまでGitHubは、1つのリポジトリを標準で5台のサーバーに保存し、書き込みのたびに多数決を取っていました。読み取りを増やそうとして複製を足すと、書き込みが遅くなる弱点がありました。

新しい仕組みは、データの置き場所と計算を分けます。コードはMicrosoftのクラウド（Azure）の保管庫に置き、Gitのサーバーは一時的な写しだけを持ちます。書き込みの順番待ちも、リポジトリ全体からブランチ（作業の枝）ごとに変わります。別のブランチなら同時に書けるため、公式ブログは3〜4倍速くなると説明しています。

いつ変わり、何が残るか

GitHubは、Azureへの移行と複数地域での運用を、来年初めに終える見通しです。Publickeyによると、全利用者が新方式へ移るのも来年初めです。GitHubは、ほぼすべてのリポジトリの写しの1つをAzureに置き、Gitの通信の約半分をAzureで処理していると説明しています。

The Registerによると、開発の流れやレビュー、セキュリティの設定は変えない方針です。ブランチの保護や必須レビュー、監査ログも残ります。
