Claude API、1回に送れる量が4倍の128MBに

AI11月3日（火）の号出典：PC Watch

3行でわかる

  1. AnthropicのAPIで、1回に送れるデータ量の上限が32MBから128MBの4倍になった。
  2. 画像を20枚を超えて送る依頼は、1枚の上限が2000ピクセルから3000ピクセルに。
  3. 128MBは直営APIだけ。クラウド経由は20〜32MBのまま。料金はトークン課金。

AnthropicがClaudeのAPI（開発者向けの窓口）で、1回に送れる量の上限を4倍の128MBにしました。

上限が32MBから128MBに

対象は、メッセージを送るMessages APIと、使う量を事前に数えるToken Counting APIです。上限を超えると、送りすぎを知らせる413エラー（request_too_large）が返ります。

引き上げの背景にあった困りごと

画像が多い依頼では、AIが読める文章量にはまだ余裕があるのに、データ量だけで断られることがありました。長い画面操作の記録はスクリーンショットが溜まり、細かい図やスキャンを含む大きなPDFも同じように引っかかりました。

開発者には、次のような工夫が必要でした。 ・画像を縮小する ・文書を分ける ・履歴を削る ・Files APIを使う

画像の上限もゆるんだ

1回に20枚を超える画像を送る場合、1枚あたりの上限が2000ピクセルから3000ピクセルになりました。画面、表、図、スキャンの細かい部分が残りやすくなります。

20枚以下の場合は従来どおり2000ピクセルと説明する記事もあります。解像度が上がると、使うトークン（AIが数える文字量の単位）も増えやすくなります。

128MBは直営APIだけ

128MBになったのは、Anthropic直営のAPIだけです。各社によると、Amazon Bedrock経由は20MB、Google管理のClaudeは30MBのままです。ほかのクラウド経由は、32MBのままです。 ・Claude Platform on AWS ・Anthropic管理のGoogle Cloud ・Microsoft Foundry

Bedrockの20MBは、直営の以前の上限（32MB）より低いままで、直営との差が広がりました。

変わらないことと費用

Message Batches APIは256MB、Files APIは500MBのままです。コンテキストウィンドウ（一度に扱える文章量）やトークンの上限も変わりません。料金の仕組みも変わらず、トークンで課金されるので、たくさん送れば費用も増えます。

大きな依頼は処理に時間がかかり、1分あたりのトークン制限にも当たりやすくなります。そのため、ストリーミング（結果を少しずつ受け取る方式）やバッチ（まとめて処理する方式）の利用が勧められています。適用が始まった日付は発表されていません。

あなたへの影響・やること

  • Claudeを直営APIで使う開発者は、大きなPDFや画像を分けずに送れるか試す。
  • Bedrockなどクラウド経由で使っている人は、上限が20〜32MBのままなので、どちらの窓口を使っているか確認する。
  • 送れる量が増えても料金は増えるので、細かい図が必要な画像だけ高解像度にする。
  • コードを書かない人は、今のところ特にすることはありません。
