Turning a simulation idea into a working application means assembling assets, connecting physics and rendering, and checking that the scene behaves as intended. Developers are combining frontier AI models with
NVIDIA Omniverse libraries
to help carry out that work — building applications for exploring scenarios, investigating failures and improving designs.
Developers direct AI agents through natural-language instructions, review results and guide changes. Omniverse libraries provide GPU-accelerated physics, rendering and sensor simulation capabilities.

Build a Robot Pick-and-Place Simulation With SimReady Assets
🔗
Getting a robot model into a scene is only the start. Developers also need to assemble its components, add controls and check whether it can complete a task.
NVIDIA developers Dillon Bailey and Rishabh Chadha used 3D assets from the
SimReady Central
library to build a pick-and-place simulation of a robot moving a can using the
NVIDIA Isaac Sim

Testing the assembled scene shows how the assets work together, from joint movement and contact behavior to the gripper’s ability to hold, move and release the can. With that baseline in place, developers can adjust object positions and motion paths and repeat the tests to evaluate how each change affects the task.

Build a Voice-Controlled VR Simulation With SimReady Assets
🔗
Bringing 3D assets into virtual reality (VR) requires more than rendering a scene. Objects need to respond to controllers and behave as expected when grabbed, moved or released.
NVIDIA Omniverse community developer Michael Wagner took on this challenge. He directed GPT-6 Astra to use
Blender
software to model a study environment from two reference images, balancing visual quality with efficient performance in VR.
He then used Claude Code to build an application that lets users find SimReady Central assets by voice and interact with them in an immersive VR scene. The Claude Code agent worked for about eight hours, and Wagner built the application over a weekend using an NVIDIA RTX 6000 Ada workstation and a Meta Quest 3 VR headset.
The application ran on
NVIDIA Omniverse libraries
:
ovstage
shared the OpenUSD scene,
ovrtx
rendered it,
ovxr
enabled VR and
ovphysx
ran physics. Wagner later built a second version with
ovnewton
, which integrates with ovstage, to compare the physics libraries.
The biggest challenge for Wagner was checking what happened inside the headset. Automated tests missed problems he could feel, including objects shaking when grabbed. Wagner reported the symptoms, guided the agent through changes and verified the interaction himself. Updating the grab control once per frame resolved the shaking. His takeaway: Give agents renders and logs to inspect, then check the experience directly.

Send Microducks on Rounds in a Simulated Hospital
🔗
https://blogs.nvidia.com/wp-content/uploads/2026/11/microducks-icu-16x9-1920x1080-new.mp4
Before adapting a robot to a new environment, developers need to test whether its walking policy — the AI that controls how it moves — can keep it stable in that setting.
AI developer Maziyar Panahi directed Claude Code, using Claude Opus 5.5, to assemble an intensive care unit from 13
NVIDIA SimReady
hospital assets and test Microduck robots inside it. The assets came with
Newton physics
settings, so Panahi didn’t have to model the furniture or create collision geometry from scratch. The Newton physics engine also helped replicate the ward so hundreds of copies could run together on one NVIDIA RTX PRO 6000 GPU.
When the cloud containers lacked graphics support, Panahi and the Claude Code agent separated simulation from rendering, recording robot poses in the cloud and rendering them locally. They also treated the furniture as static collision objects, which enabled larger runs within the solver’s limits.
The robots walked using AI they had already been trained on and followed preset points along a route. Panahi checked how many robots remained upright: In a 256-ward run, 766 of 768 Microducks were still standing after 14 simulated seconds. He said the agent’s work took about two hours.

Test Gas-Turbine Operating Scenarios With a Digital Twin
🔗
https://blogs.nvidia.com/wp-content/uploads/2026/10/Turbine-Lab-RTX-and-What-If-under-10MB-1.mp4
Before changing how industrial equipment operates, engineers need a way to explore the consequences. Pradeep Kaushik, a member of the NVIDIA Omniverse developer relations team, directed Astra to build a what-if analysis application around a simulated gas turbine and generator.
The application lets users adjust conditions such as load, ambient temperature and fuel composition, then compare power, efficiency, fuel consumption and equipment response. Six test procedures explore scenarios including load changes, a stuck fuel valve and an exhaust-sensor error.
The prototype gives engineers an interactive way to investigate how operating changes and faults could affect equipment behavior, supporting decisions about which scenarios warrant further testing.
Astra used tools like Cantera for thermochemistry and SciPy for equipment dynamics. The application maps solver results to rotor animation and color-coded temperature, pressure and flow-velocity indicators in a 3D turbine. NVIDIA Omniverse libraries update the scene (
ovstage
), render it with RTX (ovrtx) and stream the view to the browser (ovstream). Engineers can rotate and zoom the cutaway, switch between indicators, and pause or scrub through a simulated response alongside charts and virtual instruments.

Stress-Test a Warehouse Simulation at Scale
🔗
https://blogs.nvidia.com/wp-content/uploads/2026/10/Infra-scale-demo-20260914_144614-Meeting-Recording.mp4
A warehouse simulation needs to keep running smoothly as more robot arms, conveyors and boxes fill the scene.
When it slows down, developers need to identify what’s holding it back.
Bhavik Sanganee, principal engineer at NVIDIA, used Astra with
NVIDIA Omniverse libraries
to build a warehouse simulation, increase its complexity and investigate slowdowns.
Performance first fell below the target when the scene doubled in size. Running physics calculations, image rendering and video preparation concurrently restored performance and enabled further scaling.
With 80 conveyors, 40 arms and 800 boxes, the simulation sustained 30 frames per second at full HD resolution during a two-minute test. The arms completed 640 successful box placements.
Doubling the scene again reduced performance. Testing traced the slowdown to the physics and robot-control pipeline, giving Sanganee a specific area to improve.

Test Robot Control for Flexible Cable Routing
🔗
https://blogs.nvidia.com/wp-content/uploads/2026/10/scurve_rl_vs_astra_side_by_side.mp4
In electronics assembly, a robot may need to position a flexible cable around components before plugging it into a port. The cable bends as the robot moves it, and the connector must line up precisely to fit.
Oyindamola Omotuyi, robotics technical marketing manager at NVIDIA, directed Astra to build a robot simulation using
NVIDIA Isaac Lab
,
Newton
physics and Omniverse rendering with a
Robotiq gripper
handling the cable.
Astra also developed a
reinforcement learning
system that combined learned cable-routing movements with position-and-orientation feedback and corrective adjustments for USB-C insertion. The simulation gave Omotuyi a way to test cable handling and connector alignment before moving to physical-robot experiments.
The controller used information supplied directly by the simulation. Next steps include testing a friction-held grasp and using information a physical robot could obtain from cameras and sensors.
